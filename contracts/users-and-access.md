# 本地用户、权限与域名白名单

状态：实现于当前开发分支，验证结果见交付说明。本地用户最初在 schema 10 引入，当前多库授权为 schema 36；历史 admin 密码、有效会话、歌曲 ID、歌单、收藏及收听统计迁移保留。当前不提供公开注册、邮件找回或账号删除。

## 角色与身份

音乐、封面和歌词按音乐库共享，访问同时受角色能力和库授权限制；收藏、普通/规则歌单、播放次数、时长与最近播放按用户隔离。所有者只能通过个人歌单接口操作自己的歌单。播客节目与音频缓存共享，个人关注和进度独立，详见[多库与个人关注](multiple-libraries.md)。

- `owner`：配置音乐库及多个来源、分配库权限、管理账号和实例设置，隐式访问全部启用库。
- `librarian`：在获授权库内导入、扫描和管理共享音乐资料。
- `editor`：在获授权库内编辑资料。
- `listener`：浏览和播放获授权库，管理自己的歌单、收藏、关注与收听进度。
- `/api/v1/manage/**` 按具体能力校验；仅隐藏网页管理入口不能构成授权。AI/MCP 与后台任务沿用同样的检查。
- HTTP Cookie、认证音频和写请求的 `X-Wildstring-Client: web|android|ios` 规则继续生效，不把令牌放入 URL。

`GET /api/v1/auth/status` 保留 `configured`、`authenticated`；已登录时增加 `user`。`POST /api/v1/auth/login` 接受 `{username,password}`，返回用户的 `profile` 等公开资料。用户名不区分大小写，内置账号 ID 仍为 admin。

所有新建账号的用户名为 1–32 位 ASCII 字母、数字、点、下划线、连字符，首位为字母或数字。密码为 12–128 个字符，采用独立随机盐与 scrypt；返回信息和输入校验错误不回显密码或哈希。登录与当前密码校验按规范化账号名和请求来源隔离计数：同一组合连续 5 次失败后暂停 60 秒，不阻断其他账号或其他来源。来源取自直接连接地址；反向代理部署应保持独立登录入口或由代理实施额外限流。

## 密码与用户管理

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/v1/auth/password` | 已登录用户提交 `{current_password,new_password}`；成功 204，清 Cookie，撤销该用户所有设备会话 |
| GET | `/api/v1/manage/users` | 所有者读取 `{items:[User]}`，不返回凭据 |
| POST | `/api/v1/manage/users` | `{username,password,profile,library_ids?:[id]}`，默认听众；成功 201 |
| PUT | `/api/v1/manage/users/{id}` | `{version,profile,enabled}`；更新后撤销目标用户全部会话 |
| POST | `/api/v1/manage/users/{id}/password` | `{version,new_password}`；管理员重置其他用户密码，成功 204 并撤销目标用户全部会话 |

全部写接口要求合法客户端标头。重名返回 409，版本过期返回 409，未知账号返回 404，非法输入返回 422。停用账号不能登录。不能停用或修改当前账号的角色，从而保留至少一个启用的管理员；自己的密码必须通过当前密码校验入口修改，不能走管理员重置绕过。终端 `make admin` / `make docker-admin` 仍用于恢复内置 admin，只撤销该账号会话，不清理其他用户的数据。

网页的“账号设置”向所有用户开放；管理员另有“管理 → 用户”。改密后客户端应停止播放并重新登录。角色/停用/重置操作使其他客户端的后续请求返回 401；库授权按新的范围检查后续请求，撤权保留私人引用；已经传给客户端的音频字节不可撤回。

## Host 白名单

管理路径为 `GET /api/v1/manage/access` 与 `PUT /api/v1/manage/access`，格式 `{enabled,hosts:[string],version}`。默认 `enabled:false, hosts:[]`，不限制访问域名。启用时 hosts 不能为空，最多 50 项。

- 每项为精确主机名或 IP，不含协议、端口、路径、凭据或通配符。支持 IDNA、IPv4、IPv6，大小写与域名末尾的点归一化。请求端口不参与域名匹配。
- 校验实际 HTTP `Host`，不相信 `X-Forwarded-Host`。反向代理需正确设置 Host；各客户端使用的局域网 IP、域名均须列入。
- 启用后，网页静态资源、登录与已登录请求、封面、歌词和音频均受限制。不匹配或重复/非法 Host 返回 400 `host_not_allowed`，管理员没有旁路。
- `/health` 与 `/health/ready` 仅暴露原有健康信息，保留探针可用性，不能通过它们访问设置或曲库。存储无法读取时，其他请求返回 503。
- 修改后立即生效并持久化。网页明确显示当前主机名及锁定风险；不提供临时回退窗口或未认证的关闭接口。

### 误配置恢复

如果当前访问主机被排除，管理页面也无法访问，**只能直接修改数据库关闭白名单**。先在服务器对数据库做 SQLite 在线备份，再执行：

```sql
UPDATE site_access SET enabled=0, version=version+1 WHERE id=1;
```

数据库位于运行目录的 `wildstring.sqlite3`，Docker 默认 `/data/wildstring.sqlite3`。正常运行时每个请求读取生效设置，修改后无需重启。不要通过删除数据库恢复，以免丢失账号和曲库信息。

## 客户端对接

新增用户身份读取、角色显示和密码修改接口需要客户端实现。账号登录框不能固定 admin。遇到 401 应清理当前连接的私密状态并停止播放；403 表示当前账号的角色或库授权不允许，不应无限重试。域名限制使用客户端配置的服务端 URL 对应的 Host；修改 Base URL 时必须重新建立该地址的认证上下文。本文不代表 Android/iOS 等原生客户端已完成新增 UI。
