# 播客单集进度与音乐接续

本契约由服务端进度测试、Web Playwright、Android 进度与媒体服务测试、Apple 共用播放核心测试验证。各层结果与真机缺口见[0.8.20 说明](../docs/releases/v0.8.20.md)的验收记录。

## 两种同步

| 类型 | 同步对象 | 触发与恢复 |
| --- | --- | --- |
| 音乐 | 当前曲目、队列、顺序与播放位置 | 沿用音乐接续；播放期间约 15 秒同步，暂停等动作立即同步。遵循用户的关闭／询问／自动恢复设置 |
| 播客 | 每个账号、每一集的独立书签 | 播放中本机约 5 秒落盘、服务端约 10 秒上报；暂停、定位、切集、播完时立即保存。重新选集按账号偏好，主动恢复检查最新书签 |

播客不覆盖音乐接续快照，也不产生音乐收听统计、推荐反馈和 Last.fm 记录。音乐队列含播客时不发布这份混合队列；播客自己的待播列表走独立端点，见[播客待播列表、新集自动待播与自动续播](podcast-queue.md)，不写入 `playback_states`。打开页面、加入待播、读取进度都不抢占写入权。允许多个设备同时出声，云端当前会话以服务端接受的写入为准。

续听模式按账号保存：自动续听（默认）、询问接续位置、从头播放，本机只缓存服务器偏好以供离线使用。三种方式都会保存进度，**只在重新从列表／详情选集时应用**。普通播放键恢复不重复询问，也不套用从头播放偏好。

### 主动恢复与系统恢复

- 用户暂停后主动按播放（App、可识别的系统媒体命令）时，最多等待一次整体 1500ms 的进度读取，不串行等待旧上传或新会话上传。异会话的最新书签优先，即使位置更小；自己的旧回声不能覆盖最新本机暂停点。用户暂停后明确定位的目标优先于自动选择。
- 读取超时、断网或 5xx 时，从最新本机位置继续，包括已冲突但仍保存的位置。401、403、404 等客户端错误保持暂停并提示重试，不能按离线绕过。迟到响应、暂停、切集、切换账号后的旧请求不能让播放器跳转或重新出声。
- 无异会话更新时沿用本机会话；需接续其他会话或改变 `restart` 意图时新建 `resume` 会话。新写入遇到 409 后停传，不循环争抢。普通恢复读到已听完则保持暂停；明确定位可以回听，但 `resume` 不清除已听完状态。
- 连续播放、缓冲结束、电话／导航临时中断后自动恢复，继续刚才本机位置，不重新读进度、不建立新会话；中断期间用户暂停则取消自动恢复。重复 PLAY 在已有播放意图时不重复准备。
- Web 在实际获得播放许可后才上传首个 `play`。浏览器拒绝播放时保留选定位置，原播放键重试不重复读取或建立会话。通用 `playing / pause` 事件无法可靠推断用户原因；只在可识别命令上执行接续。耳机重连若发送普通 PLAY，也按主动命令处理。

完整场景与平台限制见下文，实际验证范围见 [0.8.20 说明](../docs/releases/v0.8.20.md)。

## API

需要登录，进度以当前认证用户隔离。沿用现有 Web CSRF 标识或 Android 认证方式，客户端不能指定其他用户。

`GET /api/v1/podcasts/episodes/{episode_id}/progress`：读取当前书签；不存在书签时返回版本 0、位置 0、空会话。单集不存在返回 404。

`PUT /api/v1/podcasts/episodes/{episode_id}/progress`：原子比较并写入，字段如下。

```json
{
  "session_id": "new-listening-session-uuid",
  "device_id": "persistent-device-id",
  "base_version": 12,
  "sequence": 1,
  "position_seconds": 900,
  "duration_seconds": 3600,
  "event": "play",
  "intent": "resume"
}
```

- `session_id`：本次主动收听生成的新标识，16–128 字符；重试沿用原标识。
- `device_id`：客户端设备标识，1–128 字符。
- `base_version`：开始本次收听前读到的服务端版本，非负整数；后台重试不改它。
- `sequence`：本次会话内递增序号，正整数；拖回前面也递增。
- 位置和时长：0–31536000 秒的整数；时长为 0 表示未知，有时长时位置会限制到时长范围内。
- `event`：`play`、`progress`、`pause`、`seek`、`stop` 或 `ended`。有效的 `ended`（无时长，或位置在时长最后 2 秒内）标记已听完。`pause`、`stop`、`ended` 停在片尾余量内也标记已听完：余量是时长的 5%，限制在 30–120 秒；时长不长于这个余量时，仍只靠真正的 `ended`。播放中的 `progress` 和单独的 `seek` 不标记完成。已有书签不回溯。
- `intent`：可选的 `resume` / `restart`，不落库。`resume` 保留服务器已有的完成状态，也允许未完成正常变为完成；`restart` 或缺省值按既有事件规则重算。客户端须在会话的每次写入（含离线补传）携带同一意图，只在首个 `play` 携带不能保护后续进度。明确从头播放或标为未听使用 `restart`，接管本机位置使用 `resume`。请求中混用意图时以该次请求为准，版本与序号校验仍优先执行。
- 兼容顺序：先升级服务器再发布携带 `intent` 的客户端；旧服务器拒绝未知字段并返回 422。旧客户端配新服务器维持原行为，不自动获得完成状态保护。

成功响应与 GET 一致：

```json
{
  "episode_id": "episode-id",
  "version": 13,
  "session_id": "new-listening-session-uuid",
  "device_id": "persistent-device-id",
  "sequence": 1,
  "position_seconds": 900,
  "duration_seconds": 3600,
  "completed": false,
  "updated_at": "2026-10-25T06:00:00+00:00"
}
```

节目详情、单集详情和单集收藏列表的单集对象附带 `last_listened_at`（当前账号的最近进度写入时间，无记录为 `null`），供客户端选择最近收听的单集；读取不更新时间。

## 账号级续听模式

需要登录，按认证账号隔离，不接收其他用户 ID。

- `GET /api/v1/podcasts/resume-mode` 返回 `{"resume_mode":"auto"}`，无记录时默认 `auto`，读取不会创建记录。
- `PUT /api/v1/podcasts/resume-mode` 接收并返回 `{"resume_mode":"ask"}`，合法值仅 `auto` / `ask` / `restart`，未知字段或非法值返回 422。沿用现有写请求的客户端／CSRF 校验。
- schema 54 新增 `podcast_resume_prefs`，保存账号、模式与更新时间；不自动导入旧客户端的本机设置。
- 客户端在登录、回前台、进入设置页时拉取；开播使用缓存，修改成功后才更新缓存，离线使用上次缓存。四端实现与冲突提示的实际验收范围见 [0.8.18 发布说明](../docs/releases/v0.8.18.md)，端点或控件存在不代表真机验收通过。

## 顺序与冲突

1. 同一用户、同一集：新会话必须匹配 `base_version`，接受后替换当前会话并增加版本；同时争用时只有一个成功。
2. 当前会话：只接受比已保存值大的 `sequence`。重复或乱序的旧序号返回当前状态，不更改位置、版本或完成状态。
3. 旧设备延迟上传：其会话已被另一台设备替换，且原版本落后，返回 HTTP 409：`{"detail":{"code":"podcast_progress_conflict","current":{...}}}`。不使用客户端时钟，也不选最大的播放位置。
4. 客户端收到 409 后，按以下优先级处理，不使用时间阈值自动接管：
   - 历史待发送记录（不是当前会话）：采用响应中的 `current`，清掉待发送记录，不重传、不提示；即使远端与本机 `device_id` 相同也先执行本条。
   - 当前会话：保留本机位置和播放，停止该会话上传；仍保存本机检查点。即使设备 ID 相同也不自动改版本重试，同浏览器的另一标签页仍是另一会话。播放器显示「另一台设备更新了这一集的进度。本机进度暂不同步到服务器。」与「用本机进度」按钮。
   暂停、拖动和切集不隐含接管。冲突后拖动仅改本机位置；重新点播先读服务器，再按服务器状态开始新会话。「用本机进度」以最近观察到的 `current.version` 创建 `intent=resume` 的新会话，不清除已有完成状态；再次遇到 409 保留提示，不自动重试。明确从头播放、标为已听完或标为未听也可创建新会话；只有从头播放和标为未听使用 `restart`。
   已听完规则：用户主动点开服务器已听完的单集按明确从头播放处理（`restart`）；只有自动续播碰到已听完的单集才按「跳过已听」改播下一集，此时只读取不写入。
5. 当前设备主动从 30 分钟拖到 10 分钟，会发送更大的序号，10 分钟成为新书签。旧设备的 40 分钟补传仍被拒绝。
6. 完成状态只在已接受的完成转换后处理。听完、取关、过期或重放的结束报告均不释放显式个人保存引用，也不删除共享音频；回收统一使用零引用清理策略。

7. 自然结束只有本次会话的本次 `ended` 得到完成确认后，才移除待播并自动选择下一集；等待最多 1500ms。未确认或已失去写入权时保留结束待发送记录，停在当前集，不改共享待播；手动下一集仍可操作。单集进度和待播队列分别 CAS，不提供账号级跨集原子互斥或远程停播。

其他错误：401 未登录，404 单集不存在，422 格式或字段不合法。旧版无版本请求返回 422，需同时更新客户端与服务端；不会为了旧客户端兼容绕过冲突校验。

## 本机持久化与后台限制

- 读进度超时或离线时，仍按本机待发送记录／最后已知位置建立并持久化本地会话（包含 `session_id`、`intent` 和已知 `base_version`，未知版本为 0），首个 `play` 暂不上报。恢复后的第一个既有心跳尝试 PUT，409 按上述优先级处理；迟到的开播读取结果不得跳转本机位置或重建会话。
- Web 使用按来源站点、账号分隔的 localStorage 待发送记录；每个活动播放器持有自己的会话与检查点，另一标签页的持久记录不替换本页正在播放的会话。联网、回到前台、重开页面后补传；冷恢复使用最后落盘记录并保持暂停。存储不可写时退回内存并提示，不能承诺关闭页面后恢复。
- Android 使用 Room 独立进度表，按稳定的服务器与账号标识保存，进程重建不会换掉保存位置；请求仍校验当前登录会话，避免切换账号后的响应串用。清理播放队列不删除待发送进度。
- 四端在重新点播同一集／从头播放时，若读取与本进程旧上传交错，只用该旧请求的成功确认衔接尚未上传的新会话基准；已成功确认但晚于读取快照的本机版本也可衔接。不等待旧上传才播放，不根据相同设备 ID 推断接管，收到 409 后仍按冲突规则停传。
- Android 上报由现有媒体播放服务负责，锁屏时不依赖 Compose 页面计时器。最后一次退出回调仅作补充，定时落盘才是兜底。
- 四端将选定书签应用到播客原始音频时间线；即使音频尚未准备完成，也由媒体引擎保留提前定位，不能只更新进度元数据却实际从零出声。实现与专项验证见 [0.8.20 说明](../docs/releases/v0.8.20.md)。
- 四端暂停与定位直接控制本机播放器；主动恢复按上文执行有界读取，后台上传不阻塞本机控制。缓冲和临时音频焦点中断不伪造 `pause / stop / ended`；实际暂停、停止和结束分别保存对应事件。暂停不制造周期性播放进度，已有待发送记录仍可重试。
- Apple 按服务器与账号作用域持久化会话、位置和待发送事件；恢复时保留会话与序号，重新开始本机节流计时。当前播放的既有检查点也串行补传历史待发送记录，成功后清理；历史 409 采用远端并丢弃，不提示或重试。
- 网页后台计时器可能被浏览器节流；系统强制终止应用时也不能保证执行最后一次回调。恢复到最近已落盘位置，不承诺零丢失或离线时实时同步。
- 服务端 schema 34 增加会话与顺序字段，旧书签的位置、时长与完成状态保留；Android Room 从 1 升级至 2，保留原队列和当前位置。当前 schema 以代码中的 `SCHEMA_VERSION` 为准。

## 场景规则

下表描述四端的共同决策；涉及具体系统生命周期的能力按后面的平台差异处理，不能把原生后台能力等同网页后台能力。UI 数值与动效规则见 [DESIGN.md](../DESIGN.md)。

| # | 场景 | 行为 |
| --- | --- | --- |
| 1 | 第一次点播未听单集 | 应用账号偏好；上传不阻塞开播。 |
| 2 | A 暂停，B 没更新，A 再播放 | 有界读取；保留 A 最新暂停点，不倒退到自己的旧上传 |
| 3 | A 暂停，B 听到新位置，A 再播放 | 接服务端最近接受的 B 位置并尝试接管 |
| 4 | A 仍播放，B 主动开始同一集 | A 继续本机出声，停传且不跳位置；B 写入 |
| 5 | B 从 35 分钟回退到 20 分钟，A 随后恢复 | A 接 20 分钟；较小位置也可能是最新有效操作 |
| 6 | A 失权后继续听到更远 | 更远不意味着应覆盖云端 |
| 7 | 失权的 A 播放中后退 15 秒 | 普通定位不能重新抢权 |
| 8 | A 暂停后先定位，再播放 | 新增读取后仍尊重明确目标，不被 B 的书签覆盖 |
| 9 | 耳机／锁屏／通知播放 | 与 App 的主动恢复一致；后台也不等待交互弹框 |
| 10 | 仅回前台／打开播放器 | 刷新显示不接管 |
| 11 | 失权后点「用本机进度」 | 失败不循环争抢，不清已听完 |
| 12 | A、B 听不同单集 | 不引入账号级独占播放 |
| 13 | 两端基于同一版本开新会话 | 未获权仍可本机听 |
| 14 | GET 后、首 PUT 前 B 心跳更新版本 | 首个 PUT 可能 409；播放不阻塞，收到 409 后不自动跨设备改版本重试。 |
| 15 | 同会话重传或乱序 | 按递增序号幂等处理，回退也发更大序号。 |
| 16 | A 的旧 `ended` 晚于 B 新会话 | 旧 ended 被拒绝，不触发该端的待播修改或自动续播。 |
| 17 | A 离线，B 在线更新，A 重连补传 | 历史 409 采用远端并丢弃，当前会话 409 停传；重连不是主动接管。 |
| 18 | 两端都离线，之后依次联网 | 由服务端 CAS 决定结果，不按离线动作的现实时间合并。 |
| 19 | 服务端已接受 PUT，但响应丢失 | 保留同会话同序号重试；不得新建会话 |
| 20 | GET 很慢／超时 | 恢复读取使用整体预算；超时本机继续，迟到结果不 seek |
| 21 | 进度 GET 返回 5xx | 可恢复错误降级本机；权限／认证错误分开处理 |
| 22 | 首个进度 PUT 卡住 | 点播与主动恢复均不等待上传完成才播放 |
| 23 | 已冲突，离线重新恢复 | 优先 A 最新本机位置，仍不绕过版本隔离 |
| 24 | GET 中暂停、seek、切集、退出登录 | 旧请求遵守同一取消边界；seek 胜出，暂停不被迟到结果解除。 |
| 25 | 锁屏／Activity 或 ViewModel 被销毁 | 恢复逻辑不依赖可见 UI；后台可用性仍受平台限制。 |
| 26 | 长时间暂停 | 只重试真实待发送记录，不发暂停心跳 |
| 27 | 进程重建后，恢复暂停队列再按播放 | 按主动恢复处理；冷恢复队列本身不播放 |
| 28 | 缓冲、临时失去焦点再恢复 | 保留本机位置／会话，不读远端、不接管 |
| 29 | 缓冲／焦点抑制时划掉任务 | 按真实意图／结束状态落盘，不伪造片尾暂停或完成 |
| 30 | A 暂停，B 已听完，A 再播放 | 普通恢复保持暂停和完成状态；明确重播另行触发 |
| 31 | 手动标为已听完／未听 | 显式操作更新状态，不靠普通恢复清完成；不突然移动正在播放的位置。 |
| 32 | 已完成后回退重听一段 | 只有明确重播／标未听才清除 |
| 33 | 失权 A 自然播完，单集也在待播里 | A 本机结束即可；结束被拒绝则不得移除待播 |
| 34 | 失权 A 自然播完，原播放线还有下一集 | 已失权／结束未确认就停；用户主动下一集仍允许 |
| 35 | 切账号／服务器，旧请求回来 | 相同单集 ID 不跨账号回写、开播或显示提示 |
| 36 | 电话期间用户主动暂停，电话结束 | 继续暂停，不自动出声、不检查接续 |
| 37 | A 被临时中断期间 B 更新，A 自动恢复 | A 继续刚才位置；之后 A 真正暂停再主动播放才检查 B |
| 38 | 拔耳机／断蓝牙，随后重连 | 仅重连不主动播放；若收到 PLAY 则按主动命令处理，无法保证知道是否按了实体键 |
| 39 | 缓冲或已经播放时收到重复 PLAY | 重复 PLAY 幂等，不重复读取或建立会话。 |
| 40 | 快速播放→暂停→播放，前一个 GET 仍在路上 | 只执行最后仍有效的播放意图，旧结果不得覆盖新结果 |
| 41 | 暂停期间在 B 改续听偏好 | 普通恢复规则稳定；下一次重新选集才用刷新后的偏好 |
| 42 | 再次点同一集，第一次请求迟到 | 旧请求不能影响新选择，即使两次选择的是同一集。 |
| 43 | GET 返回 401／无权限／单集失效 | 保留权限边界，说明登录／权限／内容问题；不新建云端会话 |
| 44 | 离线自然结束，结束上报未确认 | 保留结束待发送记录并停在片尾，不改待播；主动下一集不受此门禁阻塞 |
| 45 | 结束确认后，B 恰好开播或两端听不同集后同时接下一集 | 不承诺账号级独占自动续播；下一集仍按本集版本冲突处理，禁止无限重试 |
| 44 | 本机旧上传与重新点播／从头播放交错 | Web、Android、Apple 只用本进程具体旧请求的成功确认衔接尚未发送的新会话；确认在 GET 返回前后均可。显式接管、历史补传也走同一单集写入链，音频不等待它们。真正异设备获胜仍 409 停传。 |
| 45 | 书签早于音频准备返回 | 四端保留目标位置，应用到原始音频时间线；不能只更新界面而从零出声。 |
| 46 | 大节目点播 | 不在主线程对整批单集重复做同步 IO 或设备查询；取消已过期的准备，播放前仍核对当前意图与账号。 |
| 47 | 待播、已待播、当前项切换 | 相同内容与字号下操作区域及行布局稳定；内容、语言或字号改变仍允许自然排版。 |
| 48 | 播放、暂停与缓冲反馈 | 控件位置稳定，图标连续过渡；减少动态效果直接落位，缓冲中仍可暂停／取消。播客文章不走音乐歌词接口。 |

## 跨端可行性与技术限制

四端共用以下核心规则：明确命令入口、有界读取、本机持久化、会话隔离、连续播放不跳转。不能统一成「任何平台、任何系统事件都保证一次点击自动出声」。下表区分实现边界与平台限制；运行结果与真机缺口见版本说明。

| 平台 | 可用边界 | 行为与限制 |
| --- | --- | --- |
| Android | MediaSession 命令与 Media3 的播放意图、缓冲、焦点抑制分开；播放服务可脱离 UI 工作 | 使用显式命令入口触发恢复读取。引擎自动恢复不得重新走该入口；准备流程内部 `play` 也不能再次发起恢复 |
| iOS | `MPRemoteCommandCenter` 接收外部命令；`AVAudioSession` 提供中断与恢复信息 | 中断通知进入内部本机恢复，外部命令进入主动接续；中断中暂停取消自动恢复。沿用最低部署版本支持的中断 API |
| macOS | 与 iOS 共享播放核心和远程命令入口；可以区分明确命令与 AVPlayer 状态 | 现有音频会话观察只编译在 iOS，不能直接套用手机的中断回调。桌面按输出路由／播放器状态处理本机恢复，状态回调不建云端会话；具体输出设备恢复需运行验收 |
| Web | App 命令可追踪；支持时由 Media Session action 接收系统播放键 | App 与 Media Session play 进入相同接续入口。HTML 媒体通用事件不提供同等焦点原因，不能由 `playing` 猜测主动接管；不支持的系统控制不能靠前端补齐 |

### 必须保留的差异

1. **Web 自动播放限制。** 网络等待后 `audio.play()` 可能被浏览器／系统策略拒绝，不能保证所有浏览器均一次点击出声。失败时保留已经选好的位置和暂停状态，给出原播放按钮再次操作的路径；再次点击只完成该次被拦截的播放，不重新读进度或反复建会话。不以“先播旧位置，再跳远端”绕过限制。未获得播放许可时不要提前上传新的 `play` 接管。
2. **通用媒体事件没有用户原因。** 按 HTML 标准，`pause / playing` 是普通事件；仅凭它们不能区分电话、脚本、系统 UI 或用户操作。Web 只在可识别的 App／Media Session 命令上执行接续；其他自动恢复只用本机。某浏览器如果只发通用事件、不把系统 PLAY 送到 action handler，无法保证该系统键与 App 键完全同效。
3. **暂停后不能靠后台持续探测。** 网页可能被节流或冻结，原生 App 也可能被系统停止；恢复时再读，不能承诺暂停期间持续刷新。强制结束不能保证最后回调，按最近落盘恢复。正常后台音频播放与已经暂停的后台应用分别验收。
4. **硬件命令来源不可完全辨认。** 耳机／车机重连自动发出的普通 PLAY 与按键触发的 PLAY 可能没有可区分信息。四端统一按实际收到的命令处理，不承诺还原实体按键意图，不增加按时间猜测的策略。
5. **Web 多标签页也是多实例。** 同账号标签页共享 localStorage 的设备 ID 和单集持久记录；每个活动播放器在内存保存自己的会话与检查点，防止另一页写盘替换正在播放的会话。任何 409 都停传，不能把同 `device_id` 的另一会话视为自己。冷恢复读取最后落盘记录，保持暂停；两个标签页回归另列于验收。
6. **进度不是实时遥控协议。** 远端没有可靠的“此刻正在播放／已暂停”信息；续听只接最近接受的书签，可能落后对方当前出声位置。不让手机等待电脑暂停，也不承诺远程停播、无缝零秒误差或跨集独占。
