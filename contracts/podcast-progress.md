# 播客单集进度与音乐接续

本契约由 `backend/tests/test_podcast_progress.py`、Web Playwright 回归和 Android 进度单元测试验证。Android 真机锁屏、强制结束与恢复另行验收。

## 两种同步

| 类型 | 同步对象 | 触发与恢复 |
| --- | --- | --- |
| 音乐 | 当前曲目、队列、顺序与播放位置 | 沿用音乐接续；播放期间约 15 秒同步，暂停等动作立即同步。遵循用户的关闭／询问／自动恢复设置 |
| 播客 | 每个账号、每一集的独立书签 | 本机约 5 秒落盘、服务端约 10 秒上报；暂停、定位、切集、播完时立即保存。进入这一集时选择续听方式 |

播客不覆盖音乐接续快照，也不产生音乐收听统计、推荐反馈和 Last.fm 记录。音乐队列含播客时不发布这份混合队列。打开页面、恢复暂停的本机队列、加入待播、读取进度都不抢占写入权。

客户端单独保存播客偏好：询问接续位置（默认）、自动续听、从头播放。三种方式都会保存进度；冲突始终询问，不自动覆盖。

## API

需要登录，进度以当前认证用户隔离。沿用现有 Web CSRF 标识或 Android 认证方式，客户端不能指定其他用户。

`GET /api/v1/podcasts/episodes/{episode_id}/progress`：读取当前书签；不存在书签时返回版本 0、位置 0、空会话。单集不存在返回 404。

`PUT /api/v1/podcasts/episodes/{episode_id}/progress`：原子比较并写入，字段如下。

```json
{
  "session_id": "new-listening-session-uuid",
  "device_id": "persistent-device-id",
  "base_version": 12,
  "sequence": 1,
  "position_seconds": 900,
  "duration_seconds": 3600,
  "event": "play"
}
```

- `session_id`：本次主动收听生成的新标识，16–128 字符；重试沿用原标识。
- `device_id`：客户端设备标识，1–128 字符。
- `base_version`：开始本次收听前读到的服务端版本，非负整数；后台重试不改它。
- `sequence`：本次会话内递增序号，正整数；拖回前面也递增。
- 位置和时长：0–31536000 秒的整数；时长为 0 表示未知，有时长时位置会限制到时长范围内。
- `event`：`play`、`progress`、`pause`、`seek`、`stop` 或 `ended`。只有有效的 `ended` 可标记已听完；接近片尾的拖动本身不标记完成。

成功响应与 GET 一致：

```json
{
  "episode_id": "episode-id",
  "version": 13,
  "session_id": "new-listening-session-uuid",
  "device_id": "persistent-device-id",
  "sequence": 1,
  "position_seconds": 900,
  "duration_seconds": 3600,
  "completed": false,
  "updated_at": "2026-10-25T06:00:00+00:00"
}
```

## 顺序与冲突

1. 同一用户、同一集：新会话必须匹配 `base_version`，接受后替换当前会话并增加版本；同时争用时只有一个成功。
2. 当前会话：只接受比已保存值大的 `sequence`。重复或乱序的旧序号返回当前状态，不更改位置、版本或完成状态。
3. 旧设备延迟上传：其会话已被另一台设备替换，且原版本落后，返回 HTTP 409：`{"detail":{"code":"podcast_progress_conflict","current":{...}}}`。不使用客户端时钟，也不选最大的播放位置。
4. 客户端保留本机位置，展示“已同步位置／本机位置”。用户主动选择后，以当时展示的服务端版本创建新会话；若选择期间又有更新，再次报冲突，不能静默强制覆盖。
   冲突后如果音频继续播放，仍定时保存本机位置，但停止上传；后续主动播放或定位需先处理冲突。
5. 当前设备主动从 30 分钟拖到 10 分钟，会发送更大的序号，10 分钟成为新书签。旧设备的 40 分钟补传仍被拒绝。
6. 完成状态只在已接受的完成转换后处理。听完、取关、过期或重放的结束报告均不释放显式个人保存引用，也不删除共享音频；回收统一使用零引用清理策略。

其他错误：401 未登录，404 单集不存在，422 格式或字段不合法。旧版无版本请求返回 422，需同时更新客户端与服务端；不会为了旧客户端兼容绕过冲突校验。

## 本机持久化与后台限制

- Web 使用按来源站点、账号分隔的 localStorage 待发送记录；播放时保存，联网、回到前台、重开页面后补传。存储不可写时退回内存并提示，不能承诺关闭页面后恢复。
- Android 使用 Room 独立进度表，按稳定的服务器与账号标识保存，进程重建不会换掉保存位置；请求仍校验当前登录会话，避免切换账号后的响应串用。清理播放队列不删除待发送进度。
- Android 上报由现有媒体播放服务负责，锁屏时不依赖 Compose 页面计时器。最后一次退出回调仅作补充，定时落盘才是兜底。
- 网页后台计时器可能被浏览器节流；系统强制终止应用时也不能保证执行最后一次回调。恢复到最近已落盘位置，不承诺零丢失或离线时实时同步。
- 服务端 schema 34 增加会话与顺序字段，旧书签的位置、时长与完成状态保留；Android Room 从 1 升级至 2，保留原队列和当前位置。本分支其他功能可能继续增加服务端 schema，部署前以当前 `SCHEMA_VERSION` 为准。

## 验收场景

- 两台设备轮流收听同一集，旧设备断网补传不会覆盖新设备。
- 当前设备主动向后拖动；发送乱序或重放请求，最终保持主动选择的位置。
- 播放中不点击暂停，服务端也出现新进度；本机断网、刷新或重启后恢复待发送记录。
- 不同账号、服务器和单集不混用进度；仅打开播放器不产生写入。
- 播客播放不影响音乐接续快照；过期结束报告不触发音频清理。
- 真机仍需核对锁屏播放、切网、系统回收后台和用户强制停止后的恢复位置。
