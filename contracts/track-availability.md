# 曲目可用状态与播放

更新时间：2026-11-06。当前分支实现，尚未发布。

- 复用 `Track.status`：`available`、`missing`、`unreadable`。文件扫描负责更新状态；恢复文件并重新扫描后，同一曲目 ID、收藏、歌单位置继续保留。客户端网络错误不写成永久失效状态。
- 曲库、专辑、艺人、字母索引，以及普通歌单／收藏的 GET 查询新增 `include_unavailable=true`。默认仍只显示可用记录，保持旧客户端及 AI 检索行为。启用后分页总数、字母位置与专辑／艺人统计包含缺失和不可读记录；不可访问的音乐库及回收站条目仍不可见。
- 歌单详情和列表的 GET 查询支持同一参数；智能歌单仍根据可用曲目动态生成。修改响应保留原有统计行为，刷新 GET 可取得包含失效记录的数量。
- Mac、iOS、Android 与 Web 浏览页面启用该参数。列表把已确认不可用的歌曲以弱化文字及原因呈现，保留收藏和移除等操作。
- 播放全部选择首个可用曲目，队列建立和添加时跳过已确认不可用的项。手动选择不可用曲目显示原因与恢复、扫描、刷新后的重试提示，保留原队列。全部不可用时显示提示。
- 文件在扫描后才丢失：流式响应和播放计划返回 `audio_not_found`；不能读取或文件变化使用相应错误码。客户端显示播放错误，不把超时或断网当作文件缺失。列表状态要在服务端扫描并重新读取后更新，不在每次列出歌曲时逐一访问磁盘。
- 当前播放中途出错保留原有重试和换曲入口；不承诺对尚未经扫描确认的坏文件自动跳下一曲。离线文件与收藏不会因网络故障被删除。

验证：真实临时曲库删除／恢复文件的后端测试；Apple 播放队列与旧响应解码回归；Android 状态解码及错误分类回归；Web 桌面／手机浏览器状态模拟与真实音频播放回归。具体本轮结果见 Mac README；真机端到端、正式签名包及部署另行验收。
