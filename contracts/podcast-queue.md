# 播客待播列表、新集自动待播与自动续播

2026-11-07 新增，2026-11-08 修订。适用于 Web / Android / macOS / iOS 四端。本文描述目标行为与接口，实现与验证状态见文末。

取代此前各端自行推导续播的做法：Web 的动态自动尾部、macOS 的一次性全量入队、Android 的单集队列都按本文收敛。相关背景见 [播客单集进度与音乐接续](podcast-progress.md)。

## 1. 概念与统一心智

在服务端底层仍保留有序待播队列（`podcast_queue`）与无序稍后听候选池（`podcast_inbox`）以兼容历史数据与并发分发；但在**客户端交互与用户感知上，全面收敛为单一的「待播列表」**：

| 概念 | 用户感知与交互 | 职责与呈现 | 存储与同步 |
| :--- | :--- | :--- | :--- |
| **待播列表** | 接下来想听的内容（统一入口与弹窗） | 统一聚合展示待播队列与稍后听单集，支持「▶ 播放全部」、单项即时播放与行内一键移除 | 服务端，按用户，带版本，跨设备同步 |
| **新集自动待播** | 节目更新后自动进入待播规则 | 简化为三选项（`ignore` / `queue_last` / `queue_next`），隐藏主界面数字微调框 | 服务端，按用户＋节目，跨设备 |
| **自动续播** | 队列播完后自动接听下一集 | 播放器续播策略，只读预览不生成队列条目 | 客户端本地派生，不同步 |
| **单集收藏** | 永久标记喜爱单集并保护音频 | 独立于关注和队列，提供「已收藏」列表过滤，且阻止服务端音频清理 | 服务端，Schema 50，按用户隔离 |

订阅（关注）只决定是否接收节目更新，不产生任何列表条目。自动下载与预缓存管的是音频文件，与上述概念无关；Android 的「预缓存下一集」文案不得被理解为下一集入队。

## 2. 不变式

1. 订阅、首次抓取、OPML 导入、节目合并去重都不向待播列表写入历史单集。
2. 待播队列只装用户显式加入的条目，或用户显式开启的「新集自动待播」规则产生的条目。
3. 客户端统一使用单一「待播列表」入口与弹窗；旧有的独立「加入稍后听」右键菜单/操作已废弃收敛为「加入待播」/「下一集播放」及行内快速切换。
4. 单集列表提供行内三态快速切换按钮：未在待播中显示 `+ 待播`（点击加入），已在待播中显示 `✓ 已待播`（点击从待播中移除），当前正在播放该单集时显示 `正在播放`（禁用点击）。
5. 播客列表头部提供快捷播放待播操作：`▶ 播放待播 (N)`，只要存在待播单集即可一键顺次起播。
6. 单集上下文菜单提供手动完成状态切换：`标为已听完` 与 `标为未听`，切换后立即更新播放进度与未听计数；已听完单集在列表中应用视觉静音（`opacity: 0.62`，标题置灰，隐藏底部进度条）。
7. 单集级收藏（`单集收藏` / `取消收藏`）独立于节目关注，单集数据模型包含 `favorite: bool` 与 `loved: bool`；节目详情提供「已收藏」过滤标签；服务端实现音频防清理保护。
8. 探索榜单具备 1 小时 TTL 内存缓存并在空闲时静默预加载，避免用户反复打开发现页时闪现加载动画。
9. 自动续播不写队列；界面「接下来」中的自动部分是只读预览，不参与拖拽与排序。
10. 队列条目带来源 `manual | rule`；用户拖动 `rule` 条目即转为 `manual`，移除即删除。
11. 播放某集时把它插到队首并保留其余队列，不清空已排好的内容。
12. 待播列表、队列、偏好按账号隔离并跨设备同步；自动续播预览不同步。
13. 音乐接续快照 `playback_states` 不接收播客条目；播客队列走独立端点，`available_tracks()` 的曲目校验保持不变。
14. 加入待播或收藏不隐式关注节目，只建立单集级引用。

## 3. 基线与新集分发

判定「新集」的依据是**服务端首次见到该 `(podcast_id, guid)`**，不是 `pub_date`、`podcast_episodes.created_at` 或 `podcast_follows.created_at` 之间的日期比较。RSS 首次抓取会一次性写入 feed 中全部历史单集，用时间比较会把它们全部误判为新集。

- 用户首次关注某节目时，把当时已存在的全部单集记为基线，按 `(user_id, podcast_id)` 保存。基线内的集不触发任何规则。
- 后续抓取中新插入的 guid 才触发分发：遍历该节目的关注者，按各自「新集自动待播」设置写入待播队列或稍后听池。
- 分发在服务端抓取事务内完成，只处理成功插入的集；抓取部分失败时不重放。
- 老数据迁移必须为所有现存 `(user_id, podcast_id)` 补写基线完成标记，避免升级后首次刷新灌入历史单集。
- 取关再关注不重置基线，进度与偏好保留。节目合并去重时基线随保留节目迁移。

## 4. 新集自动待播设置

向用户呈现精简的三选项选择器：

| 值 | 行为 | 适用 |
| :--- | :--- | :--- |
| `ignore` | 关闭（仅关注） | 连载、按旧到新追更 |
| `queue_last` | 自动加到队尾 | 每期都听、不急于插队（默认） |
| `queue_next` | 自动插到当前播放之后 | 新闻、日更 |

- **Legacy 选项归一化**：服务端历史值或旧客户端上报的 `inbox` 选项在客户端统一映射并展示为 `queue_last`。
- **界面降噪**：主界面彻底移除单节目上限数字微调框（spinbox / stepper），后台静默保留安全上限（默认 3）以防队列暴涨，设置按 `(user_id, podcast_id)` 存服务端并跨设备同步。
- 设置必须存服务端：分发发生在服务端抓取处，若设置只留本机，会出现「手机开了自动入队、Mac 没开却看到同一份云端队列」的不一致。

## 5. 自动续播规则

客户端纯函数 `nextEpisode(current, detail, progress, preference)`，输入为当前集、节目单集列表、每集进度与偏好，输出下一集或停止。四端共用同一组测试向量。

- 以当前集所属节目为边界，不跨节目合并。
- 排序方向为跟随列表 / 从旧到新 / 从新到旧 / 关闭，默认跟随；默认跳过已听完。
- 只在待播队列为空时接管；队列非空一律按队列走。
- 关闭自动续播只停止预览，保留手动队列。
- 不沿用音乐的随机或循环模式。
- 预览项可「加入待播」转为真实条目；本次主动移除的预览项不回插。
- 「从第一期开始追更」把续播锚点设到最早未听集并按从旧到新播放，不向队列写入整批条目。

## 6. API

需要登录，按当前认证用户隔离，沿用既有 Web CSRF 或 Android 认证方式。路径相对 `/api/v1`。

`GET /podcasts/inbox` 返回 `{version, items:[{episode_id, podcast_id, source, added_at}]}`。

`PUT /podcasts/inbox/items/{episode_id}` 幂等加入，`DELETE` 同路径移除。单集不存在返回 404。

`GET /podcasts/queue` 返回 `{version, device_id, items:[{episode_id, origin}], updated_at}`。

`PUT /podcasts/queue` 请求 `{version, device_id, items:[{episode_id, origin}]}`，整份 CAS 替换。版本落后返回 409 `{"detail":{"code":"podcast_queue_conflict","current":{...}}}`；条目不是真实可访问单集返回 422。冲突后客户端保留本机队列并提示，不静默覆盖。

`GET /podcasts/queue/preferences` 与 `PUT /podcasts/queue/preferences` 读写 `{default_action, auto_limit, auto_continue, shows:{[podcast_id]:{action, auto_limit, order, skip_completed, auto_continue}}}`，标量后写覆盖，`shows` 按提交映射同步。客户端读取续播偏好的优先级统一为：**节目单独设置 → 账号默认值 → 网络不可用时使用对应账号的本地缓存**。

`PUT /podcasts/episodes/{episode_id}/favorite` 请求 `{favorite: bool}` 或 `{loved: bool}`（缺省默认为 true），返回 `{episode_id, favorite: bool, loved: bool}`。单集不存在返回 404。收藏后冻结底层音频零引用计时；取消收藏且无其他引用时恢复零引用计时。

`GET /podcasts/favorites/ids` 返回当前用户收藏的全部单集 ID 列表 `{ids: [str]}`。

`GET /podcasts/favorites` 返回当前用户收藏的全部单集详细列表（附带节目元数据、收听进度与下载状态）。

`GET /podcasts/discover` 与排行榜查询具备服务端与客户端 1 小时 TTL 缓存，支持空闲时静默预加载。

队列条目只允许本用户有权访问的节目单集 ID；服务端校验节目授权，不信任客户端提交的排序外字段。所有写操作不产生音乐收听统计、推荐反馈或 Last.fm 记录。

## 7. 边界状态

- 待播列表为空：提示「待播列表为空」，说明加入待播或关注节目更新后会出现在这里，给出浏览节目入口。
- 队列为空：区分「自动续播开启，播完会接下一集」与「已关闭，播完即停」。
- 单集收藏列表为空：提示「暂无收藏单集」，说明在单集菜单或详情中点击「单集收藏」可快速标记并保留音频。
- 加载：队列同步、节目详情读取各有布局匹配的骨架，不阻塞当前播放；探索榜单优先使用 1 小时内存缓存，避免白屏或转圈。
- 错误：同步失败保留本机队列并平静说明「暂时无法同步，本机播放不受影响」及重试入口；单集失效说明原因与下一步。
- 权限不足：普通账号按服务端校验，不显示无响应的管理入口。
- 超限：队列达到软上限时说明实际加入数量，不静默截断；自动入队上限触发时把溢出项移入稍后听。

## 8. 验收场景

1. 关注一个已有数百集的节目，待播列表为空，节目页可浏览全部历史集。
2. 之后 RSS 出现新集：默认进队尾（`queue_last`）；`queue_next` 时插到当前之后；`ignore` 时不入队；旧设置 `inbox` 在界面归一化为加到队尾。
3. 单集列表行内三态快速切换：点击 `+ 待播` 变为 `✓ 已待播` 且加入待播列表；再次点击 `✓ 已待播` 从待播中移出恢复为 `+ 待播`；正在播放的单集按钮变为 `正在播放` 且禁用点击。
4. 头部快捷操作：存在待播单集时，点击 `▶ 播放待播 (N)` 立即顺次起播待播单集。
5. 单集菜单点击 `标为已听完`，进度更新至 100% 并显示 `✓ 已听完` 状态标签，整行置灰降低透明度，底部进度条隐藏；点击 `标为未听` 进度重置为 0，恢复正常行样式。
6. 单集菜单或单集详情中点击 `单集收藏`，单集标记为已收藏；节目详情单集工具栏选择 `已收藏` 过滤标签，只展示被收藏的单集。
7. 收藏的单集音频在服务端受到防清理保护：即使零引用且未听完，自动或手动资源清理也不会删除其音频文件。
8. 探索榜单在 1 小时内重复打开无需重新拉取网络，秒开展示无转圈。
9. 手机排好队列，Mac 打开顺序一致；两台设备并发修改不丢数据，版本冲突可见。
10. 播放某集后原有队列保留；播完自动出队并标记已听完；队列空时自动续播接上。
11. 队列里只出现显式条目，自动续播不写入队列；关闭自动续播后播完即停。
12. 加入待播或稍后听不产生关注；播客队列不污染音乐接续快照。
13. 四端空、加载、错误、权限不足状态与窄屏、浅深主题逐张核对。
