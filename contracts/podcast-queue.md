# 播客稍后听、待播队列与新集处理

2026-11-07 新增。适用于 Web / Android / macOS / iOS 四端。本文描述目标行为与接口，实现与验证状态见文末，不代表已全部交付。

取代此前各端自行推导续播的做法：Web 的动态自动尾部、macOS 的一次性全量入队、Android 的单集队列都按本文收敛。相关背景见 [播客单集进度与音乐接续](podcast-progress.md)。

## 1. 四个概念

| 概念 | 用户感知 | 职责 | 存储 |
| :--- | :--- | :--- | :--- |
| 稍后听 | 攒着以后听 | 无序候选池，不决定播放顺序 | 服务端，按用户，跨设备 |
| 待播队列 | 接下来按顺序听 | 有序播放清单，播完出队 | 服务端，按用户，带版本，跨设备 |
| 自动续播 | 队列空了自动接下一集 | 播放器策略，不生成队列条目 | 客户端本地派生，不同步 |
| 新集处理 | 节目更新后去哪 | 按节目设置把新集分发到前两者 | 服务端，按用户＋节目，跨设备 |

订阅（关注）只决定是否接收节目更新，不产生任何列表条目。自动下载与预缓存管的是音频文件，与上述四者无关；Android 的「预缓存下一集」文案不得被理解为下一集入队。

## 2. 不变式

1. 订阅、首次抓取、OPML 导入、节目合并去重都不向稍后听或队列写入历史单集。
2. 待播队列只装用户显式加入的条目，或用户显式开启的「新集处理」规则产生的条目。
3. 自动续播不写队列；界面「接下来」中的自动部分是只读预览，不参与拖拽与排序。
4. 队列条目带来源 `manual | rule`；用户拖动 `rule` 条目即转为 `manual`，移除即删除。
5. 播放某集时把它插到队首并保留其余队列，不清空已排好的内容。
6. 稍后听、队列、偏好按账号隔离并跨设备同步；自动续播预览不同步。
7. 音乐接续快照 `playback_states` 不接收播客条目；播客队列走独立端点，`available_tracks()` 的曲目校验保持不变。
8. 加入待播或稍后听不隐式关注节目，只建立单集级引用。

## 3. 基线与新集分发

判定「新集」的依据是**服务端首次见到该 `(podcast_id, guid)`**，不是 `pub_date`、`podcast_episodes.created_at` 或 `podcast_follows.created_at` 之间的日期比较。RSS 首次抓取会一次性写入 feed 中全部历史单集，用时间比较会把它们全部误判为新集。

- 用户首次关注某节目时，把当时已存在的全部单集记为基线，按 `(user_id, podcast_id)` 保存。基线内的集不触发任何规则。
- 后续抓取中新插入的 guid 才触发分发：遍历该节目的关注者，按各自「新集处理」设置写入稍后听或队列。
- 分发在服务端抓取事务内完成，只处理成功插入的集；抓取部分失败时不重放。
- 老数据迁移必须为所有现存 `(user_id, podcast_id)` 补写基线完成标记，避免升级后首次刷新灌入历史单集。
- 取关再关注不重置基线，进度与偏好保留。节目合并去重时基线随保留节目迁移。

## 4. 新集处理设置

每个节目四选一，默认 `inbox`：

| 值 | 行为 | 适用 |
| :--- | :--- | :--- |
| `inbox` | 进稍后听，不占队列（默认） | 一般订阅 |
| `queue_last` | 自动加到队尾 | 每期都听、不急于插队 |
| `queue_next` | 自动插到当前播放之后 | 新闻、日更 |
| `ignore` | 不处理，只留在节目页 | 连载、按旧到新追更 |

另有「每节目最多自动入队 N 集」上限，超出的最老 `rule` 条目移入稍后听而不是丢弃。设置按 `(user_id, podcast_id)` 存服务端并跨设备同步；个人设置里可改全局默认值，节目页可覆盖。OPML 导入与节目合并继承全局默认，不自动开启自动入队。

设置必须存服务端：分发发生在服务端抓取处，若设置只留本机，会出现「手机开了自动入队、Mac 没开却看到同一份云端队列」的不一致。

## 5. 自动续播规则

客户端纯函数 `nextEpisode(current, detail, progress, preference)`，输入为当前集、节目单集列表、每集进度与偏好，输出下一集或停止。四端共用同一组测试向量。

- 以当前集所属节目为边界，不跨节目合并。
- 排序方向为跟随列表 / 从旧到新 / 从新到旧 / 关闭，默认跟随；默认跳过已听完。
- 只在待播队列为空时接管；队列非空一律按队列走。
- 关闭自动续播只停止预览，保留手动队列。
- 不沿用音乐的随机或循环模式。
- 预览项可「加入待播」转为真实条目；本次主动移除的预览项不回插。
- 「从第一期开始追更」把续播锚点设到最早未听集并按从旧到新播放，不向队列写入整批条目。

## 6. API

需要登录，按当前认证用户隔离，沿用既有 Web CSRF 或 Android 认证方式。路径相对 `/api/v1`。

`GET /podcasts/inbox` 返回 `{version, items:[{episode_id, podcast_id, source, added_at}]}`。

`PUT /podcasts/inbox/items/{episode_id}` 幂等加入，`DELETE` 同路径移除。单集不存在返回 404。

`GET /podcasts/queue` 返回 `{version, device_id, items:[{episode_id, origin}], updated_at}`。

`PUT /podcasts/queue` 请求 `{version, device_id, items:[{episode_id, origin}]}`，整份 CAS 替换。版本落后返回 409 `{"detail":{"code":"podcast_queue_conflict","current":{...}}}`；条目不是真实可访问单集返回 422。冲突后客户端保留本机队列并提示，不静默覆盖。

`GET /podcasts/queue/preferences` 与 `PUT /podcasts/queue/preferences` 读写 `{default_action, auto_limit, shows:{[podcast_id]:{action, auto_limit, order, skip_completed, auto_continue}}}`，标量后写覆盖。

队列条目只允许本用户有权访问的节目单集 ID；服务端校验节目授权，不信任客户端提交的排序外字段。所有写操作不产生音乐收听统计、推荐反馈或 Last.fm 记录。

## 7. 边界状态

- 稍后听为空：说明关注的节目更新后会出现在这里，给出浏览节目入口。
- 队列为空：区分「自动续播开启，播完会接下一集」与「已关闭，播完即停」。
- 加载：队列同步、节目详情读取各有布局匹配的骨架，不阻塞当前播放。
- 错误：同步失败保留本机队列并平静说明「暂时无法同步，本机播放不受影响」及重试入口；单集失效说明原因与下一步。
- 权限不足：普通账号按服务端校验，不显示无响应的管理入口。
- 超限：队列达到软上限时说明实际加入数量，不静默截断；自动入队上限触发时把溢出项移入稍后听。

## 8. 验收场景

1. 关注一个已有数百集的节目，稍后听与队列都为空，节目页可浏览全部历史集。
2. 之后 RSS 出现新集：默认进稍后听；改为 `queue_last` 时进队尾；`queue_next` 时插到当前之后；`ignore` 时两处都不出现。
3. 老数据升级后首次刷新不灌入历史单集；取关再关注、OPML 批量导入、节目合并同样不灌入。
4. 手机排好队列，Mac 打开顺序一致；两台设备并发修改不丢数据，版本冲突可见。
5. 播放某集后原有队列保留；播完自动出队并标记已听完；队列空时自动续播接上。
6. 队列里只出现显式条目，自动续播不写入队列；关闭自动续播后播完即停。
7. 加入待播或稍后听不产生关注；播客队列不污染音乐接续快照。
8. 四端空、加载、错误、权限不足状态与窄屏、浅深主题逐张核对。
