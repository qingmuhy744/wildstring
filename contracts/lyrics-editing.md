# 歌词编辑与网页逐行打点

状态：实现于当前分支，验收结果见交付说明。管理员在“编辑歌曲信息 → 歌词”独立编辑和保存歌词，普通用户读取共享的生效结果。首批仅保存数据库覆盖，不写入音频标签或同名歌词文件。歌词与歌曲基本信息分别保存。

## 接口

下列接口要求管理员会话，写请求和预览要求 `X-Wildstring-Client: web|android|ios`。

- `GET /api/v1/manage/tracks/{id}/lyrics`：返回 `{track_id,version,file_version,override,observed,observed_text,effective,text}`。
- `POST /api/v1/manage/tracks/{id}/lyrics/preview`：提交 `{text:string|null}`，使用正式解析器返回 `{kind,source,lines}`，不保存。
- `PUT /api/v1/manage/tracks/{id}/lyrics`：提交 `{version,file_version,text}`，返回更新后的编辑记录。

`text:null` 恢复文件歌词，`text:""` 明确不显示歌词，其余为纯文本或 LRC。`override` 为保存的原文或 null，`observed_text` 为从当前文件歌词整理出的可编辑文本。`version` 从 1 开始；并发保存、托管音频或已解析文件歌词变化导致 409 `lyrics_version_conflict`，不会覆盖其他人的新结果。

上限为 UTF-8 512 KiB、5000 行及 5000 个时间标签，拒绝 NUL、超限和不合法时间；有时间标签时不能混入未标时间的歌词行，以免静默丢句。沿用 [本地歌词解析规则](local-library-assets.md)，保存前可预览排序与相同时间的译文合并结果。

公开读取路径仍为 `GET /api/v1/tracks/{id}/lyrics`，向全部已登录用户开放。增加 `source:"user"`，优先级为人工覆盖 → 同名 LRC → 内嵌 → 同名文本。空覆盖返回 none；重扫不删除覆盖，恢复文件歌词后重新应用文件优先级。

## 网页制作流程

1. 粘贴或编辑歌词，每句一行，也可直接编辑 LRC。
2. 进入“逐行打点”，选择播放这首歌；共用现有音频元素与真实时间线。编辑其他歌曲不会自动替换正在播放的歌曲，只有明确点击播放才切换。
3. 听到下一句开始时按空格，或点击“下一句（空格）”；记录整曲真实毫秒位置，切换当前句和下一句。第一下记录第一句起始时间；支持中间空行作为间奏。输入框中的空格、长按重复及输入法组合不触发打点，暂停/缓冲/跳转期间不记录时间。
4. 可选中句子重新打点，撤销最近操作，逐句输入秒数、试听或统一偏移。已标时间必须非递减，完成全部句子后才能生成同步歌词；允许相同时间的译文。
5. 预览和试听，再保存；支持导出 UTF-8 `.lrc`。未全部打点不能把未打点句子虚构为 0 秒。纯文本仍可直接预览并保存，不承诺自动识别时间。

保存不重新加载音频源；当前网页的全屏歌词会重新读取。其他已打开的客户端通过既有刷新/重新读取获得新歌词，首批没有跨设备实时推送。服务器没有 ASR、自动音频对齐或逐字卡拉 OK 时间轴。

流程参考 [LZL 歌词工具](https://lzltool.com/audio-lrc)，直接使用服务端曲库音频，无需重新上传歌曲。快捷键按本项目约定使用空格切句。
