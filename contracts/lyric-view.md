# 歌词视图跨端契约

状态：本批实现 Web 全屏播放页；Android 现有实现基本符合，macOS／iOS 待实现，逐项状态见第 6 节。验证边界见交付说明。本契约只约束**展示与交互**；歌词解析、时间轴、译文配对、偏移与编辑仍见 [歌词编辑](lyrics-editing.md) 和 [本地歌词解析规则](local-library-assets.md)。

数据来自 `GET /api/v1/tracks/{id}/lyrics` 的 `kind: none | plain | synced` 及 `lines[].time_ms / words / translation / romanization`。四端共用同一份数据，不另建客户端时间轴，不伪造时间。

## 1. 定位：内容决定可滚动区间

当前行只由播放进度决定。定位用同一条公式，不为「歌曲开头」「歌曲结尾」「短歌词」写按设备或按行数区分的特例：

```
scrollTop = clamp(lineCenter − H/2, 0, maxScroll)
```

- `lineCenter` 为当前行中心相对滚动内容顶部的距离（含上边距），按**实测行高**累计；行高必须包含译文、音译、字号与换行后的高度。
- `H` 为歌词视口高度，`maxScroll = scrollHeight − H`。
- 长歌词：`top = 24px`（若语言开关浮在歌词滚动区域内则 40px），`bottom = H/2`。底部留白使 `maxScroll` 足够大，最后几行仍能居中。
- **短歌词**（内容高度 ≤ `H − 2 × top`）：`top = bottom = (H − contentHeight)/2`，整块垂直居中，`maxScroll = 0`，不滚动；切行只换高亮，不触发位移动画。
- 歌曲开头 `lineCenter < H/2` 时被 `0` 钳住，歌词从上方开始、后续行同时可见；禁止把第一行强行拉到视口正中。

禁止使用「前 N 行置顶」这类按行数写死的判断：行高随语言、字号和换行变化，必须按像素或实测高度判断。

## 2. 高亮：只属于当前行

- 视觉强调只给 `active`（播放进度所在的当前行），与 `DESIGN.md` §2.3 一致。已播过的行与未播行**同色、同样弱化**，不给过去的内容留强调色。
- 逐字着色只允许出现在 `active` 行内；其它行渲染纯文本（可由 `words[].text` 拼接），不渲染逐字渐变，避免已播行 `progress = 100%` 后整行保持主题色、比当前行更亮。
- 手动滚动回看只移动视口，**不改变高亮**。视口中心行（`candidate`）只用于跳转预览的目标时间，不参与高亮判断。
- 播放尚未开始、歌词无时间轴或为 `plain` 时不高亮任何行。

## 3. 跟随恢复：两端共用一套状态机

播放中任何手动浏览（滚轮、拖动、触摸滑动）都会暂停自动跟随，并在**停止操作约 2 秒**后平滑回到当前行。触屏与键鼠共用该状态机，不因输入方式取消自动恢复。

以下条件必须同时满足才开始计时：

1. 没有进行中的拖动与惯性滚动；每次新的滚动／拖动重置计时。
2. 播放处于进行中；暂停时不计时，恢复播放后重新开始计时（暂停期间用户可自由查看歌词）。
3. 歌词为 `synced` 且当前行有效。
4. 用户没有通过「跟随播放／回到当前歌词」按钮、点击歌词行或确认跳转提前恢复。

恢复跟随只移动视口，**不改变播放位置**；跳转必须来自用户显式操作。默认 2 秒可配置（Android `lyric_follow_seconds`，取值 1/2/3/5/10 秒），其它端未提供设置项时固定 2 秒。按钮始终作为即时入口保留。

## 4. 触屏与键鼠的分流

分流只在「怎么操作」，不在「滚到哪儿」与「何时恢复」：

| 行为 | 触屏 `pointer: coarse` | 键鼠 `pointer: fine` |
| :--- | :--- | :--- |
| 定位公式 | 共用第 1 节 | 共用第 1 节 |
| 恢复跟随 | 共用第 3 节，2 秒 | 共用第 3 节，2 秒 |
| 点歌词行 | 切换封面／面板（防误触） | 直接跳转 |
| 跳转确认 | 滑动后时间预览，显式确认才跳转 | 不需要二次确认 |
| 大封面 | 长按 | 长按或右键菜单 |

## 5. 状态、边界与动效

- Loading、Empty、Error、权限不足四态齐备且布局一致；读取失败平静说明「原因 + 下一步操作」，重试不改变播放；`none` 与 `plain` 歌词不伪造时间轴、不高亮、不自动滚动。
- 切换译文／音译／字号、窗口尺寸变化、歌词重新读取后必须重新计算行高与锚点。
- 动效仅 `transform/opacity`（Web 使用原生 `scrollTo({ behavior: 'smooth' })`，不自行逐帧改 `scrollTop`），遵守 `prefers-reduced-motion`；恢复跟随与切行使用同一种滚动方式。
- 语义：当前行用 `aria-current`，确认跳转按钮可命名，歌词／队列切换保留键盘焦点。
