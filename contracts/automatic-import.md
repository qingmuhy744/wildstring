# 自动发现、预检与待整理

首批已实现，schema v7。当前仍是一个部署配置的导入源、一个托管曲库；未接入下载器回调、外部信息来源、音频指纹匹配或 AI 自动修复。

## 入口与策略

管理 → 导入与整理。自动发现默认关闭，可保存检查间隔（15–86400 秒，默认 60）与稳定期（5–86400 秒，默认 120）。启用后由现有持久任务 Worker 定期检查；手动“导入音乐”视为用户声明源已准备就绪，不等待稳定期。静默期只是完成状态的推断，不能保证下载完整；下载器完成状态接入仍为后续工作。

自动观察保存文件的设备、inode、大小、纳秒修改时间，以及同目录 CUE/歌词/封面版本。变化后重新等待；重启保留观察时间与待整理记录。不会每次重读全部音频或把整库发送给模型。源离线或单项无法读取时后续可继续检查，已入库音乐照常播放。文件事件监听、下载器通知尚未实现。

默认忽略隐藏音频和符号链接。导入源始终只读；未知格式维持跳过。输入接受 MP3、FLAC、M4A，新增 WAV 的预检与转换；实际支持的 WAV 转换限于 16/24 位整数 PCM、1–8 声道。

## 预检和待整理

- 已有导入映射保持原来的保护语义：源变化报告冲突，不覆盖库内副本；库内副本缺失不擅自恢复。
- 新文件缺标题/歌曲艺人/专辑时暂存等待整理。只有专辑艺人而没有歌曲艺人时可用于补齐数据库值；单文件对应的 CUE 可以补缺失标签，不自动替换已有值。同目录同专辑有不同歌曲艺人而缺专辑艺人时，要求核对合辑归属。
- 目标路径已有不同内容的新文件时进入待整理，不能直接靠后缀消解发行版歧义；用户确认后可保留指纹后缀，两份都不覆盖。完全相同来源仍可复用；对人工明确指定到另一归档路径的文件，不复用成同一个曲目再改写旧曲目标签。
- 问题音频复制到 `<data_dir>/intake/<item_id>/<version>/source.<扩展名>`，匹配侧车一并保存；普通扫描不发布暂存文件。待整理暂不提供播放入口。
- 补充六项基础信息后，以项目版本和源文件版本校验确认，再由后台继续导入。普通压缩音频保存数据库覆盖，不对音频写标签；转换产生的新 FLAC 使用已确认的信息。后续重扫保留覆盖；自动补全只应用一次，用户清除覆盖后不会被下次导入悄悄恢复。
- 可忽略或重试失败项；源版本改变后重新检查。忽略不删除原件或暂存副本。暂存归档与忽略项尚无自动清理，需要计入容量规划。

每项独立处理，待整理或失败不阻断其他曲目。转码前检查空间，预留源暂存、输出及 32 MiB 余量；这是单项检查，不代表整批容量已预留。家用服务器部署前仍需把持久数据挂到大盘并核对 UID/组的读取权限。

## WAV / FLAC 整轨与 CUE

有效单镜像 CUE 可自动分轨，分轨文件中的单文件条目用于补齐缺失信息。仅引用不存在旧镜像的残留 CUE 不会触发再次拆分。CUE 支持 UTF-8、UTF-16 BOM、GB18030；拒绝路径逃逸、错误曲序、超范围/非整数采样边界、合成 PREGAP/POSTGAP 与首曲隐藏间隙，不猜测或丢弃音频。多镜像复杂 CUE、DSD、浮点 WAV、32 位 PCM 等尚不自动转换。

曲间 INDEX 00 间隙保留在前曲末尾；按 INDEX 01 切分，所有源样本恰好保留一次。Python 生成固定 FFmpeg 参数，单次解码分发到各曲 FLAC；不重采样、不降位深、不混音、不应用音量归一化。转换后重新解码所有输出，比较采样参数、总样本数与拼接 PCM SHA-256，再发布到正式曲库。输出内嵌封面予以继承；单曲 WAV 的 USLT 歌词也继承，整轨歌词尚不自动分割时间轴。源完整暂存副本与原 CUE 保留；原 WAV 的所有私有 RIFF 块并不保证映射进 FLAC。

每个子进程有 30 分钟上限，仅启用本地文件/管道协议，无用户自定义 Shell。失败清理本轮转换输出；成功的文件及任务记录持久保留，重复执行复用已发布副本。不承诺浏览器无缝播放或所有编码直放。

## 管理接口

以下接口沿用管理员认证，写请求要求 `X-Wildstring-Client: web`：

- `GET /api/v1/manage/intake/settings`、`PUT`：`{version, enabled, interval_seconds, stable_seconds}`，过期版本 409。
- `GET /api/v1/manage/intake/items?limit=20&offset=0`：分页待处理项，含版本、原始信息、候选覆盖、原因与是否可补充。状态为 waiting/ready/review/approved/retry/imported/failed/conflict/ignored，完成与忽略项不在默认列表显示。
- `POST /api/v1/manage/intake/items/{id}/approve`：`{version, overrides}`。字段规则同单曲编辑；缺基础信息 422，源变化、不可编辑或版本冲突 409。确认后提交后台导入，与已有任务协调。
- `POST .../{id}/ignore`、`POST .../{id}/retry`：`{version}`；重试只接受 failed 项，不授权覆盖已入库冲突。

## 验证入口

`make ci` 检查项目与浏览器测试；主机没有 FFmpeg 时转换用例会明确跳过。`make docker-test` 使用生产镜像内的 FFmpeg、锁定开发依赖、非 root 与只读根文件系统运行全部后端测试，不挂载用户音乐或生产数据。CI 安装 FFmpeg，并同时运行容器测试。

后续依次扩展下载完成通知、多导入源策略、NFO/旧库匹配、完整发行版本识别，以及外部候选和 AI 工具。Agent 不负责猜测切分位置或直接执行任意文件操作。
