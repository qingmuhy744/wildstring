# 曲库管理接口

已实现首批管理页，SQLite schema v11。所有 `/api/v1/manage` 接口要求管理员会话，写请求和模型测试还要求 `X-Wildstring-Client: web|android|ios|macos`。共用当前 Python 服务，不增加独立任务服务。

## 概览与设置

- `GET /overview`：曲目总数、不可用数、音频大小、可用专辑/艺人数、导入源/托管库/运行目录及所在文件系统剩余空间、最近扫描、活动任务、曲库名称与应用/数据库版本。
- `PUT /preferences`：提交 `{name, version}`，持久化当前曲库的显示名称；版本过期返回 409。
- 路径和网络部署配置首批只展示，不提供任意目录浏览或根目录切换。Docker 中返回容器路径和服务端连接地址，不能当作宿主机路径或公网入口。

概览总曲目包含保留的缺失/不可读记录，另外列出不可用数量；专辑/艺人只汇总可用曲目。大小来自数据库记录，不递归测量整个卷；剩余空间来自所在文件系统，多个目录可能共用同一磁盘。

## 导入与扫描任务

- `POST /jobs`：提交 `{kind: "import"|"scan", full: false|true}`，返回 202 和任务。导入复制新文件并扫描；扫描只检查托管库，`full` 要求重新读取全部标签。
- `GET /jobs?limit=20&offset=0`、`GET /jobs/{id}`：分页任务历史和单项状态。包含关联导入/扫描记录、当前计数与最多 100 条逐文件错误；不伪造全库处理百分比。
- 状态为 `queued`、`running`、`completed`、`completed_with_errors`、`failed`、`interrupted`。网页任务历史从本功能启用后开始记录；既有 CLI 扫描可在“最近扫描”查看。

任务写入 SQLite 后再交给工作线程。每个运行目录通过 `admin-worker.lock` 选出一个消费者，实际导入/扫描沿用 `library-scan.lock` 与 CLI 互斥。同库只有一个排队或执行中的任务：相同请求返回已有任务，其他请求返回 409；等待 CLI 时仍为排队状态。

关闭网页不停止任务。服务重启后排队任务继续，丢失执行进程的任务及其关联运行记录标记中断，不自动重放；可重新提交一次任务。单进程正常关闭会等待工作线程最多 5 秒，较长任务在进程退出后由下次启动识别为中断。尚无取消、定时计划或分阶段断点续传。

工作线程检查运行目录的文件系统标识；目录丢失或被替换时停止领取任务，恢复原目录或重启服务后再处理。运行中的普通数据库连接不创建缺失的数据库，避免存储失联后误建空库；只有服务初始化显式创建数据库。

## 单曲编辑

- `GET /tracks/{id}/metadata`：返回 `{track_id, version, observed, overrides, effective}`。
- `PUT /tracks/{id}/metadata`：提交 `{version, overrides}`；`overrides` 为完整的人工覆盖集合，移除键即恢复该字段的文件观测值。
- 可编辑字段为 `title`、`artists`、`album`、`album_artists`、`track_number`、`disc_number`。艺人使用真实字符串数组，网页每行一位，不切分 AC/DC 等名称。空艺人数组、空专辑/编号允许明确清除；编号为 1–99999 整数或 null，标题不能为空。
- 版本冲突返回 409，未知/跨库 ID 返回 404，未知字段或错误类型返回 422。编辑版本在人工保存或文件观测值变化时递增，未变化的全量重扫不制造冲突。

文件观测值与人工覆盖分别保存；事务中更新 `tracks` 的生效字段、搜索文本和专辑 ID，因此歌曲、艺人、专辑、收藏与普通/规则歌单查询共用生效值。重扫更新观测值再应用覆盖，保留曲目 ID、收藏/歌单引用和收听记录。变更艺人/专辑名称可能改变其派生聚合 ID，不改变歌曲 ID。

首批预览和保存只更新数据库；编辑当前歌曲仅刷新播放器显示，不重新设置音频源。导入源原件始终只读，托管副本允许后续显式写回与重整，但本版本未实现这两种操作。已增加独立保存的歌词编辑与网页逐行打点，见 [歌词编辑接口](lyrics-editing.md)。批量、封面编辑与元数据自动匹配待后续交付。

## AI API 连接

- `GET /ai`：版本、API 基础地址、模型 ID、超时、是否配置、是否有密钥；永不返回密钥。
- `PUT /ai`：提交 `{version, base_url, model, timeout, api_key?, clear_api_key?}`。空/缺省 `api_key` 保留原值，`clear_api_key: true` 清除；本地无鉴权服务允许无密钥。版本冲突返回 409。
- `POST /ai/test`：使用已保存配置发送一条简短 Chat Completions 请求，成功表示模型返回兼容响应；不表示支持工具调用或 Agent 任务。会消耗少量 token，未配置时返回 409，网络/模型错误返回脱敏的 502。

当前支持一个兼容 Chat Completions 的 API，URL 包含服务所需的基础路径（如 `/v1`），模型名称手动填写。仅接受 HTTP/HTTPS、1–120 秒超时；不接受 URL 中的凭据、查询参数或片段，不跟随重定向转发密钥。响应读取上限 64 KiB，探测请求不携带曲库信息。

配置保存在持久运行目录 `ai/.env`，专用文件锁和版本检查串行化保存，临时文件 fsync 后原子替换，密钥文件权限为 0600。它是服务端的明文凭据文件，应随私密运行数据保护；不写入曲目数据库、前端包或日志，不任意改写项目部署 `.env`。API 校验错误同样不回显提交的密钥。当前没有多供应商配置、模型列表发现或模型工具兼容测试。

内置整理 Agent、自然语言找歌/歌单和 MCP 尚未实现；框架建议与后续边界见 [设计讨论](../docs/decisions/0002-ai-connections-and-agent.md)。AI 未配置或失败不阻断基础管理、浏览和播放。

## 自动发现与待整理

管理页新增“导入与整理”，共享现有任务 Worker；默认关闭自动发现。设置、待整理审批、重试和转换边界见 [自动导入接口](automatic-import.md)。

## 账号与访问设置

管理员可管理本地账号、角色、停用与密码重置；所有用户通过账号设置修改自己的密码。设置页增加默认关闭的 Host 白名单，误配置锁定后需直接修改数据库恢复。权限、个人数据隔离和恢复命令见 [账号与访问接口](users-and-access.md)。网页外观提供浅色、深色和跟随系统，保存在浏览器，不属于实例级设置。
