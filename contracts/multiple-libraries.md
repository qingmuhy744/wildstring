# 多库、个人关注和共享内容

本契约描述本轮实现目标，验证状态在 v0.8.0 发布说明中分别记录。沿用同一个数据库、
账号和会话；导入源只读，音乐复制到各库的托管目录。旧库、曲目、歌单和进度 ID 保留。

## 曲库与授权

`GET /api/v1/libraries` 返回当前用户获授权且启用的库。所有者可访问所有库。
`POST /api/v1/libraries`、`PUT /api/v1/libraries/{id}` 仅所有者可调用，写入要求客户端标头。
配置体为 `{name,source_roots:[绝对目录]}`，修改另携带 `version`，可用 `enabled` 停用库。
新库托管目录默认由服务端生成，可指定独立可写目录；已有库切换目录必须通过显式迁移。目录不能与导入源重叠。重复、父子重叠来源拒绝配置。
停用库或移除来源不删除托管音频。默认库保留，避免破坏旧客户端与私人记录的容器。

`GET/PUT /api/v1/libraries/access/{user_id}` 仅所有者可用。响应和更新分别包含
`{version,library_ids:[id]}`；版本冲突返回 409，任一库无效则整批不写入。
新库不自动授予非所有者。旧库在迁移时保留现有用户访问权限。
旧版创建账号请求未提供库字段时只授予默认库；新版明确传入 `library_ids`，空数组不授权音乐库。

浏览使用查询参数 `library_id` 或 `X-Wildstring-Library` 选择库，`all` 表示全部可访问库。
单个对象的读取和写入按真实所属库再次授权，不能凭传入另一个库绕过。
角色能力与库授权同时成立，才允许导入、编辑、播放、封面和下载。未授权对象返回 404。
后台工作保留提交用户和目标库，执行时重新检查；AI/MCP 使用同一范围。

歌单归当前账号，普通歌单可以引用多个获授权库的曲目。详情、统计、封面与播放仅包含
当前有权限的可用曲目；撤权不删除私人引用，重新授权后恢复。排序保留隐藏引用与槽位。
收藏继续使用原有个人记录，提供跨可访问库的统一入口。

## 播客

节目、单集、RSS 更新和服务端音频文件共享。节目响应增加 `followed`，默认 false。
`GET /api/v1/podcasts?followed=true` 仅返回当前账号关注；省略仍返回本服节目，兼容旧客户端。
`PUT /api/v1/podcasts/{id}/follow` 接收 `{followed:true|false}`，要求登录与客户端标头，
听众可用。重复请求幂等，不修改其他账号；取关保留进度，也不删除共享缓存。
新增 RSS 与删除共享节目仍需曲库管理权限。旧节目不自动替所有账号关注。

未听预缓存按关注者的个人进度判断，不固定使用 admin。关注、进度和显式个人保存引用独立。
听完不删除共享文件；只有零引用、未保护且未使用的音频才参与管理员清理。
旧缓存默认保护，自动清理默认关闭；具体 API、保留期和租约见[存储与共享资源契约](storage-and-podcast-resources.md)。
