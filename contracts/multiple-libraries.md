# 多库、个人关注和共享内容

本契约描述本轮实现目标，验证状态在 v0.8.0 发布说明中分别记录。沿用同一个数据库、
账号和会话；导入源只读，音乐复制到各库的托管目录。旧库、曲目、歌单和进度 ID 保留。

## 曲库与授权

`GET /api/v1/libraries` 返回当前用户获授权且启用的库。所有者可访问所有库。
`POST /api/v1/libraries`、`PUT /api/v1/libraries/{id}` 仅所有者可调用，写入要求客户端标头。
配置体为 `{name,source_roots:[绝对目录]}`，修改另携带 `version`，可用 `enabled` 停用库。
新库托管目录默认由服务端生成，可指定独立可写目录；已有库切换目录必须通过显式迁移。目录不能与导入源重叠。重复、父子重叠来源拒绝配置。
停用库或移除来源不删除托管音频。默认库保留，避免破坏旧客户端与私人记录的容器。

`GET/PUT /api/v1/libraries/access/{user_id}` 仅所有者可用。响应和更新分别包含
`{version,library_ids:[id]}`；版本冲突返回 409，任一库无效则整批不写入。
每个库有 `default_access`（新用户默认可访问）。新建库默认关闭，旧默认库迁移为开启，其他旧库为关闭；迁移和修改此开关都不改变已有用户授权。
创建账号省略 `library_ids` 时仅授予启用且开启 `default_access` 的库；明确传入的数组优先，空数组不授权音乐库。网页创建账号预选默认库，可逐项调整。

普通用户默认浏览全部已授权音乐，有多个可访问库时可选择浏览范围；授权和目录配置只放网页管理。

网页在「管理 → 用户」逐个账号设置库权限，角色、库权限、停用与重置密码按列排列；所有者始终可访问全部库，无需单独授权。音乐库名称、默认新人授权、来源和托管目录配置集中在「管理 → 设置」。两者共用既有库授权记录，保存时校验版本，冲突后重新读取再确认，不改变既有用户的权限或个人数据。
管理页的「当前音乐库」只用于概览、歌曲信息、任务和导入整理，位于标签内容内；用户、全服设置和诊断不受此选择影响。

`GET /api/v1/libraries/folders?path=绝对路径` 仅所有者可用，只返回服务器子目录、当前路径和上级路径，不读取文件内容。省略路径返回配置的来源和存储位置；隐藏目录、符号链接不列出，拒绝穿越、链接和非目录路径。响应增加 `can_create` 和 `creation_blocked_reason`，说明当前目录是否允许新建。选择目录不创建、不移动文件；Docker 只可见容器内挂载路径。

`POST /api/v1/libraries/folders` 仅所有者可用，要求客户端标头，体为 `{parent_path:绝对目录,name:单层文件夹名称}`。只在已存在的可写父目录创建一个空文件夹，成功返回 201 及新目录的浏览结果；不创建多层路径，不覆盖同名目录或文件（409）。名称不允许隐藏目录、路径分隔符、控制字符或 `.` / `..`（422）。已配置的所有只读导入来源及其子目录拒绝新建（403），穿越和符号链接父目录拒绝操作。网页创建后进入新目录，可继续选择；保存音乐库及迁移仍校验可写性和重叠关系。

浏览使用查询参数 `library_id` 或 `X-Wildstring-Library` 选择库，`all` 表示全部可访问库。
单个对象的读取和写入按真实所属库再次授权，不能凭传入另一个库绕过。
角色能力与库授权同时成立，才允许导入、编辑、播放、封面和下载。未授权对象返回 404。
后台工作保留提交用户和目标库，执行时重新检查；AI/MCP 使用同一范围。

歌单归当前账号，普通歌单可以引用多个获授权库的曲目。详情、统计、封面与播放仅包含
当前有权限的可用曲目；撤权不删除私人引用，重新授权后恢复。排序保留隐藏引用与槽位。
收藏继续使用原有个人记录，提供跨可访问库的统一入口。

## 播客

普通用户客户端只展示个人关注，不提供本服节目切换；管理员也默认进入个人关注，可显式切换查看全服节目。出品方聚合跟随当前浏览范围。普通用户列表请求携带 `followed=true`；共享节目和缓存继续复用，不额外复制。

节目、单集、RSS 更新和服务端音频文件共享。节目响应增加 `followed`，默认 false。
`GET /api/v1/podcasts?followed=true` 仅返回当前账号关注；省略时普通用户只返回本人有关联的节目（含旧关注、保存或收听关联），所有者和曲库管理员可读取全服目录。未知或无关联的节目、单集和出品方返回 404。
`PUT /api/v1/podcasts/{id}/follow` 接收 `{followed:true|false}`，要求登录与客户端标头，
听众可用。重复请求幂等，不修改其他账号；取关保留进度，也不删除共享缓存。
`GET /api/v1/podcasts/catalog-settings` 返回全服 `allow_user_subscriptions`、`version` 与当前账号的 `can_add`；仅所有者可 `PUT`（客户端标头、版本校验）。开关迁移默认关闭，保持已有权限边界。
开启后，所有已登录账号可通过 `POST /api/v1/podcasts` 提交 `feed_url`，添加并仅关注自己；关闭时仅曲库管理员和所有者可添加。普通用户不能在此请求携带全服更新、下载或存储设置。新节目使用每小时更新、无批量自动下载的默认策略。相同 RSS 复用已有节目，不重置策略、进度或缓存，不触发一次额外刷新；并发添加也只存一份。
修改全服节目设置、刷新和删除仍需曲库管理权限；音频全服清理和订阅开关只由所有者管理。网页和 Android 都按服务端返回的 `can_add` 展示轻量添加入口，旧节目不自动替所有账号关注。

节目自动下载按当前用户与节目独立，未听范围只读取本人进度；播放缓存使用每用户网络偏好。手动与自动保存分开记录，一个用户对同一音频仍计一个引用。具体版本、保留、迁移与访问边界见 [存储与资源契约](storage-and-podcast-resources.md)。
听完不删除共享文件；只有零引用、未保护且未使用的音频才参与管理员清理。
旧音频与新音频适用同一套引用、保留期限和手动保护规则；具体 API、保留期和租约见[存储与共享资源契约](storage-and-podcast-resources.md)。
