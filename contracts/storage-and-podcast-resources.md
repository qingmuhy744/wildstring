# 库存储、迁移与播客共享资源

本轮契约，当前 schema 42；验证状态单独记录在 0.8.0 发布说明。重管理只在网页开放，Android 保留消费、库选择和有权限的轻量资料修改。

## 库配置

原有 `source_roots` 保持兼容；新增 `paused_source_roots`（省略则保留原状态）和新建库可选的 `managed_root`。源为现存的只读绝对目录；托管目录可写且独立，禁止库间、与来源及运行数据目录交叉。更新已存在库的托管路径返回 409 `library_migration_required`。

所有者通过 `POST /api/v1/libraries/{id}/migrations` 提交 `{version,managed_root}`，GET 同一路径查看进度。任务持久化，复制全部文件、校验内容和源文件稳定性后，原子切换库根目录与导入清单；保留库、曲目、歌单和进度 ID，并保留旧文件。失败保留原库与已复制文件，支持 `POST /migrations/{job_id}/retry`。目标目录须为空或属于该任务，不能覆盖已有不同内容。迁移与导入/扫描共用锁，重启恢复未完成任务。

网页集中配置每库自动导入开关、检查间隔和文件稳定等待时间；每个来源可单独暂停自动监听，手动导入仍可使用。审批和重试保留实际来源；当前导入忙碌时，显式审批的后续任务持久排队，按顺序执行。

## 播客保存和复用

`POST /api/v1/podcasts/episodes/{id}/download` 改为登录用户保存共享音频；重复保存幂等。现存有效文件返回 `{id,status:"reused",saved:true,reused:true}`；否则建立个人引用并复用/创建单一下载任务。普通听众也可保存。`DELETE` 同路径只释放本人引用，不直接删文件。单集响应以 `resource_saved` 标记本人手动保存，`resource_automatic` 标记本人自动保存。关注、进度和手动保存彼此独立，听完/取关不释放手动引用。

引用数从唯一的 `(user_id,episode_id)` 关系计算。旧音频和新音频适用同一套引用、保留天数、使用状态及手动保护规则，不自动为任何用户建立手动保存引用，自动引用由各自的节目策略生成。

网页管理员的 `POST /api/v1/podcasts/{id}/download-all` 同样为当前操作者建立全部单集的手动引用，已有音频直接复用，缺少的音频进入共享队列；不替其他用户建立保存记录，重复提交不重复保留或下载。

schema 39 移除此前自动添加且未被手动修改过的历史保护（`protected=1 AND version=1`），保留明确设置的保护、已有引用、音频文件和自动清理配置。迁移本身不删除文件。后续发现已有音频也默认不添加保护，自动清理由管理员现有开关及保留天数决定。

## 共享音频管理

仅所有者通过 `/api/v1/podcasts/resources` 分页查看资源、引用数、磁盘占用和保护状态；`GET/PUT /resources/settings` 采用版本校验，配置是否自动清理和零引用保留天数。`PUT /resources/{id}/protection` 显式设置或取消手动保护。

播放缓存偏好目前按 `user_id` 独立（当前单集、下一集和网络条件），应用于该用户的所有节目；音频文件及下载任务仍共享。节目自动下载按 `(user_id,podcast_id)` 独立，节目 RSS 更新频率和传输参数仍由管理员配置。手动保存、自动保存和临时播放缓存分别记录，底层音频及下载任务共享。

schema 41 增加按账号记录的 `podcast_playback_cache`。通过 `stream?cache=1` 且符合本人的缓存和网络设置时，记录当前单集与启用预取的下一集；直接复用服务器已有音频也记录归属。单集响应新增 `resource_playback_cached`，网页与 Android 的「我的下载」合并本人手动保存、自动下载和播放缓存；「服务器已有」显示共享音频状态。播放缓存不建立长期保留引用，正常零引用清理仍可回收，回收成功后同步移除缓存归属记录。旧音频不推测原下载人，已有手动、自动引用、进度和文件保持原状。

`POST /resources/cleanup` 接收 `{dry_run:true|false,podcast_id?:id}`，默认只预览；自动清理遵守保留期限，显式手动清理允许立即清零引用文件。清理在事务内重新核对引用、保护、下载状态和播放/传输租约；共享同一路径的其他资源也受保护。新增保存与清理串行化，不能把他人新建立的引用对应文件删掉。文件实际删除失败不清空登记。进行中的下载与播放不回收。

安卓个人保存使用同一接口，复用时提示“已复用服务器已有音频，无需重复下载”。手机离线副本仍需独立传输。网页保留全量下载、共享节目删除、资源清理和存储策略；安卓移除上述重管理入口。

本地接口回归另保留 [Postman 集合](checks/storage-resources.postman_collection.json)，仅允许访问本机隔离服务，并在执行写入前校验 `Storage Resource Fixture` 标记；需要预置 `storage-resource-shared` 与明确手动保护（版本大于 1）的 `storage-resource-legacy` 测试音频。该夹具 ID 保留兼容，不代表自动添加历史保护。检查同时验证两个用户的播放缓存偏好互不覆盖。使用临时测试凭据、`--no-report-events` 执行，不绑定或发布云端工作区。

## 用户自动下载与个人访问（schema 40）

`GET/PUT /api/v1/podcasts/{id}/download-settings` 读写当前账号的节目策略：`{version,download_policy,retention_policy}`。支持关闭、最新 3/5/10 集、本人未听完、全部；保留规则支持保留策略范围内音频、听完释放自动引用。自动下载需要本人关注且账号启用。节目 RSS 更新频率、下载传输与重试参数、共享文件清理由管理员管理。

最新 N 集先按发布时间（兼容 ISO 和 RFC RSS 日期，缺失时使用入库时间）确定固定窗口，再判断文件是否缺失；已缓存或听完的单集不会令窗口向旧集扩张。关闭策略、取关或窗口变化只释放自动引用。引用按用户、单集计数，分别记录手动和自动来源；两者并存仍计一个用户引用。手动取消保存只释放手动来源，文件只有在全部引用释放后才进入普通清理。

旧手动引用迁为手动来源。旧全服策略迁移给已有关注者，新增关注默认关闭；不替任何用户新增关注，不删除音频、旧进度、旧全服配置或歌单。

个人节目关联由添加 RSS、关注、保存和收听记录保留。迁移从已有个人记录恢复关联。普通用户只能列出和访问与本人关联的节目、单集、出品方、保存及进度接口；未知或属于其他账号的节目返回 404。新增 RSS 开关控制新的节目加入，不能通过直接提交别人节目 ID 来建立关联。管理员可查看全服，并仍只能修改自己的个人下载策略。取消保存幂等且只删除自己的手动引用。

网页个人偏好按同源下的账号保存；安卓按服务器与账号保存。旧设备偏好只迁给迁移时的账号，其他账号从默认值开始。账号切换不继承其他人的网络许可、音质、主题、播放样式、列表或歌词偏好；设备启动图标与服务器连接信息保留本设备范围。此处不承诺不同设备同步界面偏好。网页的非认证 API 请求附带当前账号绑定 `X-Wildstring-Account`；与会话账号不符返回 401 `account_session_changed`，避免跨标签页换账号后旧页面写入新账号。旧客户端省略此标头时仍按真实会话授权，标头本身不能授予任何权限。


个人自动下载及访问隔离另见 [Postman 检查](checks/podcast-personal-settings.postman_collection.json)；使用同一隔离存储夹具和 [本地 RSS 模拟](checks/rss.context.md)，覆盖两用户独立策略、重复刷新固定窗口、手动/自动引用、重复队列与未知节目拒绝访问。模拟音频为传输测试字节，实际编码播放由已有音频回归覆盖。
