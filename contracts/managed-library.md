# 托管曲库导入与整理

`WILDSTRING_MUSIC_DIR` 是只读导入源（本机可用 `data/`，Docker 挂载 `/music:ro`）。`WILDSTRING_LIBRARY_DIR` 是托管副本目录，默认 `<WILDSTRING_DATA_DIR>/library`；Docker 默认 `/data/library`，位于持久卷。两者必须分离，不能相互包含。

```sh
make import-music   # 复制、整理并扫描；使用本地 runtime
make docker-import  # 同样流程，写入容器持久卷
make scan           # 仅重扫托管副本，不从源覆盖
make docker-scan
```

导入规则：

```text
托管曲库/
  专辑艺人（缺失时用歌曲艺人，否则未知艺人）/
    专辑（缺失时为未命名专辑）/
      CD01/                     # 无碟号时用 01，仅用于路径，不写入标签
        01 - 歌名.flac
        01 - 歌名.lrc
        cover.png
```

普通音频支持 MP3、FLAC、M4A；WAV 与整轨 CUE 的预检、转换见 [自动导入](automatic-import.md)。无曲号时使用“未编号 - 歌名”，无标题时使用原文件名。保留中文，文件名使用 NFKC 归一化、替换跨平台非法字符、处理 Windows 保留名和尾部空格/点，并限制 UTF-8 字节长度。源文件名与标签不改变。

同名不同内容先进入待整理，用户确认后可增加 SHA-256 指纹后缀；字节完全相同的来源复用已有副本。重复导入依靠持久的源→目标映射跳过已有音频；托管副本被手工修正后不会被源覆盖或重新改名。若同一源路径的大小/修改时间变化，再核对源哈希：内容不同则报告冲突并保留副本。导入器不删除任何源文件或已托管文件；缺失副本报告错误，不擅自恢复用户可能主动删除的文件。

同名 LRC/LRYC/TXT 随音频重命名；同名封面随音频改名，共享的 cover/folder/front 图片归为 `cover.<扩展名>`。仅复制当前支持的音频和匹配侧车，不复制日志、NFO、任意附加文件。内嵌封面、歌词和所有标签随音频逐字节复制。已有托管侧车不同则报告冲突，不覆盖。

导入按块读写；在目标目录写临时文件、fsync、检查源版本与哈希，再通过排他硬链接发布完整文件。托管文件和源文件是独立数据，**不是彼此硬链接**。排他链接仅用于同一目标文件系统内从临时文件发布，要求目标文件系统支持硬链接（本地 Docker 持久卷已验证）。不支持时报告失败，不回退为可能覆盖目标的操作。POSIX 下拒绝源/目标符号链接；中断清理当前临时文件，已成功导入项保留，下次可继续。突然断电/SIGKILL 遗留的临时文件不会被识别为音频。

SQLite v4 保存导入运行、计数、最多 100 条错误，以及源根目录、相对路径、目标路径、大小、纳秒时间与 SHA-256。导入与扫描共用跨进程锁，复制结束后扫描托管库；之前直接扫描源目录的记录，在可迁移时保留曲目 ID。GET `/api/v1/imports?limit=20` 要求 `library:inspect`，不暴露宿主机根目录。普通管理账号只读取通过 `admin_jobs.import_id` 明确关联到当前授权音乐库的记录；所有者可读取全部历史，包括无法可靠归属的旧记录。日常任务仍通过按库过滤的 `/api/v1/manage/jobs` 管理。

源离线不影响已导入副本播放。导入源被修改不会自动替换托管数据。Make、管理页与自动发现共用导入逻辑；已支持单曲数据库覆盖编辑与待整理补充，尚无可配置的命名模板或已有文件标签写回/目录重整。详见 [管理接口](library-management.md) 与 [自动导入](automatic-import.md)。
