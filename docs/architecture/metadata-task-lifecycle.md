# 元数据任务与建议的生命周期

查询的执行结果和管理员是否处理建议分别记录。Web 管理任务区显示进行中、待确认、需处理，历史记录默认折叠；同一分类内按歌曲合并多次查询并分页读取，完成后自动退出进行中。

- 进行中：排队、查询中。
- 待确认：存在与当前歌曲信息版本一致且尚未应用、忽略的建议。查询结束不会清除建议。
- 需处理：查询失败、歌曲已变化或来源警告尚未处理，且没有可应用的待确认建议。有建议且来源报错时显示“部分完成”，保留错误说明。
- 历史：已处理、无新增资料或候选已随歌曲信息版本变化失效的终态任务。查询结果本身保持不变，批次统计仍可信。

应用建议后按照剩余有效建议自动分类。忽略建议会标记该页快照中的同曲建议为 ignored，并确认这些查询的问题；忽略问题只确认错误。操作只处理页面读取时已结束的结果，之后完成的新查询继续保留。重新查询先入队成功，再确认原错误；近期成功来源允许命中缓存，旧建议继续保留。重新查询依然按当前启用的资料来源执行。

历史默认展示查询结束后 30 天，服务端每小时清理过期的已归档列表记录，关闭联网功能时也执行。待确认、未处理失败、正在执行的记录不自动清理。手动清理同样仅隐藏页面快照内的历史记录，不删除任务、建议、已应用元数据或刷新批次；任务及应用来源仍可在歌曲详情追溯。

新增管理员接口：

- `GET /api/v1/manage/providers/tasks?view=active|pending|attention|history&limit=20&offset=0`，返回分页、各分类歌曲数、排队及执行总数、快照时间。响应禁止缓存。
- `POST /api/v1/manage/providers/tasks/tracks/{id}/review`：`view` 为 pending 或 attention，`through` 为页面快照时间。
- `POST /api/v1/manage/providers/tasks/{job_id}/retry`：重新入队，成功前保留原问题。
- `POST /api/v1/manage/providers/tasks/history/clear`：`through` 为历史页面快照时间。

变更采用 SQLite schema 16，新增独立 review 表，旧任务、建议、刷新批次无需重写。旧 `/providers/jobs` 和批次接口保持兼容。需要升级服务端后才能使用新的 Web 任务区；不需要修改 Android 协议。发布和线上部署另行验收。
