# 多用户设置归属检查

检查日期：2026-10-26；当前开发代码为 schema 41。以下区分个人数据、共享媒体和实例管理，实际验证与发布状态分别记录。

## 本轮修复

| 问题 | 当前行为 | 主要实现 |
| --- | --- | --- |
| 自动下载策略被全服共用 | 按用户与节目分别保存策略、保留规则和版本。本人关注且账号启用时执行，管理员也只更改自己的个人策略。网页和 Android 增加「自动下载」。 | `podcast_download_settings.py`、`podcast_user_schema.py`；两端个人设置对话框。 |
| 最新 N 集逐轮向旧集扩张 | 先解析 RSS/ISO 发布时间并确定固定窗口，再判断缓存、本人已听状态；重复检查不扩大窗口。缺失或空的缓存文件只在窗口内重试。 | `ordered_episodes()`、个人策略协调器、管理员一次性预取。 |
| 自动下载与手动保存混淆 | 同一用户/单集分别记录手动与自动来源，两者并存仍只计一个用户引用。关闭、取关、移出窗口和按策略听完只释放自动来源；手动保存和其他用户引用保留。 | `podcast_resource_refs.manual/automatic`、保存/释放/进度接口。 |
| 播放触发的缓存不进入个人下载 | 当前及预取单集按触发账号记录，复用已有音频也会关联本人；网页与 Android「我的下载」同时包含三种来源。播放缓存不增加长期引用，零引用回收成功时移除归属。管理员批量下载按操作者建立手动保存。 | schema 41 `podcast_playback_cache`、播放/资源接口、两端单集范围。 |
| 客户端只过滤个人关注，API 仍全服可读 | 普通账号的节目、单集、播放、出品方、进度与保存均检查个人节目关联。添加 RSS 才能建立新关联，不能用已知他人节目 ID 绕过开关。管理员保留全服目录管理。 | `podcast_access.py`、节目/出品方路由。 |
| 网页偏好切换账号后沿用 | 主题、播放样式、歌曲列表大小、歌词字号、浏览入口、离线音质、网络许可和容量按同源账号保存。单例状态和跨标签页事件使用当前账号范围。 | `user-preferences.ts` 与各偏好入口。 |
| Android 偏好仍属于设备全局 | 外观、音质、列表和歌词偏好、排序、触感、缓存预算、离线音质/网络/容量及音乐接续模式按稳定的服务器与账号身份保存。 | `AppSettings`、`AccountPreferences`、`OfflineDownloads`、`PlaybackSharing`。 |
| 旧页面/待发送记录可能沿用已切换的会话 | 网页 API、离线请求、收听统计和播客进度携带账号绑定；不匹配返回 401，旧响应不进入新页面。安卓新接口使用现有请求归属检查。 | `Auth.require_session()`、Web 请求封装、Android `RequestOwner`。 |

底层音频及下载队列按单集共享，两个用户的相同需求不会复制文件或重复创建下载任务。播放缓存偏好仍按每个用户一套，适用于全部节目；节目自动下载另按用户与节目配置。RSS 更新频率、传输重试和共享清理继续属于服务器管理。

## 旧数据与迁移

- schema 41 只新增播放缓存账号关系，不按现有共享文件或进度猜测原下载人；不改动原手动/自动引用和音频文件。
- schema 40 为旧手动引用补上手动来源；旧全服自动下载策略只迁给已有关注者，后续新关注默认关闭，不自动替用户添加关注。
- 从已有关注、保存与收听记录恢复个人节目关联；取消关注后保留历史关联与进度，允许重新关注。管理员添加、保存或收听的节目也可保留个人关联。
- 旧设备偏好只迁给第一个迁移账号，不复制给后续账号。偏好保存在本机，不承诺跨设备同步；Android 启动图标、连接信息、设备标识和应用更新仍属于设备。
- schema 39 的标准音频清理规则继续保留：撤除未被人工修改的自动历史保护，保留手动保护、原文件、用户引用、原清理开关及保留天数。迁移本身不删除文件。
- 已只读对照迁移前本地备份：旧账号、库、曲目、歌单、节目、单集、关注、进度、库授权和音频登记未丢失，原登记音频文件仍在，清理配置相同，数据库完整性检查正常。

## 其余设置的归属

| 设置 | 归属及核对依据 |
| --- | --- |
| 个人关注、收听进度、手动/自动保存 | 用户；用户字段由真实会话提供，不能在请求体指定他人身份。 |
| 播放缓存、响度与增益 | 用户；`podcast_playback_settings`、`playback_gain_settings`、`playback_gain_adjustments`。 |
| 推荐偏好、每日推荐和反馈 | 用户与音乐库；查询和更新同时校验 `user_id`、`library_id`。 |
| 通知、助手偏好、Telegram 目标和 Last.fm 同步 | 用户；保留现有用户归属与目标授权。 |
| 私人 AI 连接 | 用户；只读取本人连接及管理员显式共享的连接，返回内容不含密钥。共享连接的全局额度仍是公共连接预算，个人用量另统计。 |
| 来源、监听、托管目录与库名 | 音乐库；由网页管理入口配置，角色和库授权共同校验。 |
| RSS 添加开关、资源清理、转码与缓存总限制、插件和服务网络 | 实例管理；控制公共资源，不允许普通用户修改他人的消费设置或全服运维配置。 |
