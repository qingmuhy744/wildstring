# Agent、MCP 与通知运行说明

0.4.0 使用现有 Python／FastAPI、React、Android、SQLite。业务工具和批准逻辑位于服务端；内置助手使用有界 Chat Completions 工具循环，MCP 使用官方 Python SDK 2.3.0 的 stdio 传输。首版没有引入额外 Agent 框架，后续可在不改变业务权限、草案和持久任务的前提下评估 Pydantic AI。

接口与字段见 [Agent 平台契约](../../contracts/agent-platform.md)，产品计划见 [完整开发计划](../product/agent-mcp-observability-notifications-plan.md)。文档中的计划验收与本版实际记录分别查看；正式版本、自动化和真实设备验证见 [0.4.0 发布说明](../releases/v0.4.0.md)。

## 使用入口

Web 侧边栏进入助手、草案与巡检、通知；连接、工具凭据、Telegram 和诊断位于对应设置。Android「我的」提供相同日常入口，设置中管理模型与通知。通知在登录、回前台、恢复联网和手动刷新时补拉，持续前台每五分钟补拉；退出期间的结果留在服务端。读取列表不标已读，「全部已读」只作用于已经取得的快照。

内置助手默认可以本地找歌。选择已配置的连接后才调用模型，不自动选择其他付费连接。实例连接由管理员明确共享，个人连接只供本人使用；个人端点受管理员精确主机策略约束，局域网端点需管理员允许。已有 AI 配置以只读的「实例 AI（已有配置）」延续现有用法。连接测试分别检验文本、合成结构化结果和工具调用，会消耗最多三次模型调用。

巡检可手动触发或按关闭状态创建计划，先检查本地缺项；只有选中 AI 并授权后台使用连接时才进行模型分析。预算、连接版本或权限变化会暂停，用户检查后恢复。来源匹配继续调用既有 MusicBrainz／Last.fm／AcoustID／CAA 流程，查询成功与获得匹配分别反馈。没有可信候选的字段不自动补成事实。

草案展示真实对象、版本、修改前后和证据。用户在 Web／Android 批准具体版本，随后应用；编辑草案使旧批准失效。歌单修改属于本人，共享元数据需要管理员。重复应用使用同一幂等键，不重复改动。巡检、MCP 和模型都不直接写标签或移动音乐。

## MCP 与 Codex

先在站内创建专用工具凭据，只勾选所需 scope。令牌只显示一次，可撤销或设置有效期；它不能批准草案、读取密钥或任意修改部署配置。普通查询不要求配置内置模型。

在启动 MCP 客户端的环境中提供 `WILDSTRING_MCP_URL` 和 `WILDSTRING_MCP_TOKEN`，不要把令牌放在启动参数、聊天记录或仓库中。URL 默认需要 HTTPS；本机回环 HTTP 可用于开发，其他 HTTP 必须显式设置 `WILDSTRING_MCP_ALLOW_HTTP=true`。MCP 桥接不会访问数据库或音乐目录。

本地验证：

```sh
make setup
make mcp             # 启动后等待客户端的 stdio 协议，不是交互命令行
make test-agent      # 合成曲库、权限、草案、任务、通知与真实 MCP stdio 测试
make test-network    # 正式请求／探测共用代理的真实 HTTP 夹具
```

Codex 配置见 [不含秘密的示例](../../deploy/mcp.codex.toml.example)。替换绝对项目路径，将配置表合入个人 Codex 配置，让 URL／令牌通过 `env_vars` 传入，再在客户端重新载入 MCP。此配置依据 [OpenAI 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp)；本地启动进程与远端工具 API 是两层，不能把野弦首页 URL 当作直接的 HTTP MCP 端点。

可使用的流程包括检索歌曲、检查缺项、读取与提交来源查询、生成有证据的歌单／元数据草案、应用已批准草案、检查任务及通知、按诊断编号查询日志。管理员诊断工具只接受固定参数和固定服务目标，不提供 Shell、SQL、任意 URL 或文件路径入口。

## 网络与日志

AI 测试、真实选歌、助手、资料来源和 Telegram 复用 `outbound.py`，遵守直连／HTTP 代理／环境变量及 `NO_PROXY`。API 与凭据状态、封面下载和解码分别检验；预期 404 不能代表整个封面功能正常。当前 AI 的最小文本测试不代表结构化选歌或工具能力已验证。

响应头 `X-Wildstring-Trace-Id` 是诊断编号。请求、工具和后台任务通过上下文关联；后台 worker 的安全事件保存在独立诊断存储，不占用曲库业务事务。日志只允许固定字段，保留错误码、异常类型和代码位置，舍弃异常原文、请求正文、歌词、音频、绝对路径、完整 URL、模型对话及秘密。

诊断默认保留七天、总上限约 200 MiB，使用有界队列及容量轮转；临时 DEBUG 最长十五分钟，并按模块限制。日志不可写时诊断状态显示降级，不把成功的业务操作改为失败，也不阻断播放。管理员可分页查询、查看操作事件和下载最多一百条事件的脱敏 JSON 包；业务审计、待确认草案和失败任务另行保留。

## Telegram

Telegram 默认关闭。用户输入 Bot Token、目标和可选 Topic，点击发送验证信息，再回填目标收到的短效验证码后才能启用。配置和验证均由用户主动触发，不能仅凭 Chat ID 让私人结果发送给陌生目标。群组目标需管理员。

结果按事件、严重程度和静默时段订阅，采用固定文本摘要，不向模型发送结果以润色通知。业务结果、站内已读、Telegram 投递分别记录；外部发送失败不改变任务结果。429 按 `retry_after` 等待，临时故障有界重试；超时但可能已发送的结果进入 `unknown`，需要明确确认后才重试，不能保证外部恰好一次投递。

## 升级与运维

数据库从已发布版本的 schema 15 经任务归档 schema 16 升级到 Agent schema 17。升级前停止旧服务，备份 SQLite、已有私有配置和新的 `agent-secrets/`，并在副本演练；保持原音及导入目录挂载。回退旧镜像需要恢复与之配套的数据库备份，不能让旧版本直接写新库。

默认关闭新计划、后台 AI 与 Telegram；播放、浏览和本地找歌不依赖模型。MCP token 在服务端只存摘要；模型和 Bot 秘密独立保存在权限受限的服务端目录，不进入数据库响应、诊断包、镜像或公开附件。

物理 ColorOS、用户自选模型、私人 Telegram 目标和自托管网络的联调结果应单独记录；合成测试与模拟器通过不代表这些真实条件已验证。
