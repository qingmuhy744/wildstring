# 按账号推荐与发现新音乐

0.4.0 将推荐与助手接入同一套模型连接和额度。接口及最终验收以对应契约、[发布说明](../releases/v0.4.0.md)为准；本地推荐、外部资料和 AI 分别记录状态。

## 三种入口

| 入口 | 数据与用途 | 播放行为 |
| --- | --- | --- |
| 每日推荐 | 个人收藏、收听与反馈，结合本服热度、未听和久未重听的本地歌曲 | 只返回真实、可访问的曲目 |
| 收听排行 | 自己／本服用户汇总；近 7／30／90 天或累计，按次数或收听时长 | 从曲库播放，不公开其他账号的明细 |
| 发现新音乐 | 外部候选结合个人偏好，提供曲库之外的收藏建议 | 未入库时提供资料、复制查询文字和来源；匹配入库歌曲后才提供播放 |

“新音乐”表示对当前曲库的新发现，不保证刚发行。它是手动找音乐、下载和收藏的参考清单；用户把文件放入已有导入目录后，沿用正常导入流程。推荐功能不抓取下载资源、不创建下载任务、不修改或移动音乐文件。

## 账号与模型

每日推荐批次、偏好、反馈、库外清单、想听和忽略记录按账号与曲库隔离。多人使用同一共享 API，也分别获得推荐。用户可选择本地模式、自己的连接或管理员明确共享的连接；默认本地，不自动改用另一条付费连接。

助手、发现、每日推荐和库外 AI 筛选共用连接权限与额度：每个连接的每日调用上限全局计数，同时按用户记录本人调用与 token 用量。共享调用总量不等于展示他人的会话或收听记录。个人 API 仍保存在自托管服务端，其他普通用户不能读取密钥。

升级时保留已有实例 AI；旧版已开启 AI 的推荐偏好继续指向 `legacy`，新用户默认 `local`。管理员可从统一连接入口管理新连接及旧配置兼容入口。旧客户端的布尔开关继续受兼容逻辑约束，不绕过统一额度。

## 推荐来源

| 来源 | 依据 | 使用边界 |
| --- | --- | --- |
| 个人偏好 | 本人收藏、收听次数与时长、接受／完成／跳过／少推荐反馈 | 个人反馈影响自己的结果 |
| 本服热门 | 本实例曲库用户的实际收听汇总 | 只展示聚合数字；近期窗口与累计明确区分 |
| 本地探索与重听 | 尚未听过、久未重听的可用歌曲 | 保留探索空间，避免只有固定热门歌曲 |
| Last.fm 公共热门 | `chart.getTopTracks` | 外部公开热门，不称为本服或本人的播放排行 |
| Last.fm 标签榜 | `tag.getTopTracks` | 官方定义按标签统计排序，不当作近期播放量；标签可自行设置 |
| Last.fm 作品与相似关系 | `artist.getSimilar`／`artist.getTopTracks`、`track.getSimilar` | 从少量真实偏好种子扩展，不把统计关联说成音频分析结论 |

外部来源需要实例已配置并启用 Last.fm；每个用户再选择自己的推荐来源。国内其他平台暂未接入未确认的接口。

候选合并先保留不同来源，再限制候选规模，避免一个公共榜单占满结果。AI 只从真实候选 ID 中选择；标题、艺人、专辑和链接取自来源资料。仅向模型提供有界候选及少量偏好，不上传原音频、歌词、文件路径或整份收听明细。缺少专辑资料时保留缺失值。

## 更新、缓存与反馈

库内每日推荐当天稳定，可手动换批。库外建议默认关闭；开启后默认每七天一批，可选择其他间隔或仅手动。到期检查发生在访问清单时，不与切歌或每首歌的元数据刷新绑定；应用完全退出时不承诺定时生成。

库外 AI 筛选另行选择，来源规则仍可独立运行。公开来源使用有界缓存、查询次数和超时；模型与来源错误分别反馈。网络失败时保留已有清单并显示陈旧／降级状态，不把空结果或失败说成匹配成功。

“想听”保存当时的候选资料并按账号保留，换批仍可查看；“忽略”在后续筛选前生效。歌曲导入后重新匹配当前可用曲目；同名多版本不直接猜一个作为已入库，仍允许人工核对。

## 升级与验证

本批推荐设置与库外缓存使用 schema 18。升级前备份数据库及私有配置，在副本演练并核对旧表旧字段；回退旧镜像需恢复对应数据库。

验证覆盖多账号隔离、个人／共享连接越权、全局额度与个人统计、真实近期排行、来源混合、缓存与更新频率、想听跨批、忽略前置、模型伪造候选及来源失败。真实供应商覆盖率与模型推荐质量另行评估，不由合成测试通过推定。
