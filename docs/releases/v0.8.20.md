# WildString / 野弦 0.8.20

本版统一 Web、Android、macOS、iOS 的播客暂停恢复与进度写入行为，修复回退后无法继续、本机重播误报跨设备冲突、Android 大节目点播卡顿和 Web 待播竞态，并稳定播放器与单集列表的状态反馈。数据库 schema 保持 54，不迁移音乐、进度、收藏或待播数据。

## 已实现

- 主动恢复最多等待一次整体进度读取，接续服务器最近接受的异会话书签，向后更新的位置也有效；没有异会话更新时保留本机暂停点。普通恢复不重复应用询问／从头播放偏好。超时、断网和 5xx 使用本机位置，认证、权限与内容失效错误保持暂停。
- 暂停、回退与定位直接控制本机引擎，上传在后台执行。临时音频中断自动恢复沿用本机位置和会话，中断中主动暂停则不再自动恢复；重复 PLAY 不重复准备。迟到或已取消的请求不能让播放器再次出声或跳转。
- 四端只根据本进程具体旧请求的成功确认衔接尚未发送的新会话，覆盖重新点播与从头播放。Apple 的普通检查点、显式接管及历史补传共用单集写入链；音频不等待它。真正的 409 仍停传，不按设备 ID 猜测接管，不循环改版本争抢。
- 已失去写入权或片尾结束未获确认时停在当前集，不修改共享待播，也不自动开下一集；手动下一集仍可操作。Web 获得浏览器播放许可后才上传，拒绝播放时可用原播放键继续；Apple 冷恢复保留实际单集与未上传位置。
- Web 已打开的待播弹窗随保存结果刷新，旧读取不覆盖新顺序；接续／冲突提示按底栏实际高度避让。服务器会话断言等待上传确认，不再把音频定位完成当作上传已结束。
- Android 整批准备播放条目时只查询一次网络状态，媒体条目与缓存写入移出主线程；提前定位由音频引擎保留，避免界面到了书签而音频仍从零出声。
- 四端待播操作区宽度稳定，播放、暂停、缓冲共享固定图标槽并平滑过渡；减少动态效果直接落位。Android 和 iOS 封面按实际剩余空间排布，iOS 迷你播放器缓冲不挤动旁边按钮，保留完整触控目标。既有返回、文章与平台手势继续可用。
- iOS 播客文章不再走音乐歌词接口；与 Mac 共用段落、链接和时间码解析，保留加载、空内容、错误和无权限状态。文章中的有效时间码可直接定位本机音频。
- Android「野弦 Dev」使用独立固定签名，后续 Dev 包可保留数据覆盖安装；旧临时签名 Dev 首次迁移仍需卸载一次。正式版签名独立且保持连续。

完整场景与平台差异维护在[单集进度契约](../../contracts/podcast-progress.md)，视觉与动画规则见 [DESIGN.md](../../DESIGN.md)。没有增加服务器租约、设备锁、远程停播或账号级跨集互斥。

## 版本与升级

- 后端、Web、Android、macOS、iOS：`0.8.20`。
- Android versionCode：`56`；Apple 构建号：`55`。
- 数据库 schema：`54`，与 0.8.18／0.8.19 相同；本次客户端可连接这两版服务器测试。
- 延续先升级服务器、再升级客户端的顺序；0.8.12 及更早客户端仍不兼容 0.8.13 及更新服务器。
- Android 正式包沿用发布签名，可覆盖升级。macOS DMG 沿用现有分发方式；签名／公证状态以发布工作流为准。iOS 更新源码、构建配置和模拟器验证，本版不提供签名 IPA 或 TestFlight 附件。

## 验证与限制

- PR #165 统一实现与回归；发布前须完成后端、Web、Android、Apple 和容器检查，按 [AGENTS.md](../../AGENTS.md) L3 执行。最终 main 须先通过主线 CI 与手动 Android 全量设备门禁，再打标签；Release 工作流还会重新检查并安装正式 R8 APK。最终结果与产物见 [v0.8.20 Release](https://github.com/qingmuhy744/wildstring/releases/tag/v0.8.20) 及其对应 Actions。
- Android 修复阶段标准 Phone／Pad 的播放器专项 31 通过、1 项按宽度条件跳过；此前 69 张相关截图逐张查看。新的 Web 与 Apple 自身请求竞争用例在旧实现上实际失败，再验证两种确认顺序、显式接管和真正异设备获胜。
- Web、Mac、iOS 使用真实界面渲染检查浅深主题、窄宽窗口、长标题、待播与加载状态，并按帧采样图标和按钮边缘。Mac 首轮同步截图采样存在初始化间隔，视觉曲线从首个实际变化帧测量；不把该数据当作首次点击响应耗时证明。Apple 关闭动画的组件路径与系统设置接入分别核对，未把组件参数测试等同系统设置人工 UAT。
- Android 800 集合成节目准备路径，旧实现最长主线程间隔约 2327ms，修复后 Phone／Pad 为 58／74ms；包含实际界面与 MediaSession 的重播仍有约 275／286ms 短顿。这不是用户手机或忽左忽右 627 集的实测，也不承诺瞬间出声。进度读取预算不包含音源连接和缓冲耗时。
- 未完成真实蓝牙耳机、电话／导航、硬件重连发 PLAY、系统强制结束及真实跨设备网络 UAT；未穷举全部语言、最大字号和浏览器组合。Web 通用媒体事件、后台节流与自动播放策略存在平台限制，不能保证所有系统键都能提供与原生命令相同的原因信息。
- 没有自动部署用户服务器；发布、合并与实际部署分别记录。
