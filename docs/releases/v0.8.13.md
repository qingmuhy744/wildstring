# WildString / 野弦 0.8.13

本版是面向 0.8.12 的小版本，合入 PR #111（一份有序待播列表，播放入口决定顺着节目还是列表）与 PR #112（Android 播客播放器过渡、待播面板底部适配与关注规则菜单）。

## 不兼容说明（请先读）

**0.8.12 及更早的客户端无法正确对接 0.8.13 服务器。** 服务端已移除 `/podcasts/inbox`（调用按未注册路由处理），不再提供独立的「稍后听」接口。升级服务器后，必须同时将 Web、Android、iOS 与 macOS 客户端升级到 0.8.13；只升级其中一端会出现待播同步失败或功能缺失。先升级服务器再升级客户端，或在同一维护窗口内一并完成。

## 相对 0.8.12

### 一份待播列表（PR #111）
- 每个用户只保留一份有序待播列表。手动的「下一集播放」和自动的「加到最前」只决定这一份列表里的位置：不开始播放，也不把正在听的节目改去听别的。
- 数据库 schema 升至 52：升级时把原来的稍后听按加入时间接到该用户队列末尾，然后删除 `podcast_inbox` 表；偏好里的 `inbox` 改成 `queue_last`。`podcast_inbox_baseline` 不动，已有关注不会把历史集灌进队列。
- 新集默认 `queue_last`，按发布时间从旧到新追加到队尾；`queue_next` 从新到旧放在最前；`ignore` 只关注、不入队。去掉隐藏的每节目 3 条上限；全队列上限 5000，超出则整批不加入并标 `notice=queue_full`。`itunes:type=serial` 且该用户还没有节目偏好时，初始为不入队、从旧到新。
- 从节目、单集、搜索或收藏点播放，顺着该节目；从待播列表点播放，顺着列表。一条线走完就停，不掉进另一条。正在听的那一集如果也在待播里，听完或切到下一集会从待播移除。点播放不再把该集插到云端队首。
- 「下一集播放」：当前这集已在待播里就插在它后面；播放器是空的，或当前这集不在待播里，就放到最前。正在听的那一集本身不再插一次。「加入待播」追加到队尾；已经在列表里的再点一次，不改位置，也不改来源。
- Android 音乐队列、播放器待播和资料库待播共用一行：序号或正在播放、标题点按播放、最右拖动手柄。滑动删除并可撤销，正在播放的一行不能滑掉。冲突多一个「仅保留本机、暂不覆盖」，这一项不上传。

### Android 播放器、待播面板与关注菜单（PR #112）
- 队列卡片拖动时为阴影指定圆角，避免圆角外露出直角底色。
- 待播／播放队列面板移除外层多余的底部安全区留白，改由列表内部计算底部内边距，卡片延伸至手势条上方；音乐队列的卡片间距与播客队列对齐。
- 手机端播客播放器封面与文章改为 240ms 共享时序的淡入淡出与控制栏连续变形，文章模式使用紧凑阅读条，次要操作收进 `⋮` 菜单；平板／宽屏端封面控制与文章双栏并存。设置中可关闭界面过渡动画，并仍遵循系统动画开关。
- 节目详情页将原先单独一行的「新集待播」收进「已关注 ⌄」下拉菜单，按钮直接外显当前规则（如 `已关注 · 队尾`；默认「仅关注」不加后缀），并将原先 2×2 操作按钮收成单行。

## 已知限制
- 旧客户端不会把稍后听同步到新服务器；升级前请先在 0.8.12 上确认待播数据已同步，再升级服务器与全部客户端。
- `auto_limit` 字段仍保留在偏好接口中以免旧请求体被拒，但服务端分发新集时不再按它截断。
- Android 播客播放页「AI 导读」标签仍为即将推出占位。
