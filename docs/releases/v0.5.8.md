# 0.5.8：MCP 封面、专辑批量与结构巡检

从 main `55f159c` 的独立 worktree 开发，不包含主工作目录中的 iOS 工作。以下描述本批实现；发布产物、流水线和 home 更新分别核验。

## 封面选用

- 新增 `get_cover_candidates` 与 `get_cover_preview`，读取已有候选与匹配依据；预览经过原有服务端代理、可信域名与图片大小／解码限制，原生 HTTP 和新版 stdio MCP 返回图片内容。
- `create_draft(kind="cover")` 保存下载到的具体图片快照；Web／Android 显示该图片，加载失败时不能批准。站内批准后仍须显式应用，应用不会重新下载另一张图片。
- 元数据、候选内容或缓存快照变化时拒绝应用；客户端不能伪造图片快照字段。直接采用封面的旧 HTTP 接口也复用相同服务，不改写音频文件。

## 专辑批量修改

- `get_album_tracks` 按真实 album_id 分页返回当前字段和每首歌曲的 metadata_version。
- `create_draft(kind="metadata_batch")` 最多包含500首明确的歌曲、版本和字段差异；可指定至多20个 album_id，并要求完整覆盖这些专辑的可用曲目。
- Web／Android 展示逐曲差异，站内批准后整批应用。任一曲目版本或指定专辑的成员范围变化时拒绝整批；途中异常也完整回滚。
- 保留原有人工覆盖，逐曲记入审计；幂等重试不会重复修改。可以用于核对后的多碟专辑艺人统一，但不会自行猜测或合并发行版本。

## 巡检与证据

- `get_inspection_rules` 返回规则和解释；`inspect_library` 支持分页、专辑筛选及选择规则，持久巡检复用同一规则。
- 新增曲序缺失／重复／越界、碟号缺失／越界、同名不同版本、可能重复录音、多碟分组提示。相关性检查使用当前页之外的曲库元数据；结构上下文超过一万首时明确报告不完整。
- 缺歌词属于信息提示，纯音乐可能正常；同名、接近时长和分组提示均不代表已证明重复音频或发行事实，不自动删除、改名或应用。
- 网易云证据链接保留公开 id，酷狗保留公开 hash；其他查询参数与凭据不透传。

完整回归同时修复两处异步状态问题：迟到的助手历史设置回读不再覆盖正在输入的天数；暂停后迟到的 waiting 事件不再把歌曲标记留在缓冲状态。

## 兼容与权限

总工具数由48增加到52，按凭据范围裁剪。封面与批量草案需要管理员的 library:manage、drafts:write；应用另需 drafts:apply。MCP 仍不能批准草案，纯规则与读取已有候选不调用模型；封面预览和创建封面草案会获取公开图片。

两类新草案批准时需要确认当前预览摘要；旧客户端缺少该摘要会提示升级，不能在未展示图片或逐曲差异时盲目批准。旧草案和旧权限语义保留。

数据库仍为schema22，无新迁移；Web／服务端／Android 均为0.5.8，Android code22。数据目录中的图片快照继续随原有持久卷保存。升级或降级时仍应保留配置、数据库、图片与托管曲库；发布不等于已更新 home。
