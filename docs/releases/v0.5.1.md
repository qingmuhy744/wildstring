# 0.5.1

本次为巡检反馈和 GitHub 安全检查的小版本更新，数据库仍为 schema 20。

- 规则检查没有异常时明确说明检查范围并跳过 AI 分析，避免把整批正常歌曲发送给模型；这不代表已考证歌曲发行归属或全部音乐事实。
- 有异常时发送整个巡检的分类统计和最多 20 首异常样本，限制上下文长度，避免前 80 首正常歌曲掩盖后面的异常。最终调用要求总结已有证据，草案继续等待确认。
- 区分模型输出 Token 超限、内容过滤和服务中断，保留失败所在阶段、本地检查结果及调用计数；没有自动付费重试或截断工具执行。
- Web 和 Android 显示可理解的失败与恢复提示，历史失败记录的 `completed` 不再显示为成功阶段，Android 补齐分析说明显示。Android versionCode 升至 15。
- 启用 CodeQL 高级扫描，覆盖 Python、JS/TS、Android Kotlin、Actions，使用 `security-and-quality` 规则；增加依赖审查、Gradle 依赖图提交和 Dependabot 配置。主分支要求 CI、四项 CodeQL、依赖审查，并阻止新增高危扫描问题。扫描成功不代表已有告警全部解决，套餐限制见 [安全配置说明](../architecture/github-security.md)。

## 验证边界

使用合成模型响应验证结束原因、截断工具拒绝执行、预算计数、失败阶段与恢复。使用 home 当前失败任务的隔离快照验证 134 首本地检查结果保留、恢复时不追加模型调用；不重发私人曲库到外部模型。旧版本未保存提供商的具体结束原因，因此原始 `ai_output_incomplete` 无法追溯区分截断和过滤。

发布流水线分别检查后端、网页、Android、容器，产出签名 APK、Web ZIP、数据源插件 ZIP 和多架构镜像。发布完成、下载校验和 home 更新按实际执行结果另行核验。
