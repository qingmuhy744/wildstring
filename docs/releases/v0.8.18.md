# WildString / 野弦 0.8.18

本版是播客跨设备续听的完整版本，覆盖服务端进度协议与 Web、Android、macOS、iOS 四端接入；同时把曲库拼音排序键落到 schema 53，并为 Agent 与人工验收提供统一的截图入口。

本版保留既有数据：schema 由 52 升至 54，升级只新增表和字段，不改动已有进度、书签、待播与收藏。**0.8.12 及更早的客户端依然无法正确对接 0.8.13 及更新的服务器**（`/podcasts/inbox` 已在 0.8.13 移除），须使用 0.8.13 或更新的客户端。

## 相对 0.8.17

### 播客跨设备续听
- 单集进度写入新增可选 `intent`。本次收听在每一次写入（含离线补传）携带同一意图：继续收听使用 `resume`，保留服务器已有的已听完状态；明确从头播放与标记未听使用 `restart`。已听完不会再被另一台设备的旧缓存改回未听。
- 四端开播前先读取服务器进度：Web 与 Android 原本如此，macOS 与 iOS 改为先读再出声，最多等待约 1.5 秒，不再先按页面上旧位置播放再跳转；读取超时的迟到结果一律丢弃。
- 离线或读取失败时按本机位置播放并建立本地会话，先不上报；网络恢复后的第一次心跳直接提交，走正常冲突判断。
- 播放中遇到另一台设备更新：保留本机播放与位置、停止该会话上传，播放器提示「另一台设备更新了这一集的进度。本机进度暂不同步到服务器。」并提供「用本机进度」。暂停、拖动与切集不隐含接管；重新点播先读服务器。接管使用最近观察到的版本提交，再次冲突保留提示，不无限重试。
- 待发送记录撞到 409 时采用服务器状态并丢弃本机旧记录；同一设备的冲突只重试当前这一次写入。
- 已听完的统一规则：用户主动点开已听完的单集，从头播放并清除已听完；只有自动续播遇到已听完的集才按「跳过已听」改播下一集，此时只读取不写入。
- 单集暂停、停止或播完时，剩余时间不超过时长的 5%（最少 30 秒、最多 2 分钟）即标为已听完。短于该余量的单集仍要真正播完，播放中的进度上报和单独拖动不改变已听状态，已经停下的旧进度不回溯。

### 账号设置与界面
- 播客续听模式改为账号设置：`GET/PUT /api/v1/podcasts/resume-mode`，四端共享「自动续听／询问接续位置／从头播放」，本机只做离线缓存，登录、回到前台与进入设置时刷新。旧的本机设置不自动迁移，账号无记录时默认「自动续听」。
- 四端单集菜单增加「从头播放」；Android 恢复续听询问对话框，此前该选项没有实际效果。
- 节目详情、单集详情与收藏列表的单集对象新增 `last_listened_at`，macOS「继续收听」按最近收听选择单集，不再挑到已听完的一集；全部听完时显示「全部已听完」，不再隐藏操作。
- Android 节目页只对同步失败、需要升级服务器这类问题浮出一条紧凑提示，贴近迷你播放器上方，「已听完」等状态信息保留在播放器内；播放器的冲突提示不再挤压封面与标题。

### 曲库与工具
- 拼音排序键存到曲目与人物上（schema 53），歌曲、专辑、艺人列表与字母索引不再在查询中逐行计算拼音，排序结果不变。
- 新增 `scripts/agent_shot.sh` 与 `docs/screenshot-matrix.md`：截图按矩阵声明页面、状态、主题与宽度，产物写入清理过的 `artifacts/shots/<platform>/` 并生成覆盖与缺口清单，缺少必需状态时返回非零。窗口级人工验收改为文档化的手动步骤，不再作为默认流程。

## 升级说明
- **先升级服务器，再升级客户端**：旧服务器会拒绝携带 `intent` 的写入并返回 422。
- 续听偏好不再保存在各端本机。升级后账号没有记录时默认「自动续听」，此前选择「询问」或「从头播放」的用户需要重新设置一次。
