# WildString / 野弦 0.6.0

本版把曲库浏览、账号权限和管理流程拆得更清楚，并移除旧的账号角色兼容层。`profile` 现在是唯一的账号档案字段；Web、Android、iOS 与服务端需要一起升级。

## 主要变化

- 账号档案统一为所有者、曲库管理员、资料编辑员、听众四种；账号接口只使用 `profile`，不再返回或接受 `role`。
- 数据库升级到 schema 30：旧库先把管理员回填为所有者，再删除旧 `role` 列。
- MCP、Agent 与管理 API 统一按档案能力校验；Agent 凭据的权限不会超过账号当前档案。
- Web 歌曲列表和专辑卡片中的艺人名称可点击，按名称定位真实艺人后进入艺人页；歌曲播放按钮与艺人入口分开。
- Web 播放队列改为明确的上移／下移按钮，队列打开时点击面板外的空白区域即可收起；移动端继续使用适合触控的队列控件。
- 管理端提供只读导入源的来源和目录浏览、导入预览及按当前文件夹提交导入任务；目录条目会标出 `.part` 等未完成下载，预览不会把未完成文件列为可导入内容。
- 专辑安全删除先把托管副本移入带清单的回收区，保留曲目 ID 和元数据历史；曲库管理员可以恢复，只有所有者可以永久清理。导入源不参与移动或删除。
- 元数据候选中心区分“重新读取”和“重新查询”：歌曲信息或查询依据变化的旧候选会明确标为不可应用，待确认／需处理任务可直接进入核对结果；批量核对弹窗扩大桌面宽度。
- 元数据任务支持安全清空等待队列，只取消尚未开始的查询；正在查询、已有候选、历史和需处理记录均保留。取消记录进入历史，不伪装成来源失败。
- 专辑卡片补齐曲目数与时长，歌曲列表的艺人行保持大小档位、行高和点击区域一致。
- Pillow 升级到 13.0.0，修复 Dependabot 标记的图片解析和内存安全问题。
- 后端、Web、Android 与 iOS 版本统一为 0.6.0，Android versionCode 为 30。

## 升级说明

- 这是账号 API 的破坏性变更：旧客户端读取的 `role` 字段已移除。请先升级 Android / iOS 客户端，或与服务端同时升级。
- 旧数据库会自动迁移；迁移完成后 `users` 表不再保留 `role` 列。
- 移动端仍只对所有者显示现有管理入口；曲库管理员和资料编辑员的细粒度管理主要在 Web 端使用。
