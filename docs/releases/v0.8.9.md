# WildString / 野弦 0.8.9

本版在 0.8.8 的统一待播列表上，补齐按加入时间排序与手动调整顺序，并把待播单集与新集规则拆成两个标签页。播客下载新增「平缓下载」与快慢通道隔离，普通用户也能查看自己的下载队列。同时修复四端播客跳转进度不准或被覆盖的问题。

## 相对 0.8.8

### 待播列表排序与手动调整
- **加入时间排序**：队列与稍后听合并后按 `added_at` 升序排列；缺少时间戳的旧数据排在前面，相同或未计时的行保持原相对位置。
- **手动调整**：调整后整份写回有序队列，来源统一为 `manual`，并保留原 `added_at`，以便跨设备与重新加载后顺序一致。稍后听中的条目被拖入新位置后提升为手动待播，并从池中移除，保证一集只出现在一处。
- **桌面**：Web 与 macOS 每行提供上移／下移按钮。
- **移动**：Android 长按整行拖动、松手落位；iOS 把一行拖到另一行；Web 触屏通过左侧拖拽柄拖动。
- **兼容**：旧客户端整份 PUT 不会清空已有时间戳；服务端在入队时记录 `added_at`，整份重写保留原值，历史条目回退为队列的 `updated_at`。

### 待播面板标签页
- Web、Android、iOS、macOS 的待播面板改为「待播单集」与「新集规则」两个标签页，列表与自动入队设置分开查看。
- 单集标签页可一键播放全部待播；规则标签页按是否仍自动入队排列已关注节目。

### 平缓下载与通道隔离
- 节目可开启「平缓下载」：降低下载速度，并在单集之间稍作等待，减少被源站限流的机会。
- 服务端将普通下载与平缓下载分到两条通道：快速通道两个工作线程，平缓通道一个专用线程，互不抢占。手动保存或为播放发起的下载优先排到队首。
- 若源站返回限流（如 429），任务会降到平缓通道；必要时把该节目标记为平缓下载。
- 普通用户可通过自己的下载队列查看与自己相关的任务，不再只能看全局管理队列。
- `HEAD` 单集音频流会按文件后缀返回正确的 MIME（例如 `.m4a` 为 `audio/mp4`），供客户端探测时长与跳转。

### 播放跳转与进度
- Web：音频尚未就绪或已有待执行跳转时，先记下目标位置，避免被中间的时间更新覆盖。
- Android：补上恒定码率跳转，修正 AAC/播客起始偏移，并避免在准备播客期间把跳转写成进度检查点；缓存键忽略线路查询参数，避免同一音频因线路切换重复缓存或误判。
- Apple：`HEAD` 不被支持时回退为读取首字节探测；播放单集会带上续播位置；进度冲突后自动刷新版本并重试，不再弹出阻断式提示。

## 已知限制

- Web 端到端排序测试和 Android 拖拽仪器测试都还没有补上；现有 Web 播客播放用例只覆盖标签页切换，不覆盖拖拽或上下按钮写回顺序。
- Android 仪器测试的稳定性修复放到下一版本，不包含在 0.8.9 中。Release 工作流会跑完整模拟器回归，`NativePlaybackTest`、`LyricGestureTest` 等既有用例仍可能偶发失败；按发布文档，失败后先看日志、再重跑同一标签，不移动已有 tag。
- Android 播客播放页新增的「AI 导读」标签目前只是占位，文案为即将推出，本版没有识别或总结能力。
- 本地未执行完整 `make ci` 与真机回归，由 GitHub Actions 的 CI 与 Release 工作流覆盖；两者结果以对应运行为准。
