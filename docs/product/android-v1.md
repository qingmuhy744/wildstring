日期：2026-10-15。状态：原生首版工程与 0.1.0 固定签名发布流程已实现；本地编译、单元测试、Lint、ARM64 模拟器登录/播放/手机及平板歌词测试，以及 R8 正式包签名、安装和连接页检查已通过。GitHub 正式 APK 的可下载状态以对应 Release 工作流结果为准。

技术方向已由用户指定为 Kotlin、Jetpack Compose、Media3、Room、Retrofit/OkHttp 与 Hilt。本文中的首版边界是本轮提出的方案，可继续调整。技术约束见 [Android 技术决策](../decisions/0003-native-android.md)，交互草图见 [Android 原型](../design/android-v1.html)。

## 定位与代码基线

Android 是同一个野弦自托管服务的原生听歌客户端，共用服务端真实曲目、收藏、歌单和收听统计。手机连接一个已有实例；首次管理员初始化、曲库导入、CUE 分轨、元数据整理与 AI 模型配置继续由服务端/Web 承担。

最初交互设计从导入/管理提交 `51d7d14` 创建，仅作为设计时的基线记录。0.1.0 已集成曲库管理 [PR #3](https://github.com/qingmuhy744/wildstring/pull/3)、自动导入及 WAV/CUE 转换 [PR #5](https://github.com/qingmuhy744/wildstring/pull/5)、原生客户端 [PR #6](https://github.com/qingmuhy744/wildstring/pull/6) 与正式包名/签名发布流程 [PR #7](https://github.com/qingmuhy744/wildstring/pull/7)。设计草图保留为交互资料，实际应用和服务端功能按源码、契约与各自测试验收。Android 联调时仍需核对目标实例实际部署版本。

## 首版使用闭环

输入服务器地址 → 检查连接 → 管理员登录 → 浏览/搜索曲库 → 播放 → 锁屏或切到后台继续听 → 收藏或加入歌单 → 下次打开恢复队列和位置，点击后继续。

恢复队列不自动播放；明确区分后台仍在播放、进程重建后的暂停恢复和用户强行停止。模型不可用时，这个闭环照常工作。

| 优先级 | 首版能力 | 验收边界 |
| --- | --- | --- |
| P0 | 连接与认证 | 一个实例地址；连接测试、登录/退出、重启保留会话、过期重新登录；HTTPS 默认，HTTP 需对该服务器显式启用 |
| P0 | 曲库 | 歌曲、专辑、艺人、详情、分页和关键词搜索；展示真实标签及多艺人，不猜简繁互转/拼音搜索 |
| P0 | 原音播放 | MP3、FLAC、M4A 样本串流；播放/暂停、上下首、跳转、队列编辑、顺序/单曲循环/随机；格式需按实际编码验证 |
| P0 | Android 播放体验 | 后台/锁屏继续、系统媒体卡片、耳机和蓝牙控制、音频焦点、拔出耳机暂停；导航或旋转不重建播放器 |
| P0 | 歌词 | 复用服务端逐行/纯文本/无歌词协议；高亮、点击跳转、手动滚动与恢复跟随；不承诺逐字歌词 |
| P0 | 手机与平板适配 | 手机歌词独立全屏；平板宽窗采用封面/控制与歌词双栏、侧边导航和自适应专辑网格；旋转/分屏不重置播放 |
| P0 | 个人曲库 | 收藏、普通歌单查看/创建/改名/增删曲目/排序；规则歌单只读浏览与播放，规则编辑留 Web；409 版本冲突先刷新 |
| P0 | 本机恢复 | Room 保存队列条目 ID 与播放位置；在线校验后恢复展示信息，音频不提供离线下载；退出或换服务器清理会话及关联缓存 |
| P0 | 收听统计 | 播放服务按实际播放增量上报，沿用 UUID/累计值的幂等协议；不因旋转、后台或恢复控制器重复计数 |
| 条件交付 | AI 找歌/歌单草案 | 后端提供受控业务接口并验收后接入；展示真实候选、理由、版本差异和保存预览；当前仅设计，不作为 A1–A3 的依赖 |
| 后续 | 离线、投放与扩展 | 下载、跨设备同步、Android Auto、投屏、逐字歌词、均衡器/独占输出、多实例切换、手机上传曲库分开规划 |

随机与循环属于 Android 本地队列行为，不改服务端歌单顺序。首版“播放专辑/歌单”先明确取得完整曲目集合，再交给播放服务；若仅加载一页，按钮必须写“播放本页”，不得悄悄截断。超过本机队列上限时显示实际加入数量。

## 信息架构与屏幕

手机采用三个底部入口：**曲库 · 找歌 · 我的**，播放条常驻导航上方；平板宽窗将同样入口放入侧边导航，底部播放条跨内容区。AI 作为“找歌”中的模式，与普通关键词搜索并列；当前无 Agent 接口时默认只展示关键词搜索，不先提供不能工作的 AI 按钮。

| 屏幕 | 主要内容与操作 |
| --- | --- |
| 连接/登录 | 实例地址与可达状态；区分地址错误、TLS、超时、服务器未初始化、密码错误和限流；提供服务端配置说明 |
| 曲库 | 最近加入、专辑网格、歌曲/专辑/艺人筛选；空曲库提示去 Web 导入；无广告、榜单或外部曲库 |
| 专辑/艺人详情 | 封面、真实标签、曲目数、曲序/碟号；播放全部或本页、下一首播放、加入队列/歌单 |
| 找歌 | 关键词即时查询；后续自然语言查询返回可播放候选和歌单草案；没有结果时不伪造推荐 |
| 我的 | 我喜欢、普通/规则歌单、最近听过；进入设置查看实例、连接状态、缓存大小、版本与退出 |
| 迷你播放条 | 当前封面/标题/艺人、暂停/继续；点击正文展开播放页，暂停按钮独立可点 |
| 正在播放 | 大封面、曲名、多艺人、收藏、进度、上下首/播放/模式、歌词与队列入口；不显示伪造音质徽章 |
| 歌词/队列 | 手机点击封面或“歌词”进入全屏歌词页，返回时恢复封面；平板宽窗歌词常驻右侧，可切换队列；手机队列仍用底部面板，重复曲目用独立条目 ID 定位 |

视觉延续 Web 的深灰、暖白与珊瑚橙，采用 Compose 原生手势和组件。封面优先于装饰；缺封面使用统一占位。触控目标至少 48dp，适配边到边安全区、系统返回、大字体和 TalkBack。手机和平板适配同属首版验收范围。

### 歌词与大屏布局

按用户要求，手机采用网易云式的歌词交互：点击封面或“歌词”，由封面页切换到占满播放页的滚动歌词；大字、当前行突出、上下行弱化，底部保留进度、上下首和播放/暂停。点歌词跳转，拖动歌词暂时停止跟随，通过“回到当前歌词”恢复。返回键先退出队列，再从歌词回封面，最后收起播放器。切换过程中共用同一个 Player，不清空队列或改变暂停状态。

平板采用接近电脑端的播放页：左侧封面、曲名、收藏、进度与控制，右侧歌词；右侧可切成队列，切回仍显示同一首歌的当前位置。封面尺寸有上限，新增空间优先给歌词和曲库内容。无歌词、纯文本与加载错误都在对应区域展示，不阻断播放，也不伪造时间轴。

按当前窗口可用空间适配，不用“是否平板”作为固定布局条件。下列 dp 是 Android 原生设计断点，HTML 草图用 CSS 像素近似演示：

| 可用宽度 | 导航与曲库 | 播放与歌词 |
| --- | --- | --- |
| <600dp | 底部导航、两列专辑；窄窗口和分屏都可回到此布局 | 单栏封面，点击进入全屏歌词，底部保留控制 |
| 600–839dp | 侧边导航、约三列专辑，控制列表行宽 | 封面限制宽度；歌词仍可独立全页，避免双栏挤压 |
| ≥840dp 且高度充足 | 侧边导航、四列起自适应专辑；列表/详情可利用双栏 | 左封面和控制、右歌词/队列，同时可见 |

低高度横屏优先压缩封面并保持控制可达，必要时退回单栏；旋转、分屏缩放与折叠变化保留曲目、位置、队列、模式、歌词/队列选择和暂停状态。原生实现以 Compose adaptive / window size classes 管理，参考 [Android 窗口尺寸分类](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes) 与 [自适应导航](https://developer.android.com/develop/ui/compose/layouts/adaptive/build-adaptive-navigation)。

交互草图使用虚构曲名、艺人与封面占位，数据只在浏览器内演示；播放、收藏、搜索和队列按钮仅用于观察交互，没有接入服务或生成音频。在本分支工作目录执行 `make android-design`，打开 `http://127.0.0.1:18782/android-v1.html` 即可查看。

手机访问服务器需要可达地址。当前 Docker 默认只监听宿主机回环地址，不能直接拿 `127.0.0.1` 给真机使用；保持此默认，联调通过显式部署配置或 HTTPS 反向代理提供访问。Android 应用不自动修改宿主机监听和防火墙。

## 缓存与一致性

- 服务端是曲目、收藏、歌单和统计的事实来源。Room 保存队列与恢复点；SharedPreferences 保存连接与外观 / 缓存偏好，Cookie 使用 Keystore 加密。当前不做本地全曲库镜像或离线修改后合并。
- 本地键由安装内生成的连接空间 ID、规范化服务器 origin/base path 和实体 ID 组成。队列另有 entry ID，允许同曲重复。退出、替换实例或证书异常后不自动把旧会话转给新地址。
- 0.1.0 只复用会话内存。0.2.0 按用户确认的 [应用级缓存策略](../architecture/android-cache.md) 保留曲库页 / 歌词 / 封面和已播放音频片段，支持调整上限及退出清理。通用 HTTP / 图片磁盘缓存继续关闭；短时断网不等于完整离线下载。
- 会话令牌使用 Android Keystore 管理的密钥加密后保存在应用私有区，排除系统备份；不放 Room、日志、串流 URL 或明文 DataStore。密钥丢失则重新登录。
- 收藏/歌单提交时不因缓存旧值默默覆盖服务端。网络失败保留当前界面并提供重试；版本冲突重新读取，由用户重做变更。模型异常不影响已存在的曲目与队列。

Android 工程初始化时将开发入口加入 Makefile，例如 `android-check`、`android-test`、`android-assemble` 与 `android-connected-test`，具体命令随实际工程交付，不先增加空目标。Gradle Wrapper、依赖版本目录、依赖锁与校验元数据入库；不提交 SDK、本机路径、构建缓存、签名私钥与本地音乐。

Android 功能测试须覆盖最低支持版本与当前稳定 Android 的设备/模拟器，至少一台常用国产真机验证后台限制。minSdk 暂定 26（Android 8.0），以依赖与实际设备需求复核；target/compile SDK 与 JDK 在 A1 查官方兼容表及本地 SDK 后固定，不把 IDE 版本号当 API 级别。

设计阶段 A0 已完成文档相对链接、文件大小、JavaScript 语法与 `git diff --check`；通过 `make android-design` 启动 Python 3.12 预览，浏览器检查关键词搜索、展开/收起、暂停、收藏、队列、歌词跳转、手动滚动/恢复跟随，以及 320px 窄窗、390px 手机、768px 平板竖屏、1024px 平板横屏和低高度横窗。检查时横向无溢出，布局切换保留当前曲目、暂停状态与播放位置，浏览器无警告/错误日志。

Python/Web 与容器继续由现有 GitHub Actions 按提交执行；原生客户端新增独立 Android APK 工作流，以对应运行结果为准，见 [发布流程](../releasing.md)。文档与草图检查不能代替 APK 编译、媒体解码、耗电、系统后台行为或真实服务连接验证。
