# 0.5.7：MCP 整理能力与下载导入

用户于 2026-10-19 确认，从 main `f57fa2e` 的独立 worktree 开发；主工作目录的 iOS 规划不在本批范围内。本文是实施与验收清单，勾选前不代表已经实现。

## 已核对的现状

0.5.6 的官方 SDK stdio 桥接提供 20 个业务工具。已有实例联调验证了查询、基础字段巡检、歌单草案、未批准应用拦截、持久巡检及凭据撤销；没有调用模型或修改音乐文件。

当前缺少直接 HTTP MCP 入口，以及导入／待整理、歌词、响度和联网研究的工具。工具参数缺少完整结构与上下限：实测 `limit=200` 被拒绝，按 100 分页成功。基础字段齐全不代表发行版本、歌词质量或元数据事实正确。

## 下载器边界

现有扩展名筛选会忽略 `*.flac.part` 等文件；还需统一目录过滤和显式策略。单个音频的稳定期不等于整个下载任务完成。Transmission 可使用单独的未完成目录，任务完成后移至作为导入源的完成目录；保留原件做种，应用只复制托管副本。

参考：[Transmission 配置](https://github.com/transmission/transmission/blob/main/docs/Editing-Configuration-Files.md)、[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。后续实现按锁定 SDK 和真实测试核对。
