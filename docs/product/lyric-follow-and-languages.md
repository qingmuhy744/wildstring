# 歌词跟随与双语显示

本页描述当前开发分支的修复，尚未发布或部署。现有版本仍以 Release 和运行实例为准。

## 数据与来源

沿用原始内容 `raw`、统一时间轴 `normalized` 和当前选择 `selected_candidate`。
平台解码继续由 ZIP 插件维护；客户端消费统一的行、字时间和语言字段。
原始内容及独立的 `layers.translation`、`layers.romanization` 保留，不写回音乐文件。

播放和候选预览接口为原文行附带 `translation`、`romanization` 显示字段。
服务端按时间轴配对，允许最多 250 毫秒的格式舍入差异；缺失、未标时间或差距过大的译文不会按数组下标强行拼接。
额外的译者信息行不会把后续译文整体错位。选用偏移同时作用于原文、译文、音译和相应的字时间。

Android 和 Web 在原文下显示译文；有数据时提供译文、音译开关。
默认显示译文，音译默认收起；切换显示不改变播放位置，也不替换当前选用的歌词。
手动查询、预览并确认选用的流程保留。没有数据的歌曲不虚构翻译。

## Android 滚动

旧逻辑连续执行“滚到条目”和“移到中央”两个动画，可能产生明显的中途停顿。
修复后，可见目标直接一次滚到中心；远处的目标先测量行高，再一次滚到最终位置。
原文与译文作为同一行组布局，高亮前后文字度量一致，避免字体变粗导致重新换行。
原有手动浏览、显式跳转、空白切换和按设置恢复跟随的行为保留。

## 验证与边界

- 合成回归覆盖字时间保留、语言配对、偏移、候选确认后的播放接口、语言折叠、长行和远距离跳转。
- 同一滚动回归用例在旧逻辑下检测到中途停顿，修复后通过。
- 《Welcome to New York》测试只获取公开元数据及歌词，不下载音频，也不导入个人曲库；真实歌词在临时环境中验证后清理，仅保留数量和测试结论。
- 后端的格式解析成功不等于每个来源、每个发行版本都匹配正确；版本与时间同步仍需预览核对。
- 本地 `.krc` 文件直接导入、增强 LRC 的完整字时间导入、动态候选试听预览和自动查询策略尚未在本次修复中实现。
