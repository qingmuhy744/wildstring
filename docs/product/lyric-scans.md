# 歌词补全与洗版

0.5.3 增加管理员发起的专辑／全库扫描。Web 在管理设置、专辑更多菜单进入；Android 在设置的资料来源与维护、专辑更多菜单进入。创建前检查范围，后台任务不依赖页面保持打开。

## 目标与排序

默认洗版目标为双语逐字，也可仅补缺失，或选择静态、逐行、双语逐行、逐字。默认排序为：无歌词 < 静态 < 逐行动态 < 双语逐行 < 逐字动态 < 双语逐字；双语优先可调整两个中间类型的次序。音译独立显示，不增加等级。

等级根据统一时间轴判断，不看扩展名。逐字及译文需覆盖至少80%的非空歌词行；倒序行时间不能作为正常同步歌词。双语逐字指原文逐字、译文同步，译文不要求逐字。候选先核对版本、歌手及时长，评分至少0.9且时长差不超过2.5秒才进入可升级列表；该分数是规则匹配分，不是概率，也不能证明实际音频同步准确。

只推荐保留已有能力的升级。逐字单语和双语逐行互有优劣时，保留候选供单曲预览选择。批量选择需再次确认，手动锁定、歌词／文件版本变化时不能应用。确认仅更新数据库，不写音频或侧车；任务中可恢复洗版前歌词，后续修改过的歌词不能被旧恢复操作覆盖。

## 限速设置

设置页与创建任务处均提供低频、中频、高频、自定义。初始值为10／5／2秒，后台默认低频；每档间隔及默认档位可保存，单次任务可自定义1–120秒。任务保存创建时的配置快照，修改默认值只影响之后的任务。

每来源串行且无突发令牌；单曲、元数据与批量查询共用来源请求门控。新版1.1.0参考 ZIP 声明逐请求限速，Python传输和Node请求回调均取得许可；未声明的旧插件仅做调用级限速，调用内部可能包含多个请求。等待不占用公共资料任务线程，暂停／取消在请求边界生效，正在传输的请求允许结束。

HTTP429按Retry-After秒数或默认15分钟冷却；未知网络错误最多延迟重试2次，失败不会记为“未匹配”。强制重扫仍遵守门控。长期自定义间隔会相应扩展后台子进程等待预算，暂停及应用退出时仍可终止。

这些是WildString自己的保守初始值，不是平台配额或不会触发限制的保证。2026-10-18核对上游：QQMusicApi默认NiquestsTransport为rate=10、capacity=50、max_concurrency=20；本项目使用自定义传输，不能继承或把这些SDK参数解释成平台允许速率。酷狗及网易云所查README和请求封装未发现明确的推荐间隔。

## 扫描记录与任务

任务包含固定歌曲范围、逐曲状态、目标和来源版本；删除或修改歌曲不会让原任务总数变少。支持暂停、继续、取消、仅重试失败，服务重启后从持久记录恢复。完成后汇总站内通知，歌词查询不调用AI。

已扫记录按歌曲资料／歌词版本、来源包及配置版本、扫描目标和偏好独立保存，任务界面历史和短期查询缓存不代替它。普通扫描复用已找到或未匹配结果；改变目标、歌曲资料或来源版本可增量查询。强制扫描同时绕过已扫记录和插件查询缓存，不删除原候选。

可升级、待核对、未匹配、失败、已满足目标、已扫跳过、锁定、歌曲已变化分别统计。多个来源部分失败时保留其他来源候选与错误；新建任务不会直接替换现有歌词。定时扫描、跨来源拼接译文与本地KRC文件导入不包含在本版。

数据库迁移为schema21。发布和home部署状态以Release与实际运行记录分别核验。
