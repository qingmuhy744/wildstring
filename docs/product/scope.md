## 定位

野弦是 **AI native 的自托管音乐与播客播放器**，覆盖 Python 后端及 React Web、Android（Kotlin / Compose / Media3）、macOS（SwiftUI / AppKit）、iOS（SwiftUI）四端客户端。AI 主线围绕 **自然语言找歌、生成歌单、受控整理草案与 MCP 扩展**。

完整流程：挂载只读导入源 → 复制并整理到托管曲库 → 多端浏览曲库与订阅播客 → 播放与查看双语/逐字歌词 → 用自然语言或 MCP 找到真实曲目并生成整理/歌单草案 → 预览或按授权应用 → 播放。

当前面向自托管实例（客户端支持保存并切换多个服务器与多条连接线路），支持多个音乐库、每库多个只读导入文件夹和按用户分配库权限；所有者创建账号（所有者、曲库管理员、资料编辑员、听众四档角色），收藏、跨库歌单和收听记录按用户隔离。播客节目与音频缓存共享，个人关注、单集收藏、收听进度与待播列表分开保存；单集级收藏（`单集收藏` / `取消收藏`）提供跨端列表与详情过滤，且在服务端享有音频防清理保护（任一用户收藏即阻止自动与手动资源清理）；实现与验证见[多库与个人关注](../../contracts/multiple-libraries.md)、[播客待播与新集处理](../../contracts/podcast-queue.md)及[播客资源清理保护](../../contracts/storage-and-podcast-resources.md)。各原生客户端构建与功能边界分别见 [Mac 客户端](../../frontend/macos/README.md)、[iOS 第一版](ios-v1.md) 及 [Android 构建与安装](../../frontend/android/README.md)。

## 首版范围与验收

| 能力 | MVP 边界 | 验收条件 |
| --- | --- | --- |
| 曲库导入 | 从只读源复制 MP3、FLAC、M4A 到托管库；整理目录、复制侧车、读取标签；识别文件变化 | 重扫不重复入库；损坏文件单独报错；源文件内容不变，重复导入不覆盖托管副本修改 |
| 浏览与搜索 | 歌曲、歌手、专辑；分页、关键词搜索和基本筛选 | 中文、繁体标签可展示；无结果时返回空结果 |
| 网页播放 | 播放/暂停、队列、上一首/下一首、进度和音量；优先原文件串流 | 验证 Range、切歌和断连错误；不兼容格式明确提示 |
| 本地歌词 | 同名 LRC、纯文本与可读取的内嵌歌词 | 逐行歌词跟随播放；没有歌词时仍可播放 |
| 元数据修复 | 在服务端手动/批量编辑标题、艺人、专辑、曲目编号与封面；含歌词编辑与逐行打点；先预览，数据库覆盖与未来显式写回分开 | 核对文件版本；保留恢复材料；写回后重扫且保留曲目 ID；大文件不需在客户端来回传输 |
| 自然语言找歌 | 将意图转为曲库检索、过滤与候选选择 | 只返回存在且可访问的曲目 ID；歧义版本允许追问 |
| AI 歌单 | 根据自然语言、元数据和可用偏好生成歌单草案 | 展示真实曲目与依据，预览后保存；空曲库不编造结果 |
| 歌单管理 | 创建、重命名、增删曲目与排序 | AI 与普通界面共用业务校验 |
| 基础管理 | 本地账号、管理员/普通用户、改密/重置、模型配置和任务状态 | 密钥不下发浏览器；认证完成后再考虑局域网开放 |
| 后台任务 | 扫描等任务的持久状态、可恢复执行和失败反馈 | 重启后不把未完成任务当成功，可查看进度和原因 |
| 自托管 | 单镜像包含后端与 Web，SQLite 与文件持久化 | 容器重建不丢数据；音乐只读；无模型时仍可浏览和播放 |

“可扫描”与“目标浏览器可播放”分别验收。首版不承诺所有编码均可直放；已实现客户端明确请求的无损到 AAC 转码与偏移跳转；平台兼容状态见交付说明。

已核对的下一阶段播放方案：客户端明确请求 AAC 和目标码率时，对无损音源实时转码；有损音源默认直放，转码结果提供服务端缓存与清理。后端与 Web 已实现，接口、默认值与验收边界见 [AAC 实时转码与缓存设计](../architecture/playback-transcoding.md)。

## AI 边界

- 下一轮按 [AI 助手、MCP、诊断与通知开发计划](agent-mcp-observability-notifications-plan.md) 分阶段推进：暂不实施 SIWC，保留用户配置的 AI API，统一网络与日志，开放 MCP 和受控巡检。结果默认保存为站内通知，由 Web／Android 上线或回到前台后拉取；Telegram 为可选外部渠道。0.4.0 分支已增加首版实现；该计划的验收项与真实上线状态仍以发布记录分别核对。
- 受控工具先提供搜索曲库、读取曲目、生成歌单草案和保存歌单；共用普通业务服务和权限。
- 从元数据与结构化搜索开始，根据真实查询效果再补文本向量检索。
- 听感、音色和音频相似性需要音频分析证据，不由模型猜测补成事实。
- 候选曲目 ID 经服务端校验；说明推荐依据；外部模型失败可恢复。
- AI 修复建议先展示差异，批准后保存数据库覆盖；文件标签写回仍未实现，后续需单独显式操作且只针对托管副本。日常扫描只读取音乐文件。不默认向外部模型上传整份私人曲库。

## 后置能力

Linux / Windows 原生桌面客户端（Tauri + Rust）、无人值守批量写回原文件标签、音频内容向量、模型训练、网盘挂载、复杂多镜像 CUE/DSD、独占硬件输出、车载、OpenSubsonic、多用户协作歌单与远程播放控制仍属后置能力。Web、Android、macOS 与 iOS 四端客户端、多库与个人播客关注、MCP 受控工具与整理草案已按批次交付（见上方各版本记录）。外部信息自动匹配与目录自动重组另行验证，文件标签写回仍须作为显式操作且只针对托管副本。

第三方来源的覆盖率和使用条件后续单独核验，不直接把原始讨论里的接口变成首版依赖。

## 里程碑

1. **M0 工程基座**：依赖锁、Make、hooks、测试、Docker、Actions；网页显示真实连接状态。
2. **M1 曲库与整理**：SQLite 模型、扫描、浏览、搜索、管理员认证，以及元数据修复的预览、应用和显式写回。
3. **M2 播放**：原文件串流、网页队列、本地歌词与浏览器兼容验证。
4. **M3 AI**：模型适配、受控工具、自然语言找歌与歌单预览/保存。

完整 MVP 需要 M1–M3 全部通过。使用有权使用的中文曲库，覆盖繁体、同名、现场与多发行版本；至少整理 30 个有预期结果的 AI 查询，检查筛选、可播放性、歧义处理与零虚构曲目 ID。0.3.0 已增加 30 条中文本地检索条件的 API 验收及真实 HTTP 模型夹具；云端模型听感与真实账号授权的验证边界见本批记录。
