# MVP 范围

更新日期：2026-10-15。

## 定位

野弦是 **AI native 的自托管音乐播放器**。第一阶段提供 Python 后端与 React 网页端。AI 主线已确定为 **自然语言找歌与生成歌单**。

完整流程：挂载只读导入源 → 复制并整理到托管曲库 → 浏览曲库 → 网页播放与查看本地歌词 → 用自然语言找到真实曲目 → 预览并保存歌单 → 播放。

当前面向单个自托管实例与一个共享曲库，支持管理员和普通用户；管理员创建账号，收藏、歌单和收听记录按用户隔离。手机可通过网页访问；Android 已增加 Kotlin/Compose/Media3 原生首版客户端、独立 APK 检查与版本发布流水线，功能及构建/设备验证状态见 [Android 第一版](android-v1.md) 和 [构建与安装](../../frontend/android/README.md)。

## 首版范围与验收

| 能力 | MVP 边界 | 验收条件 |
| --- | --- | --- |
| 曲库导入 | 从只读源复制 MP3、FLAC、M4A 到托管库；整理目录、复制侧车、读取标签；识别文件变化 | 重扫不重复入库；损坏文件单独报错；源文件内容不变，重复导入不覆盖托管副本修改 |
| 浏览与搜索 | 歌曲、歌手、专辑；分页、关键词搜索和基本筛选 | 中文、繁体标签可展示；无结果时返回空结果 |
| 网页播放 | 播放/暂停、队列、上一首/下一首、进度和音量；优先原文件串流 | 验证 Range、切歌和断连错误；不兼容格式明确提示 |
| 本地歌词 | 同名 LRC、纯文本与可读取的内嵌歌词 | 逐行歌词跟随播放；没有歌词时仍可播放 |
| 元数据修复 | 在服务端手动/批量编辑标题、艺人、专辑、曲目编号与封面；含歌词编辑与逐行打点；先预览，数据库覆盖与未来显式写回分开 | 核对文件版本；保留恢复材料；写回后重扫且保留曲目 ID；大文件不需在客户端来回传输 |
| 自然语言找歌 | 将意图转为曲库检索、过滤与候选选择 | 只返回存在且可访问的曲目 ID；歧义版本允许追问 |
| AI 歌单 | 根据自然语言、元数据和可用偏好生成歌单草案 | 展示真实曲目与依据，预览后保存；空曲库不编造结果 |
| 歌单管理 | 创建、重命名、增删曲目与排序 | AI 与普通界面共用业务校验 |
| 基础管理 | 本地账号、管理员/普通用户、改密/重置、模型配置和任务状态 | 密钥不下发浏览器；认证完成后再考虑局域网开放 |
| 后台任务 | 扫描等任务的持久状态、可恢复执行和失败反馈 | 重启后不把未完成任务当成功，可查看进度和原因 |
| 自托管 | 单镜像包含后端与 Web，SQLite 与文件持久化 | 容器重建不丢数据；音乐只读；无模型时仍可浏览和播放 |

“可扫描”与“目标浏览器可播放”分别验收。首版不承诺所有编码均可直放；已实现客户端明确请求的无损到 AAC 转码与偏移跳转；平台兼容状态见交付说明。

已核对的下一阶段播放方案：客户端明确请求 AAC 和目标码率时，对无损音源实时转码；有损音源默认直放，转码结果提供服务端缓存与清理。后端与 Web 已实现，接口、默认值与验收边界见 [AAC 实时转码与缓存设计](../architecture/playback-transcoding.md)。

## AI 边界

- 受控工具先提供搜索曲库、读取曲目、生成歌单草案和保存歌单；共用普通业务服务和权限。
- 从元数据与结构化搜索开始，根据真实查询效果再补文本向量检索。
- 听感、音色和音频相似性需要音频分析证据，不由模型猜测补成事实。
- 候选曲目 ID 经服务端校验；说明推荐依据；外部模型失败可恢复。
- AI 修复建议先展示差异，由用户选择是否写回原文件；日常扫描只读，写回由单独启用的服务端任务执行。不默认向外部模型上传整份私人曲库。

## 后置能力

其余平台原生应用、离线下载、逐字歌词、在线歌词聚合、无人值守批量写回、音频内容向量、模型训练、复杂推荐、网盘、复杂多镜像 CUE/DSD、独占输出、车载、OpenSubsonic、多用户协作与跨设备播放同步。Android 按独立分期推进，不改变 Web MVP 的验收条件。外部信息自动匹配与目录自动重组另行验证，不作为手动修复的前提。

第三方来源的覆盖率和使用条件后续单独核验，不直接把原始讨论里的接口变成首版依赖。

## 里程碑

1. **M0 工程基座**：依赖锁、Make、hooks、测试、Docker、Actions；网页显示真实连接状态。
2. **M1 曲库与整理**：SQLite 模型、扫描、浏览、搜索、管理员认证，以及元数据修复的预览、应用和显式写回。
3. **M2 播放**：原文件串流、网页队列、本地歌词与浏览器兼容验证。
4. **M3 AI**：模型适配、受控工具、自然语言找歌与歌单预览/保存。

完整 MVP 需要 M1–M3 全部通过。使用有权使用的中文曲库，覆盖繁体、同名、现场与多发行版本；至少整理 30 个有预期结果的 AI 查询，检查筛选、可播放性、歧义处理与零虚构曲目 ID。此处为验收计划，尚未执行。

## M1 的首个交付单元

先实现只读扫描、持久曲目 ID、增量更新、扫描记录，以及分页查询和基础关键词搜索。通过 `make scan` / `make docker-scan` 手动启动；该单元不包含网页扫描按钮、定时 Worker、管理员认证、播放或文件写回。

下一单元已推进管理员认证、网页曲库浏览与搜索，以及基础原音播放（队列、切歌、进度、桌面音量）。现已继续接入歌曲/专辑/艺人视图、封面、本地歌词与标准目录导入，播放使用托管副本；普通/规则歌单、♥ 收藏、收听次数/时长与播放队列排序也已接入，见 [个人曲库](../../contracts/personal-library.md)。播放器支持原音与明确请求的 AAC；已支持单曲元数据的数据库覆盖编辑；批量整理和修复写回仍待开发。验证状态见 PR 与交付说明。写回设计见 [服务端整理](../architecture/metadata-repair.md)。

## 下一开发单元：曲库管理与设置

`feat/library-admin` 先补管理入口、曲库概览、网页导入/扫描与任务记录，再完成单曲元数据的数据库覆盖编辑；重扫保留人工值。批量编辑、封面/歌词管理、计划任务及显式写回分批交付。具体边界与验收计划见 [曲库管理与设置](library-admin.md)。首批管理界面、持久任务和单曲编辑已实现，另提供 AI API 连接配置与模型测试；写回、Agent 与 MCP 尚未实现。实现边界见 [管理接口](../../contracts/library-management.md)，框架建议见 [Agent 设计](../decisions/0002-ai-connections-and-agent.md)。

## 自动导入首批

已实现默认关闭的定期发现、稳定期观察、基础元数据预检、托管暂存和待整理补充；WAV 16/24 位整数 PCM、单镜像 WAV/FLAC CUE 可转换为逐曲 FLAC，发布前核对完整 PCM。实现、格式限制和验证入口见 [自动导入](../../contracts/automatic-import.md)。下载器完成回调、多导入源、外部匹配、AI 修复、已有文件自动写回仍未实现。

## 网页与账号扩展

当前分支增加管理员歌词编辑、纯文本逐行打点与 LRC 导出；歌词覆盖存数据库，重扫保留，不写回文件，见 [歌词编辑](../../contracts/lyrics-editing.md)。增加本地多用户、个人数据隔离、改密/重置、默认关闭的 Host 白名单，见 [账号与访问](../../contracts/users-and-access.md)。网页提供浅色、深色和跟随系统，偏好保存在当前浏览器；全屏背景从专辑封面取色。这些实现的测试和容器状态以本次交付记录为准，不代表原生客户端已增加对应 UI。
