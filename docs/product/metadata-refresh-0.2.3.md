# 0.2.3 元数据刷新与指纹识别

2026-10-17。用户确认接入 AcoustID，并增加类似 Emby／Jellyfin 的手动更新及网页来源优先级设置。功能实现与验证状态以 PR 检查和交付记录为准；尚未发布。

## 入口与更新方式

- 管理员在歌曲的「⋯」菜单或歌曲编辑器选择「更新元数据」。专辑页提供「更新专辑元数据」，曲库管理概览提供「更新曲库元数据」。普通用户没有这些入口或管理 API 权限。
- 弹窗默认「只查缺失资料」：保留现有字段和全部人工覆盖，包括人工留空的字段，仅为缺失字段生成建议。来自文件名的歌名可作为缺失标题补充；外部 ID 只在录音身份一致时补充缺少的标识。
- 「查询全部资料」重新生成可比较的候选。无论选择哪种方式，都不自动覆盖现有值；在歌曲编辑器中逐字段确认后才应用。
- 「重新联网查询」绕过近期的联网响应缓存。关闭时可复用近期结果；本地指纹仍按文件版本复用，文件变化后重新计算。
- 提交立即显示反馈，后台逐曲处理；重复提交只返回新增任务数及已在处理的歌曲数。管理「任务记录」可以查看待处理、查询中和最近结果，并打开歌曲建议。重启后继续待处理任务。
- 本次不提供批量自动应用，不删除自选封面，不自动写回标签或重排文件目录。已有本曲／专辑封面继续优先，CAA 仅为缺图提供候选。

## 来源优先级

管理 → 设置 → 联网资料可用三横杠拖动 MusicBrainz／Last.fm 的先后顺序，支持触屏和键盘方向键；保存后生效，默认 MusicBrainz 在前。

优先级决定候选显示和同名字段的优先推荐。高优先来源没有某字段时，较低来源可提供该字段；不同发行版仍单独展示，不合并成一个未经核对的专辑。优先级变化也会调整已有候选的显示次序，不会直接改歌曲。

人工覆盖保留，本地图片优先是独立规则。AcoustID 用于识别录音，CAA 用于发行版封面；它们不与 MusicBrainz／Last.fm 的资料字段争抢排序位置。

## AcoustID 流程

1. 管理员保存应用 API Key，勾选「AcoustID 音频指纹识别」，同时启用 MusicBrainz；指纹识别默认关闭。
2. `fpcalc` 读取托管副本的前 120 秒计算 Chromaprint 指纹，同时读取完整曲长。服务端只发送压缩指纹、曲长及应用标识，不发送音频、文件路径或标签。只调用 lookup，不提交新指纹。
3. 接受相似度不低于 0.7 的录音候选，去重后最多保留三个 MusicBrainz recording ID；相似度用于筛选，不等同于身份正确的概率。
4. MusicBrainz 补充资料，每个录音最多保留三个发行版。已有发行版 ID 只作为排序提示，错误 ID 不会排除识别出的其他候选。网页显示「AcoustID 指纹匹配」、相似度、识别来源和 MusicBrainz 来源，用户核对版本与字段后应用。
5. 无匹配或指纹服务失败时回退至既有外部 ID／歌名艺人查询；错误不会阻断本地播放。指纹失败、密钥拒绝与网络错误保留固定错误码，不记录密钥、指纹或远程原始错误。

联网请求复用现有网页代理和 Docker 环境变量，跨进程限流保持每秒约一次，低于 AcoustID 公开服务上限。联网结果与本地指纹缓存均为 24 小时，复用现有有容量上限的服务端缓存。音频只读、限时解码、检查文件变化，关闭服务时终止解码子进程。

## 部署与凭据

Docker 的原有单镜像增加 Debian `libchromaprint-tools`，不增加容器，也不增加 Python SDK。镜像 smoke 会检查 FFmpeg 和 fpcalc。原生 macOS／Linux 后端需要自行安装 Chromaprint；使用 `make fingerprint-check` 检查。该指纹适配使用安全文件描述符，Windows 后端使用 Linux Docker；Windows 客户端不受影响。

应用 Key 只保存于未跟踪的 `providers/.env`（0600；Docker 中位于 `/data/providers/.env`），网页保存后清空输入框，API 只返回是否配置。生产 Key 不进入测试夹具、Git 或 CI；测试使用模拟响应和合成音频。

数据库从 v12 原子升级至 v13，新增来源优先级、AcoustID 开关、指纹匹配依据及任务更新方式；保留原设置、曲目 ID、人工修改与用户数据。实际服务升级时使用新镜像和持久卷，不让旧版本同时运行于已升级的数据库。
