# 曲库管理与设置

状态：规划中，管理页面和下列新增接口尚未实现。更新日期：2026-10-15。开发分支：`feat/library-admin`。

## 目标与入口

在现有 React 网页中增加“管理”入口，共用 Python 服务与管理员会话。管理曲库、任务和设置时保留当前播放器、队列和进度；返回听歌页面无需重新登录。保持现有单管理员、一个导入源与一个托管库的边界。

参考 Emby 的 [曲库设置](https://emby.media/support/articles/Library-Setup.html)、[元数据管理](https://emby.media/support/articles/Metadata-manager.html) 和 [任务管理](https://emby.media/support/articles/Scheduled-Tasks.html)：把配置、媒体编辑与长任务放入统一管理区，同时允许从歌曲操作进入编辑。人工字段锁定也值得借鉴，避免刷新覆盖已整理的信息。这是交互设计参考，不代表实现其全部服务功能。

## 功能分期

| 阶段 | 页面/能力 | 范围与验收 |
| --- | --- | --- |
| 首批 | 概览与曲库 | 展示歌曲/专辑/艺人数量、导入源、托管目录、可用空间、最近任务；区分导入与重扫，支持网页手动启动 |
| 首批 | 任务记录 | 查看排队、执行中、完成、部分失败、中断状态及逐文件错误；阻止冲突任务并发，重启后可识别未完成任务 |
| 首批 | 基础元数据编辑 | 单曲编辑标题、歌曲艺人、专辑、专辑艺人、曲号与碟号；预览差异、保存数据库覆盖、撤销覆盖；重扫保留人工修改 |
| 第二批 | 批量整理与图片/歌词 | 多选批改、专辑级编辑、封面与歌词管理、字段锁定；按真实曲目 ID 执行，保留多艺人结构 |
| 第二批 | 计划任务与账号 | 定时导入/扫描、任务失败重试；修改密码、撤销会话；配置修改提供版本冲突提示 |
| 后续独立交付 | 写回与目录重整 | 显式将选定字段写回托管副本；“保存并整理”预览新路径并准备恢复材料，执行后保留曲目 ID 与收藏/歌单/统计引用 |
| 随对应功能交付 | 信息来源与 AI 设置 | 来源优先级、只补缺失/刷新策略、模型地址/名称、超时和连通性测试；外部来源及 AI 尚未实现，不先提供无效开关 |

首个开发闭环为：进入管理 → 查看曲库和任务 → 启动导入或扫描 → 查看结果 → 编辑一首歌并保存 → 重扫验证人工值仍在 → 返回继续播放。

## 设置如何划分

- **曲库设置**：显示名称、导入/扫描策略、命名规则预览。首批展示当前配置的路径与可访问状态；路径仍由服务端部署配置管理。更改根路径会影响现有曲库身份，需要单独迁移设计，不直接通过表单替换。
- **系统设置**：应用版本、数据位置、数据库状态、磁盘空间和备份状态。监听地址、端口、挂载目录、HTTPS Cookie 等部署项显示当前有效值及修改方式，不在浏览器任意改写 `.env`。
- **账号与会话**：沿用单管理员认证；未来网页改密校验当前密码，并撤销已有会话。首次初始化与恢复仍保留服务器端 Make 命令。
- **来源与模型配置**：非敏感配置按版本保存；密钥继续来自未跟踪的 `.env` 或部署 secrets。管理 API 只返回是否已配置，不返回原始密钥。
- **个人播放偏好**：默认视图、歌词跟随等归播放器偏好，和实例级曲库/任务设置分别保存。跨设备同步单独设计。

多曲库、多管理员权限、任意服务器目录浏览、自动删除音频、在线更新程序、完整转码与插件市场不在本分支首批范围内。

## 数据与执行约束

1. 编辑时区分文件观测值和数据库覆盖值；展示生效值、来源和差异。人工覆盖优先，清除覆盖才恢复文件观测值。扫描不会把人工值当成新文件标签写回。
2. 首批保存只修改数据库，不改名或写音频。导入源始终只读；后续写回和目录整理都只作用于托管副本，沿用 [服务端修复设计](../architecture/metadata-repair.md)。
3. 编辑请求使用真实曲目 ID、字段白名单与版本校验，服务端确认曲库归属。修改后歌曲、专辑、艺人和规则歌单使用相同生效元数据；当前播放不重载音频。
4. 导入/扫描沿用现有服务能力，增加持久任务调度与状态查询；网页请求提交后立即返回任务 ID，不让 HTTP 请求等待全库处理。进度只展示已知计数，未知总量不伪造百分比。
5. 同一托管库的导入、扫描与未来写回/移动协调执行，命令行入口也遵守同样的锁和状态约束。中断任务标记原因，只有支持幂等的阶段才能恢复或重试。
6. 管理 API 要求管理员会话，写请求沿用客户端标头与校验；不接受可逃逸托管根目录的任意文件路径，不打印凭据。

## 验证计划

- 后端覆盖数据库升级、覆盖值与原始值分离、撤销/重扫、版本冲突、曲库隔离、任务去重、并发与中断恢复。
- 浏览器覆盖桌面/手机管理导航、任务结果、单曲差异预览与保存，并确认进入/退出管理不重建音频元素或清空队列。
- 按 `make ci` 检查；涉及任务执行或配置行为时运行 `make docker-up docker-smoke`。真实容器验证前备份数据库，比较曲目 ID 及导入源/托管音频哈希，确认首批数据库编辑没有修改音乐文件。
