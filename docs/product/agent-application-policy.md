# 用户选择整理方式

0.5.9 实现，实际发布与部署以对应版本记录为准。此页替代历史文档中“所有草案必须先批准、再应用”的交互约定。

## 使用方式

- Web：助手设置 → 整理方式。
- Android：野弦助手 → AI 连接 → 整理方式。
- 默认“审核后应用”：打开差异与来源后，点击一次“接受并应用”。服务端在同一事务内批准当前版本并保存修改；无需再点应用。
- 可选择“自动整理”，再勾选允许的类型：本人歌单，以及管理员可用的单曲信息、专辑批量信息、封面、歌词、导入整理。新草案按授权直接应用，未授权类型仍待确认。
- 设置属于当前账号，不代表对其他用户或整个实例授权。MCP 可读取设置，不能修改设置或替用户接受；凭据同时需要 `drafts:apply` 才会自动应用。
- 开启设置不会追溯执行已有待确认草案。关闭设置后，不再自动批准新的或尚未批准的修改。旧客户端的批准、应用接口继续兼容。

## 一致性与留痕

自动和手动使用同一应用事务，校验角色、对象所有权、元数据版本、专辑成员和图片快照。整批任一曲冲突则整批回滚，人工接受失败也不会留下仅批准状态。重试沿用幂等键，不重复改动或重复发出成功事件。

自动应用失败时保留待确认草案与 `result.automatic_error`；只有 `status=applied` 表示完成。成功结果记录 `application_mode`，自动应用另记 `policy_version`，与修改前快照、逐曲历史、审计及通知关联。已有历史界面可供核对；本批没有新增通用的一键撤销。

资料覆盖保存在数据库，封面采用创建草案时缓存的图片；歌词沿用原有候选版本校验。导入安排原有复制流程，不写回标签、不移动或修改导入源。

## 接口

- `GET /api/v1/agent/application-policy`：`mode`、`kinds`、`version`、`allowed_kinds`。
- `PUT` 同地址：仅登录会话；传 `mode`、`kinds`、当前 `version`，冲突返回 409。其他通知及助手设置合并保存，不覆盖整理授权。
- `POST /api/v1/agent/drafts/{id}/accept`：仅登录会话，传当前 `version`、稳定的 `idempotency_key`；封面与批量类型还需 `preview_digest`。
- MCP `get_application_policy` 只读；`create_draft` 可能直接返回 applied，调用者须读实际状态。`apply_draft` 可消费人工批准或当前自动授权，但不允许 rejected 草案，不接受伪造的批准或设置字段。

使用现有 schema22 的账号偏好 JSON，不更改数据库版本。模型调用与来源查询频率沿用原设置，授权自动应用本身不会启动整库抓取或调用模型。
