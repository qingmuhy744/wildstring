# 方案文档（docs/plans）

重活的执行契约。跨文件重构、批量机械改动及需要反复跑测试的重活先在这里落盘，再按方案执行；只在用户显式点名时交给外部 agent。适用范围以 `AGENTS.md` §1 为准。

## 状态

每份方案第一行写状态，状态变化时同步更新，不在正文里保留“开发分支”“尚未发布”等时效说法：

| 状态 | 含义 | 推进者 |
| --- | --- | --- |
| `草案` | 正在讨论，未经审查 | 主笔 |
| `已确认` | 已过审查，可以被执行 | 用户 |
| `已实施` | 代码已落地，等待合并 | 执行方 |
| `已交付于 PR #N` | 已合并 | 用户 |
| `已取消` | 不做了，保留原因 | 任何人 |

状态与实现不符即视为文档缺陷：代码已落地但状态仍是「草案」、或「草案」超过 30 天没有推进，按 `AGENTS.md` §1 核对并修正。

## 模板

```text
状态：草案

# <主题>

## 目标
## 不碰的边界
## 方案
## 验收（按 AGENTS.md §3 定级）
## 风险与回滚
```

## 约定

- 一个主题一份，文件名用 kebab-case：`docs/plans/ci-android-path-filter.md`。
- 交付后不删除，状态改为 `已交付于 PR #N`。
- 方案是该主题的执行入口：传路径，不复述内容；仍须遵守 `AGENTS.md`、`DESIGN.md` 与现行产品契约。
- 早期批次方案与一次性审计已归档至 [`docs/archive/`](../archive/README.md)；其余未归档的计划、设计与审计文档按 `AGENTS.md` §1 维护开头状态行，部分实施时分别列明已落地与剩余范围，历史验收清单不自动补勾。
