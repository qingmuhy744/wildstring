# 播客暂停恢复与跨设备接续

## 目标与交付顺序

补全「手机暂停 → 电脑继续 → 手机再按播放」以及多设备同时播放的行为。用户已确认在同一 PR 实施 Android、Web、macOS、iOS 的统一规则，不再等待 Android 单独合入后另开全端 PR。

代码核对基线为 Android 修复提交 `2587dfd`；已落地的回退恢复修复与实际验收见 [Android 播放控制方案](android-podcast-transport.md)。下表保留实施前现状，目标与验证状态随实现更新。现行服务端协议见 [进度契约](../../contracts/podcast-progress.md)，待播与播放线见 [待播契约](../../contracts/podcast-queue.md)。

### 已核对的原则

- 同一账号、同一集只有一份云端书签。允许多个设备出声，但只有服务端当前接受的会话能继续写入；没有远程暂停、设备在线状态或全局播放器主机。
- 连续播放期间不因远端进度而跳转。失去写入权仍能本机播放、暂停、回退并落盘；后台重试不重新抢占。
- 用户主动播放与系统临时中断后的自动恢复分开。App、通知、锁屏、耳机收到的主动播放命令采用相同规则；自动恢复沿用本机位置和会话。
- 新位置由被接受的操作决定，可以向前也可以向后；不选最大进度，不用客户端时间判断谁更新。
- 服务器故障不能无限阻塞本机播放。进度读取有整体等待预算；超时后的迟到结果不能再跳转。
- 显式定位优先于自动选择的位置；暂停、切集、退出登录后，旧请求不能让播放器重新出声。

### 已确认的细化规则

四端统一采用以下规则：

1. **账号续听偏好只用于重新点播；普通恢复不重新套用三种模式。** 普通恢复发现异设备新进度就接续，否则保留本机暂停点；不因 `restart` 偏好把普通播放键变成从头播放，也不在锁屏恢复时等待弹框。重新从列表／详情选集才执行 `auto / ask / restart`，不是新增按钮或设置。
2. **普通恢复读到远端已听完时保持暂停，显示已有的完成状态。** 不偷偷从零重播或改播下一集；明确重新选集／从头播放仍可重播。用户明确选择位置则保留其本机定位意图，但 `resume` 不清除已听完。
3. **失去写入权的旧端播完即停，不继续修改共享待播或自动开启下一集。** 结束写入未得到确认时也先停在片尾，待播不移除；用户主动选择下一集仍可播放。此项把同步失败的影响限制在自动片尾操作，不阻塞当前集或手动控制。

## 不碰的边界

- 不增加数据库字段、播放租约、设备锁、推送、后台轮询远端进度或新续听设置。
- 不更改服务端完成阈值、音频引用清理、音乐接续或发布版本。
- 不承诺暂停设备实时知道另一台的进度；主动恢复时读取服务端最近已接受的书签即可。
- 进度离线降级不等于音频可离线播放；仍需可用的本机音频或可访问的串流。

## 方案

### 1. 按触发原因决策

| 触发 | 位置与写入行为 |
| --- | --- |
| 用户重新选集 | 读远端，应用缓存的账号续听偏好；已听完的显式点播按现有规则重播；确认起播后才尝试新会话 |
| 用户恢复已暂停的当前集 | 在整体预算内读远端；异设备更新则采用其位置，没有异设备更新则用本机暂停点；需要接管时才建立新会话 |
| 用户先定位再按播放 | 本次明确选定的位置优先；读取仅用于取得版本与完成状态，不能覆盖目标位置 |
| 连续播放、缓冲结束、临时焦点恢复 | 沿用本机位置与会话；不进入恢复读取或新会话流程 |
| 只打开页面、回前台、恢复暂停队列 | 可只读刷新显示，不启动播放、不接管 |
| 冲突后的「用本机进度」 | 明确接管本机位置，使用 `resume` 保留完成状态；再次冲突仍保留本机播放，不反复争抢 |
| 自然结束、自动续播 | 先判定本次结束是否被当前会话接受；未确认或已冲突则不改共享待播、不自动接下一集 |

「异设备更新」比较服务端版本以及会话、设备归属，与本机最后观察到的状态比较；不能只比较位置大小。远端仍是本机会话时，优先保留本机尚未上传的暂停点。同设备的另一会话也不能仅凭相同 `device_id` 就当作本次播放；须保留现有会话与账号作用域检查。

本机显式定位只覆盖本次定位后的恢复，不永久压过后续远端更新。播放恢复、重新选集或切换账号后消费／清理该意图。连续播放中冲突后回退仍只改本机，不因 `seek` 自动接管。

重复收到 PLAY 时，若已有播放意图（包括缓冲或临时抑制），不重复读取、不新建会话。只有从真正暂停恢复的主动命令进入上述流程。不能用 `isPlaying` 的真假、暂停时长或屏幕亮灭猜测用户意图。

### 2. 把网络同步移出本机控制链路

- 准备流程不要串行等待「旧待发送 PUT → GET → 新会话 PUT」才放行音频。先保留本机检查点；恢复读取只有一个整体预算，包含排队与请求时间；新会话写入通过既有待发送机制处理。
- 实施时在代码中定义统一预算，并用延迟 GET / PUT 测试断言上限。不能给每一步各设一次超时后累加等待；音频加载和用户确认不计作进度读取预算。
- GET 超时、断网、可恢复的服务端错误时，采用最新本机位置，包括已经冲突但持续保存的本机位置；无记录才用最后已知书签或零点。认证失效、无权限、单集失效不能当作普通离线绕过。
- 本机开始后，迟到 GET 只可被丢弃，不能改变位置或会话。取消本次意图、切集、账号／服务器变化时取消请求并检查归属；相同单集 ID 也须区分前后两次选择。
- 暂停时不制造周期性 `progress` 写入；已有待发送记录仍可按原规则重试。焦点抑制和缓冲只保存需要的本机状态，不能伪造片尾 `pause / stop / ended`。
- 新会话 PUT 失败或 409 时，音频从本次已选位置继续；标明暂不同步并保持版本隔离。不要为了「一定接管成功」追加无限重读、改版本、重传。

GET 与首个 PUT 之间，旧设备可能恰好上传心跳，导致主动接续遇到 409。首版沿用停传与显式接管，不新增跨设备自动改版本重试。若测试或实际数据证明影响明显，再评估「仅同一次主动意图、且远端仍是读取时的同一会话」的单次重读；这不是后台补传规则，也不是本方案默认新增的复杂度。

### 3. 完成、队列与会话边界

自然结束须等待**自己本次会话的结束写入**得到确认，不能只检查此前是否出现冲突：冲突可能第一次出现在 `ended` 的响应里。已确认且仍是本次播放，才按既有播放线移除待播、选择下一集；队列 CAS 冲突不静默覆盖。睡眠计时器到片尾仍优先停止。重复结束回调不能重复移除或开启后继。

服务器目前按「单集进度」和「用户待播列表」分别 CAS，没有把结束、队列移除和下一集开播放在一个事务中。因此上述检查能阻止**已失权或本次结束被拒绝的旧端**继续自动操作，不能承诺确认后恰好发生的跨设备操作也绝对互斥。尤其两台设备听不同集时，单集会话互不排斥。若要保证整个账号永远只有一条自动播放线，必须另做跨集协调协议，超出本轮范围。

手动标为已听完／未听沿用已有显式操作。完成状态与本机出声分开：`resume` 不清除服务端已听完；正在听时收到远端完成也不突然跳位置。不要因为播放器恢复而自动发 `restart`。

## Android 场景表

「现状」来自 `2587dfd` 源码核对，不等于所有行都做过设备复现。下文的“权”仅指当前集的云端进度写入权。A、B 是同一账号的两台设备。

### 点播、轮流听与主动定位

| # | 场景 | Android 现状 | 目标行为 |
| --- | --- | --- | --- |
| 1 | 第一次点播未听单集 | 先读后播，按账号偏好；准备还等待 PUT | 保留偏好，去掉上传对开播的阻塞 |
| 2 | A 暂停，B 没更新，A 再播放 | 已准备时直接续本机，不读远端 | 有界读取；保留 A 最新暂停点，不倒退到自己的旧上传 |
| 3 | A 暂停，B 听到新位置，A 再播放 | 仍续本机旧位置；不会主动读 B | 接服务端最近接受的 B 位置并尝试接管 |
| 4 | A 仍播放，B 主动开始同一集 | B 可建新会话；A 下次 PUT 才发现冲突 | A 继续本机出声，停传且不跳位置；B 写入 |
| 5 | B 从 35 分钟回退到 20 分钟，A 随后恢复 | 已准备的 A 不读 B；服务端允许回退 | A 接 20 分钟；较小位置也可能是最新有效操作 |
| 6 | A 失权后继续听到更远 | 保留本机检查点并停传 | 保留；更远不意味着应覆盖云端 |
| 7 | 失权的 A 播放中后退 15 秒 | 本机 seek，不隐式接管 | 保留；普通定位不能重新抢权 |
| 8 | A 暂停后先定位，再播放 | 同一集本机控制保留目标；尚无恢复读取 | 新增读取后仍尊重明确目标，不被 B 的书签覆盖 |
| 9 | 耳机／锁屏／通知播放 | 与 App 进入同一播放器控制；已准备时不读远端 | 与 App 的主动恢复一致；后台也不等待交互弹框 |
| 10 | 仅回前台／打开播放器 | 不主动开播 | 保留；刷新显示不接管 |
| 11 | 失权后点「用本机进度」 | 读远端并尝试新 `resume` 会话 | 保留；失败不循环争抢，不清已听完 |
| 12 | A、B 听不同单集 | 每集独立进度 | 保留；不引入账号级独占播放 |

### 并发、离线与网络

| # | 场景 | Android／服务端现状 | 目标行为 |
| --- | --- | --- | --- |
| 13 | 两端基于同一版本开新会话 | 服务端仅接受一个，另一端 409 | 保留；未获权仍可本机听 |
| 14 | GET 后、首 PUT 前 B 心跳更新版本 | 首 PUT 可能 409；异设备停传 | 保留安全结果，播放不阻塞；首版不自动跨设备改版本重试 |
| 15 | 同会话重传或乱序 | 服务端按递增序号幂等处理 | 保留；回退也发更大序号 |
| 16 | A 的旧 `ended` 晚于 B 新会话 | 服务器拒绝，不改进度／完成状态 | 保留，并禁止此结束引发 A 的自动队列操作 |
| 17 | A 离线，B 在线更新，A 重连补传 | 旧会话 409；历史丢弃、当前停传 | 保留；重连不是主动接管 |
| 18 | 两端都离线，之后依次联网 | 服务端 CAS 决定接受结果，不按离线动作时间合并 | 保留；不能保证最后在现实时间操作的那端获胜 |
| 19 | 服务端已接受 PUT，但响应丢失 | 持久待发送记录可重试，序号保护 | 保留同会话同序号重试；不得新建会话 |
| 20 | GET 很慢／超时 | 单次请求超时；准备还可能串行等两次 PUT | 恢复读取使用整体预算；超时本机继续，迟到结果不 seek |
| 21 | 进度 GET 返回 5xx | `prepare` 只把 IO 异常降级；HTTP 错误可能导致准备失败 | 可恢复错误降级本机；权限／认证错误分开处理 |
| 22 | 首个进度 PUT 卡住 | 新点播仍会等；已准备的本机恢复已解耦 | 点播与主动恢复均不等待上传完成才播放 |
| 23 | 已冲突，离线重新恢复 | `prepare` 排除冲突的脏记录，可能选旧远端缓存 | 优先 A 最新本机位置，仍不绕过版本隔离 |
| 24 | GET 中暂停、seek、切集、退出登录 | 已有任务取消、代次与账号检查，尚无普通恢复 GET | 扩展同一取消边界；seek 胜出，暂停不被迟到结果解除 |

| 35 | 切账号／服务器，旧请求回来 | 登录请求作用域、稳定存储作用域分开隔离 | 保留；相同单集 ID 不跨账号回写、开播或显示提示 |

| 44 | 离线自然结束，结束上报未确认 | 仍可能进入队列移除／自动下一集 | 保留结束待发送记录并停在片尾，不改待播；主动下一集不受此门禁阻塞 |

## 跨端可行性与技术限制

核心规则可在四端实现：明确命令入口、有界读取、本机持久化、会话隔离、连续播放不跳转。不能统一成「任何平台、任何系统事件都保证一次点击自动出声」。下表区分实现边界与平台限制；实际运行结果单列于验收记录。

| 平台 | 可用边界 | 实施与限制 |
| --- | --- | --- |
| Android | MediaSession 命令与 Media3 的播放意图、缓冲、焦点抑制分开；播放服务可脱离 UI 工作 | 使用显式命令入口触发恢复读取。引擎自动恢复不得重新走该入口；准备流程内部 `play` 也不能再次发起恢复 |
| iOS | `MPRemoteCommandCenter` 接收外部命令；`AVAudioSession` 提供中断与恢复信息 | 中断通知进入内部本机恢复，外部命令进入主动接续；中断中暂停取消自动恢复。沿用最低部署版本支持的中断 API |
| macOS | 与 iOS 共享播放核心和远程命令入口；可以区分明确命令与 AVPlayer 状态 | 现有音频会话观察只编译在 iOS，不能直接套用手机的中断回调。桌面按输出路由／播放器状态处理本机恢复，状态回调不建云端会话；具体输出设备恢复需运行验收 |
| Web | App 命令可追踪；支持时由 Media Session action 接收系统播放键 | App 与 Media Session play 进入相同接续入口。HTML 媒体通用事件不提供同等焦点原因，不能由 `playing` 猜测主动接管；不支持的系统控制不能靠前端补齐 |

### 必须保留的差异

1. **Web 自动播放限制。** 网络等待后 `audio.play()` 可能被浏览器／系统策略拒绝，不能保证所有浏览器均一次点击出声。失败时保留已经选好的位置和暂停状态，给出原播放按钮再次操作的路径；再次点击只完成该次被拦截的播放，不重新读进度或反复建会话。不以“先播旧位置，再跳远端”绕过限制。未获得播放许可时不要提前上传新的 `play` 接管。
2. **通用媒体事件没有用户原因。** 按 HTML 标准，`pause / playing` 是普通事件；仅凭它们不能区分电话、脚本、系统 UI 或用户操作。Web 只在可识别的 App／Media Session 命令上执行接续；其他自动恢复只用本机。某浏览器如果只发通用事件、不把系统 PLAY 送到 action handler，无法保证该系统键与 App 键完全同效。
3. **暂停后不能靠后台持续探测。** 网页可能被节流或冻结，原生 App 也可能被系统停止；恢复时再读，不能承诺暂停期间持续刷新。强制结束不能保证最后回调，按最近落盘恢复。正常后台音频播放与已经暂停的后台应用分别验收。
4. **硬件命令来源不可完全辨认。** 耳机／车机重连自动发出的普通 PLAY 与按键触发的 PLAY 可能没有可区分信息。四端统一按实际收到的命令处理，不承诺还原实体按键意图，不增加按时间猜测的策略。
5. **Web 多标签页也是多实例。** 同账号标签页共享 localStorage 的设备 ID 和单集持久记录；每个活动播放器在内存保存自己的会话与检查点，防止另一页写盘替换正在播放的会话。任何 409 都停传，不能把同 `device_id` 的另一会话视为自己。冷恢复读取最后落盘记录，保持暂停；两个标签页回归另列于验收。
6. **进度不是实时遥控协议。** 远端没有可靠的“此刻正在播放／已暂停”信息；续听只接最近接受的书签，可能落后对方当前出声位置。不让手机等待电脑暂停，也不承诺远程停播、无缝零秒误差或跨集独占。

### 平台依据（2026-11-17 核对）

- [Media3 Player 的播放意图与抑制](https://developer.android.com/reference/androidx/media3/common/Player)、[Android 音频焦点](https://developer.android.com/media/optimize/audio-focus)：`isPlaying` 还取决于缓冲和抑制；ExoPlayer 可内部管理焦点。

- [HTML 媒体事件](https://html.spec.whatwg.org/multipage/media.html#mediaevents)、[play() 与自动播放限制](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)、[Media Session action 支持范围](https://developer.mozilla.org/en-US/docs/Web/API/MediaSession/setActionHandler)、[后台页面计时器](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API#policies_in_place_to_aid_background_page_performance)。Web 的保守降级是从这些接口能力得出的设计选择，仍需目标浏览器实测。

### 实施与验证记录

- Android、Web、Apple 共用核心均已拆分主动恢复与内部恢复；普通恢复采用一次整体 1500ms 读取，旧／新上传不进入本机开播等待链。三套进度存储均移除同设备 ID 的自动改版本重试，片尾均要求本次结束确认。
- 关键接续回归在旧实现实际失败：Android MediaSession 与 Web 按钮、Apple AVPlayer 在另一端向后更新后仍续旧位置；修复后断言真实位置推进。另保存了 Web 冷恢复音频未就绪时回到零、Apple 自动续播后冷恢复错集、本机未上传暂停点被旧回声覆盖、冷恢复首次播放前明确定位丢失的失败记录。重新选集也保留自己尚未上传、序号领先于云端回声的位置。
- Android 的 183 项 JVM 测试通过，包含延迟读取、上传阻塞、503／401、同设备不同会话、较小远端位置、本机未上传暂停点及结束确认；标准 Phone／Pad（均开启物理键盘）各通过三个媒体服务专项。Apple 共用核心完整测试通过（macOS 119 项播放／106 项网络；iOS 模拟器 120 项播放／106 项网络，含 AVAudioSession 中断通知），macOS 的 43 项原生回归通过；iOS 应用构建通过。
- Web 真实浏览器回归覆盖读取中暂停／定位、迟到结果、超时、503 与 401／403／404、三种偏好下普通恢复、上传阻塞、自动播放拒绝、同账号双标签页、完成后明确定位回听及失权／离线片尾不改待播。完整检查与最终设备矩阵的结果维护在 [PR #165](https://github.com/qingmuhy744/wildstring/pull/165)，不把此前 Android 修复的绿色检查沿用到四端实现。

## 风险与回滚

- 最大行为变化是普通恢复现在会读异设备进度，必须覆盖无更新时不丢本机暂停点；不能为修复接续重新引入网络卡播放。
- 片尾未确认时停播会改变离线自动连播体验；这是用户已确认的取舍，不阻塞当前集的本机播放或手动切集。
- 现有 API 足以支持本方案的单集接续，不足以提供账号级遥控或跨集原子交接。发现需要后者时另提方案，不暗中增加服务端协调层。
- 按进度存储、服务、测试分步实施并同步契约；保留既有账号隔离与服务端 CAS。回滚本方案的客户端改动即可，不涉及 schema 回退。
