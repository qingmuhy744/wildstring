# 四端播放行为统一与 0.8.20 发布

## 目标

用户授权按 Android 已确认的标准核对 Web、Android、iOS、macOS，修复同类缺陷，完成后合并 main 并正式发版。当前正式版为 0.8.19，按补丁版本 0.8.20 推进。

## 范围与判据

| Android 暴露的问题 | 四端统一要求 |
| --- | --- |
| 回退后继续命令被吞 | 暂停、定位直接作用于本机引擎；恢复后位置实际推进 |
| 普通恢复与临时中断混淆 | 主动恢复有界读书签；系统自动恢复沿用本机位置和会话 |
| 初次定位只更新界面 | 音频未就绪时保留目标位置，实际从选定原始时间线起播 |
| 播放中从头播放撞自己的旧上传 | 仅凭本进程具体旧请求的成功确认衔接未发送新会话；真实 409 停传 |
| 大节目点播阻塞界面 | 检查各端主线程准备路径，避免逐项同步 IO；不增加额外远端轮询 |
| 待播状态切换撑高卡片 | 同一操作区稳定；内容和字号变化仍允许自然换行 |
| 封面偏小、留白失衡 | 按实际可用空间安排封面与标题，控制区及提示始终可达 |
| 播放、暂停、缓冲突变 | 固定按钮与图标槽，连续状态反馈；减少动态效果直接落位；加载中仍可暂停 |
| 改布局丢失已有交互 | 回归封面、文章、待播、返回和平台已有手势 |
| CI 把音频推进等同上传完成 | 等待对应业务结果，不增加固定睡眠或自动重试掩盖失败 |

同步规则以 [单集进度契约](../../contracts/podcast-progress.md) 为准；视觉数值只在 [DESIGN.md](../../DESIGN.md) 维护。保留平台布局差异，不增加服务器租约、设备锁、远程停播或新设置。

## 执行

1. 核对三套播放核心与四端所有调用点，先记录可复现失败，再做最小修复。
2. 扩展 Web、Apple 的进度回归及真实界面状态／动画判据；Android 复用已通过专项并补必要回归。
3. 按 L3 执行本地检查、全仓库 CI、平台测试、截图及逐帧检查；无法替代的真机 UAT 明确列入发布限制。
4. 同步各端版本／构建号、两份 README、scope、CHANGELOG 和发布说明，核对公开签名与发布 Secret 名称。
5. PR 检查通过后合入 main；在最终 main 上通过完整 CI 与手动 Android 全量设备门禁，之后才打标签。
6. 等待 Release 全流程完成，下载并核对产物、证书、校验和、双架构容器和匿名访问；不自动部署个人服务器。
