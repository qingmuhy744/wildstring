# Android 播客布局与播放状态转场

## 目标

- 修正封面偏小、内容重心偏上的静态布局。
- 切换待播三态时保持操作区域、元数据换行及卡片高度稳定。
- 播放、暂停、缓冲在同一个图标区域连续过渡，遵守 App 与系统减少动态效果设置。

用户已确认按上述判断实施。尺寸与动效数值统一见 [DESIGN.md](../../DESIGN.md) §5.3、§6.3。

## 不碰的边界

不修改进度读取预算、接续选择、上传冲突、播放线或服务端协议；不改变音乐播放器及其他客户端。

## 方案

1. 移除播放器的空提示预留和估算标题高度，先由正常布局测量标题与节目行，再用剩余空间放正方形封面；标题宽度不依赖封面受高度限制后的尺寸。
2. 待播三态使用同一个按钮；按当前语言和字号测量三种标签的最大宽度，不改变进度或完成状态的显示规则。
3. 播放、暂停、缓冲共享持续存在的转场，固定外框与图标槽；可访问名称来自当前动作，避免离场图标重复播报。

## 验收（L2）

- `git grep` 核对播放器、行组件的全部调用点和相关测试。
- 设备回归先在旧实现上证明卡片尺寸与缓冲结束转场判据失败，再验证修复。
- Phone / Pad、浅深主题、长标题与放大字号；补充与用户截图接近的长屏及标准窄屏场景。截图逐张检查。
- 按帧记录按钮边界及图标像素变化，复用 `MotionAssertions` 验证外框稳定、转场存在、落位不再变化；覆盖 App 关闭动画与系统减少动态效果。
- 覆盖封面、文章、返回、待播添加/移除、当前项、已听完、空文章、加载、网络错误及权限错误；播放行为使用既有 transport / resume 设备测试回归。
- 执行 `make check`、`make test-affected`、Android JVM/编译、lint 与上述设备专项；报告实际通过范围，未运行的完整矩阵不记为通过。

## 风险与回滚

- 可见提示会使用实际空间，小屏封面可能相应缩小；不再为不存在的提示牺牲正常封面。
- 三态按钮会比短标签原来的按钮更宽，元数据可能比旧版更早换行，但状态切换不再改变换行。
- 视觉改动可按文件恢复，不涉及数据迁移。设计文档单独提交，功能和验证另行提交。

## 实施与验证

- 播放器与单集行的全部生产调用点已用 `git grep` 核对：全屏入口仍由 `WildStringApp` 托管，单集行仍只在节目详情使用。移除的提示高度回传与预留常量没有残留引用。
- `make check`、`make test-affected` 通过；后者没有选中后端或 Web 功能用例。`make android-ci` 通过，包含 186 项 JVM、设备测试编译、Debug / Release 构建和 lint；最终手势补丁另完成 186 项 JVM、Debug 构建、设备测试编译和 Debug lint。
- 标准 Phone / Pad 各通过新增 `PodcastPresentationTest` 的 8 项，以及 `PodcastTransportServiceTest`、`PodcastResumeServiceTest`、`PlatformMediaSessionTest` 各一项。Phone 的既有封面／文章逐帧用例 5 项通过，宽屏一项按条件跳过；该项在 Pad 单独通过。390px 节目详情的 2 项及长屏封面的 1 项通过，合计 31 项设备专项通过、1 项按设备条件跳过，无类级自动重试。
- 保留封面点击、横滑切换与下拉收起。移除滚动布局后，下拉输入不再自动进入原嵌套滚动处理；封面复用已有收起手势，不新增阈值。新手势用例在缺少该绑定的 APK 上实际失败，补齐后 Phone / Pad 均通过。
- 新判据在旧行为 APK 上实际失败：合成场景的卡片底边移动 62px；封面期望约 766px、实际 555px；缓冲结束没有中间帧。APK 已保存并与当时安装包的 SHA-256 核对。普通播放／暂停的旧淡入淡出原本可通过，实际缺口在缓冲分支。
- 最终 Phone / Pad 每条图标转场各采样 28 帧：正常播放、暂停、缓冲结束各有 16 个不同画面；关闭 App 动画或系统动画后只有一个画面，加载指示也保持静止。`MotionAssertions` 检查外框边界与落位后的像素变化；落位后没有像素变化。
- 逐张检查 69 张相关截图，包括手机、平板、长屏、390px 与宽窗口的浅深主题、长标题、放大字号、待播三态、已听完、文章加载／空／500／403、音源错误和同步冲突。组件截图与 Compose 当前帧同步；服务截图中的实时进度和触摸反馈不作为静态动效判据。
- 原始结果、截图与帧数据在本地 `artifacts/android-podcast-presentation/`，不提交源码；当前验收文件与已看截图分别由 `verification.json` 和 `visual-review.json` 索引。

未验证：用户原手机的真实蓝牙、电话／导航链路与触感；所有语言和最大系统字号组合；其他客户端视觉。本轮没有重新运行全仓库 `make ci` 或正式发布门禁，不将这些专项记为完整全端矩阵通过。
