# Web 歌曲列表虚拟化

现有歌曲浏览按页加载，已加载的行全部参与渲染。在同一个 2,000 行合成曲库暂停播放并开启 Chromium 4 倍 CPU 限速时，临时只让前 50 行参与布局，p95 帧间隔从约 167 毫秒降至 17 毫秒，长任务从 31 次降至 0 次。

## 方案

保留顺序连续的已加载歌曲数据，按绝对位置分组渲染视口附近的行。远处行组用占位保持滚动高度。行高沿用列表密度样式，按实际尺寸修正包含分碟标题与多行状态的行组。把有焦点的行留在页面，应用列表格语义和绝对行号。

核对向前补页、字母定位、导航返回、切换列表密度、菜单和点播。加载边界、索引与播放队列继续使用现有分页数据。

## 验收

按 L2 验收。用同一 2,000 首合成曲库对比实际挂载行数、DOM 元素数、4 倍 CPU 限速的 p95 帧间隔和长任务。通过桌面与 390px 截图核对浅深主题，走通滚动、菜单键盘操作、播放、定位、返回、失败重试及多碟曲序。

同机 Chromium 暂停播放、4 倍 CPU 限速、约 4 秒采样。列表顶部的 p95 帧间隔由 166.7 毫秒降为 16.8 毫秒，超过 50 毫秒的长任务由 31 次降为 0 次。已加载的 2,000 首中，顶部挂载 25 行，列表中段挂载 100 行。整页 DOM 元素由约 14.1 万个降至顶部 2,155 个、中段 7,405 个。
