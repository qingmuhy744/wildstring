# 四端音乐队列与心动续播

## 四端适配

Web、Android、macOS、iOS 统一使用下述 100 首规则与只读每日推荐。沿用各端现有的列表排序、队列存储、睡眠和播放器事件。覆盖长列表首次点歌、尾段、队列上限、短列表、无批次、重复播放及切换播放来源；播客保留独立规则。Apple 两端优先共用既有播放与网络层。

## Android 点歌路径

旧版在「全部歌曲」从偏移 0 开始按 200 首取完整集合，又在主线程按曲目重复读取并解析服务器地址；完成整个队列后才打开播放器。在 `30d08d2` 的 Android 15 手机模拟器 Debug 包上，500 首曲库三次点歌到目标曲目画出的中位数为 3.11 秒，其中取数 0.33 秒、准备条目 2.02 秒，同队列全屏下一首为 0.56 秒。

新路径在歌曲行给出准备状态，按批次复用服务器地址，在后台准备条目。用户再次点歌或离开当前列表时，取消前一个未完成请求。回到同一标题或曲序排序的曲目列表，优先定位之前建立的队列条目，保留手动插队、移除及拖动的结果。列表重载、排序变化、曲库或服务器变化将使该复用失效。

## 初始队列

音乐集合至多 100 首时保留整个队列，从所选歌曲开始。超过 100 首时，从该行的绝对位置按当前来源的顺序最多准备 100 首，临近末尾时按实际剩余数量处理。已完整显示这一段时复用列表数据，否则请求该位置的一页；目标已经变化时保留原来的播放状态。播放全部从第一首开始。用户手动添加超出音乐队列容量时，保留队列并说明上限。全选、加入歌单和离线保存仍按各自的范围取数。

## 心动模式

长列表的初始队列自然播完时才读取已有批次，在当前用户和曲库的每日推荐中取可播放曲目，优先避开刚播过的一批，并重新随机排序。心动模式与每日推荐共用同一批数据；每天的生成、用户的推荐偏好和手动换批都由每日推荐管理。只有上一批时可以使用上一批；没有已生成的批次时正常停止。心动读取不触发生成、外部来源或模型调用。在新的音乐队列中替换已结束的批次，以维持 100 首上限。单曲循环、列表循环及睡眠定时器按用户选择执行，显式暂停、切歌、清空或切换账号后不得被迟到结果覆盖。短列表正常结束，播客沿用自己的队列。

## 验收

以合成曲库覆盖 100 首的边界、两万首列表中段点播、101 首列表末尾点播、快速连点、手动编辑后重选、取数失败和返回。验证已有上一批能自然接续、没有批次时停止、睡眠停止优先；逐张核对手机和平板浅深主题的准备提示与心动队列。

Android 15 手机模拟器、Debug 构建、500 首合成曲库，同一场景三次运行的中位数如下。点击从歌曲行处理器计时。

| 观测点 | 修改前 | 修改后 |
| --- | --- | --- |
| 歌曲行画出准备提示 | 无 | 112 毫秒 |
| 全屏画出目标曲目 | 3107 毫秒 | 753 毫秒 |
| 播放器报告音频位置开始推进 | 3934 毫秒 | 1239 毫秒 |
| 回到列表重选已在队列里的歌，画出目标曲目 | 未作同组三次测量 | 410 毫秒 |

三次首次点播均只请求一页，队列内重选均为零次请求。另在宿主机同时执行 R8 和 Lint 时测了三次，首次画出的中位数为 2655 毫秒，音频推进为 6286 毫秒。真机触屏至扬声器出声耗时尚未测量。

Web 在桌面与手机宽度用 257 首合成专辑验证从第 201 首点播、保留末尾 57 首、随机接续已生成的推荐以及无推荐时停止。Apple 双端共享的播放与网络层验证队列边界、只读请求、用户切库与本机暂停恢复。iPhone 模拟器和 macOS 接管 450 首的共享快照时，都从第 301 首恢复了 42.5 秒的暂停进度。隔离的旧版 SwiftData 队列经升级后保留曲序和进度。Web、iOS 和 macOS 的浅深色队列均已核对。
