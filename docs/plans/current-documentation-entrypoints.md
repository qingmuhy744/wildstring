# 现行文档入口与持续检查

## 目标

在归档过期指南后恢复明确的现行开发运维入口，为过时文档补充归档原因和替代入口，并将本地链接、章节锚点与文档状态检查固化为日常门禁。

## 不碰的边界

不修改产品功能、接口、视觉规范、发布标签或历史验收结论；不批量改写其他归档文档；不要求自动工具判断文档语义是否过时。

## 方案

1. 新建简短的 `docs/development.md`，保留启动、扫描、测试、容器、代理、备份与 TLS 的现行入口，旧长文继续保存在归档目录。
2. 为三份过时说明统一添加状态、归档原因和现行入口；移除现行产品文档中多余的状态行，并恢复 README 的开发指南链接。
3. 新增标准库文档检查脚本，扫描受管及新增 Markdown 的本地链接与锚点，校验方案五态和过时归档说明的必填头，通过 pre-commit 接入 `make check`。
4. 将文档职责和归档头规则写入 `AGENTS.md`，规范修改与上述实现分开提交。

## 验收（按 AGENTS.md §3 定级）

L0：直接运行文档检查脚本并验证故障样本会失败，执行 `make check`，反查移动路径和文档引用，检查最终 diff。

## 风险与回滚

全仓链接检查可能暴露既有断链；只修复本次可确认的路径问题，不顺手改写历史语义。新增检查仅使用 Python 标准库和 Git，可在 CI 与本地一致运行；如有误判可单独调整解析规则或回退检查脚本，不影响应用运行。
