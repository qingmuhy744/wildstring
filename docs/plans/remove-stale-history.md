# 删除低价值历史文档

## 目标

让活动工作树只保留现行行为、当前操作入口、未结束方案，以及有明确用途的发布记录与 ADR。低价值历史方案、审计和批次复述依靠 Git 保存，不再同时维护归档目录。

## 不碰的边界

不删除 `contracts/`、`docs/releases/`、`docs/decisions/`、现行开发运维入口和仍被脚本使用的矩阵；不按日期或「已交付」状态批量删除含现行行为的文档；不丢失真正未实现且仍需推进的产品路线。发布说明和 ADR 如仍需历史正文，使用带提交 SHA 的永久链接。

## 方案

1. 删除 `docs/archive/` 及已交付方案；本分支基于 PR #164，待其合入后，其执行方案同样作为已交付历史移除。逐一反查引用，现行入口改指契约，必要的历史入口改为不可变提交链接。
2. 清理产品、架构文档中的混合内容：纯批次方案与复述删除；仍描述现行行为的文档保留并去掉时效状态；现行行为与过期实现、未来规划混杂的文档先拆分再删除残余历史。
3. 取消 `scope-history.md` 与 `docs/releases/` 的第二套批次历史职责，现行范围只链接发布记录和契约；未发布路线仍保留在 `scope.md` 或活动方案。
4. `docs/plans/README.md` 改为只承载活动方案；`AGENTS.md` 的历史查阅与方案生命周期规则同步调整，规范修改单独提交。
5. 使用文档检查脚本验证全部本地链接、锚点与方案状态，再执行 `make check` 和最终差异审查。

## 验收（按 AGENTS.md §3 定级）

L0：`python3 scripts/check_docs.py`、`make check`、`git diff --check`；反查被删除路径和旧状态词。逐份核对保留文档仍有现行读者或执行入口，删除文档均可由 Git 历史恢复；不以静态检查代替语义审查。

## 风险与回滚

最大风险是误删仍有效的操作说明或未实现路线，因此混合文档必须逐份阅读后分类。历史正文改用提交链接时固定到 PR #164 合并前的源提交，不跟随分支漂移。改动仅为文档，可按提交分别回退删除、混合文档清理与规则调整。
