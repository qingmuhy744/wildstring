# PR 门禁与播放回归

## 目标

- 使 Android 系统上一首与应用内音乐队列的上一首一致，验证原音和 AAC。
- 使 Web 播客切集使用正在保存的节目偏好，阻止迟到读取覆盖用户选择。
- 精简 Android 通知页，明确音乐偏好输入的用途并验证键盘、保存与编辑路径。
- 按实际构建输入运行容器和 Apple 检查，自动核对版本并防止旧版重跑降级发布渠道。

## 方案

- Android 在会话播放器处理上一首命令，沿用转码跳转。检查入口为 `PlatformMediaSessionTest`。
- Web 复用已有的偏好写入顺序，增加慢写入期间切集的浏览器回归。
- CI 分开判断容器构建和后端测试，通过现有 `Code Quality & Packaging` 必检项汇总 Apple 检查。普通 Android PR 继续用构建、Lint 和 JVM 测试。
- 发版对比上一个已发布版本的 Android 构建号，校验 Apple 版本与构建号。发版设备范围覆盖后端运行代码和依赖。发布版本产物后，从已发布稳定版本中选择最高版本同步公共渠道。

## 验收

- L3 验证 CI 影响范围、发布版本判定、Android 系统媒体会话、Web 播客延迟响应和容器冒烟。
- 更新发布指南和用户可见变更记录。Apple 和 GitHub Actions 行为用远端检查验证，发行渠道用隔离测试核对，实际发布在独立批次执行。
