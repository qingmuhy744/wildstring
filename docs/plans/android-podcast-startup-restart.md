# Android 大节目点播与播放中重播

## 目标

- 排查忽左忽右 627 集点播时界面停顿，以隔离的大节目验证主线程开销，优化已证实的瓶颈。
- 复现同一手机播放中选择「从头播放」时，本机旧上传令新会话误报异设备冲突的问题。
- 修复书签先于音频准备完成返回时，提前定位被播放器适配层丢弃、实际从零出声的问题。

## 不碰的边界

- 保留先读后播、1500ms 读取预算、完成意图和服务端 CAS；不等待阻塞上传，不在 409 后自动重试或按设备 ID 推断接管。
- 不访问或修改真实曲库与用户进度，不调整正式发布或部署。

## 方案

- 用大节目和真实 Media3 路径测量主线程连续占用、条目构造与点播准备时间，避免把网络等待等同界面冻结。
- 点播所需的纯元数据准备与网络状态查询按批处理；播放器调用仍在主线程，保留节目顺序、手动前后集和冷恢复。
- 用受控 PUT / GET 时序验证重播竞争。只利用本进程旧请求的成功确认衔接尚未上传的新会话；真正的 409 仍按契约停传。
- 播客使用原始音频时间线，准备结果直接定位 ExoPlayer，让其保留尚未就绪时的定位请求；不依赖此时尚未开放 SEEK 的控制适配层。
- 修改前核对 `PodcastPlayRequestTest`、`PodcastTransportServiceTest`、`PodcastProgressNetworkTest`、`PodcastProgressTest`，补充旧实现必败的回归。

## 验收（按 AGENTS.md §3 定级）

- 播放器 L2 专项：`make check`、受影响测试、Android JVM、设备编译、构建和 lint；Phone / Pad 的点播、返回、回退恢复及重播。
- 记录合成样本前后数据和真实单集/蓝牙真机未验证范围；不把模拟器指标当作用户手机指标。
- 本轮没有界面布局或动画设计变更；沿用现有播放器截图检查受影响状态。

## 风险与回滚

- 批处理不得跨账号提交，取消点播不得迟到播放；保留既有取消和账号切换回归。
- 本机成功确认只调整首次发送前的新会话基准，不能成为跨设备自动抢权；覆盖真实异设备争用。
- 回滚对应 Android 实现和测试即可，无 schema 或 API 变更。

## 验证记录（2026-11-17）

- `PodcastPlayRequestTest` 的 800 集合成节目回归在旧实现上实际失败：创建并应用播放条目占用主线程 2321ms，最长消息循环间隔 2327ms，点播准备合计 3921ms。旧实现证据保存在本地 `artifacts/podcast-startup/old-implementation/`。
- 将网络查询按整批执行并移除同一条目的重复 URL 构造后，单独主线程构造仍需约 1 秒，因此继续将整批构造移到后台；同一 Phone 形态测得最长主线程间隔 61ms、点播准备 1952ms。指标属于模拟器合成样本，未包含真实音源缓冲，也不是用户手机或忽左忽右 627 集的实测。
- 两条旧实现重播回归实际失败于本机上传被误判异设备：旧 PUT 在新 GET 后确认；以及 GET 已取快照、旧 PUT 已确认但读取结果才返回。修复保留旧请求的具体会话来源，并在新会话首次上传前衔接成功版本；不增加 409 重试。
- 新增真正异设备在旧 PUT 阻塞期间抢先更新的回归，要求保留远端位置、提示冲突且不自动接管。
- Pad 首轮在初始书签开播处超时，单独复跑通过；增加状态日志后的三次独立进程仍出现一次失败，日志显示已上传 60 秒但真实位置只有约 9 秒。人为延迟首个音频响应头一秒后可控复现同一断言失败，证明是准备前定位被丢弃，不能当作重跑即通过的偶发错误忽略。该负例保存在本地 `artifacts/podcast-startup/old-implementation/early-bookmark/`；初始书签随后改为符合服务端契约的已存在版本与会话。
- 慢音源定位修复后，Pad 的专项按独立进程连续三次通过；初始书签改为有效版本与会话后再次连续三次通过。最终 Phone / Pad 各通过 `PodcastPlayRequestTest`、`PodcastTransportServiceTest`、`PodcastResumeServiceTest`、`PlatformMediaSessionTest`、`PodcastStreamTest`，各 10 项，无类级重试。
- 自动续播专项原模拟服务每次 GET 都返回版本 0 的固定书签，PUT 不保存完成状态，提前定位修复后暴露其错误假设。改为保存真实版本／会话／完成状态并执行 CAS，断言重选已听完单集从零重播，再验证片尾跳过已听完后继和冷恢复保持暂停；未因此修改产品规则。
- 最后一轮 800 集准备样本：Phone 合计 1559ms、最长主线程间隔 58ms；Pad 合计 1643ms、最长间隔 74ms。包含真实界面、MediaSession、628 条节目列表和开始后推进半秒的重播路径，Phone / Pad 分别约 2086 / 2049ms，主线程最长间隔约 275 / 286ms；不据此承诺零卡顿或真实音源立即出声。
- `make check`、`make test-affected`、186 项 Android JVM 测试、设备测试编译、Debug APK 构建和 Debug lint 通过；受影响测试选择器没有选中后端或 Web 功能测试。本轮按 L2 完成专项，不计为全端 L3 再验收。
- Phone / Pad 均启用物理键盘，各逐张查看浅深主题播放／暂停、深色冲突和重播截图。没有发现新增遮挡或异常折行；未覆盖完整空／加载／错误／权限不足、全部长文案和动画逐帧矩阵。日志与截图保存在本地 `artifacts/podcast-startup/`，不提交源码。
- 未验证用户原手机、真实蓝牙／电话和忽左忽右 627 集音源；没有修改服务端、执行部署或发版。真实单集音源与网络时延仍需用包含本次修复的 Dev 包验收。
